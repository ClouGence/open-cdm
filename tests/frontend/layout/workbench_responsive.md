# 工作台响应式壳层与列表页

## Purpose

验证 CloudDM 工作台壳层和复用列表布局在标准 MacBook、浏览器高缩放与窄视口下保持可导航、可筛选和可分页，防止固定侧栏、工具栏和分页器挤占主工作区。

## Scope

- 壳层：全局侧栏、内容头部、面包屑、系统操作区和唯一主工作区卡片。
- 系统操作区：确认旧消息中心入口、下拉内容、失败任务请求和对应路由均已移除。
- 列表页：工单、数据源、账号、角色、日志、环境、CI/CD 和复用 `table-list-layout` 的页面。
- 路由：`/#/ticket`、`/#/datasource`、`/#/manager/account`、`/#/manager/role`、`/#/manager/logs`、`/#/env`、`/#/cicd`。
- 不覆盖：SQL 全屏工作台内部面板尺寸、各列表的后端查询正确性和移动端原生手势。

## Preconditions

- 本地服务可通过 `http://127.0.0.1:8222/` 访问，Chrome 已登录具备上述页面查看权限的账号。
- 各列表至少有一页数据；不执行创建、删除或批量修改。
- 使用 Chrome 可调整窗口或视口能力复测，不读取浏览器认证数据。

## Test Data

- 使用现有只读列表数据，至少包含一个超长名称、空值和多页列表。
- 搜索条件使用可清除的现有文本，不提交状态变更。
- 视口覆盖 1512×982、1440×900、1209×786、1152×720、1008×655、960×600、1024×768 和 390×844。

## Suites

### WR-SMOKE-01 壳层导航

- 风险/目的：P0，确认中等有效视口下侧栏仍可用且主内容不会被挤出。
- 初始路由与状态：从任意非 SQL 工作台页面开始。
- 测试数据：具备多个一级菜单和至少一个展开分组的账号。
- 准备方法：展开一个侧栏分组并记录当前页。
- 操作步骤：在 1512×982、1209×786、1008×655 和 960×600 依次查看并点击一级菜单、分组和子菜单；检查内容头部面包屑、数据查询入口和系统操作图标。
- 预期结果：侧栏宽度随有效视口由 240px 逐级收敛到 208px、176px 和 160px；菜单文字不逐字换行，当前项可见，展开分组及子菜单仍可点击；主工作区始终保留可用宽度且没有页面级横向滚动；中等宽度下“数据查询”收为图标但 Tooltip/可访问名称保留；面包屑和系统操作不重叠。
- 恢复/清理：返回初始页面。

### WR-SMOKE-02 顶部系统操作区

- 风险/目的：P0，确认移除旧消息中心后不再展示无效入口，同时不影响文档、联系我们、语言切换和用户菜单。
- 初始路由与状态：Chrome 已登录，从 `/#/datasource` 等非 SQL 工作台页面开始。
- 测试数据：不需要业务数据，不创建或修改记录。
- 准备方法：记录右上角现有系统操作图标和当前路由。
- 操作步骤：在 1440×900、1024×768 和 390×844 下检查系统操作区；展开语言切换和用户菜单后关闭；分别访问旧路由
  `/#/system/info_center`、`/#/system/console_job/1`；刷新回落后的页面。
- 预期结果：不展示消息中心图标、红点、下拉列表或“消息中心”文案；文档、联系我们、语言切换和用户菜单保持可见、可操作且互不重叠；
  页面不请求旧 `consolejob` 接口；两个旧路由均不渲染已删除页面并回落到 `/#/sql`；刷新后仍保持正常工作台，不出现新的应用 Console
  错误。
- 恢复/清理：关闭已展开菜单，返回初始工作台路由并恢复默认视口。

### WR-MAIN-01 通用列表工具栏

- 风险/目的：P0，确认复用列表页在空间不足时工具栏能换行而非遮挡。
- 初始路由与状态：依次打开工单、账号、角色、日志和 CI/CD 列表。
- 测试数据：现有列表数据和可清除搜索条件。
- 准备方法：记录各页筛选控件和右侧主操作。
- 操作步骤：在 1440×900、1152×720、960×600 和 390×844 下输入但不提交搜索条件，展开下拉框，查看右侧操作按钮和底部分页；横向滚动表格查看末列后返回首列。
- 预期结果：1199px 以下工具栏允许自然换行；899px 以下筛选区和操作区上下排列、各自占满可用宽度；固定宽度输入控件受容器最大宽度约束，不撑破工作区；表格在自身容器内横向滚动而不是推动整页；分页器在空间不足时可横向访问且不遮挡表格。
- 恢复/清理：清空筛选并回到第一页。

### WR-EXTREME-01 Zoom 等效视口

- 风险/目的：P1，确认标准 MacBook 125% 和 150% 缩放的等效视口不会落入未覆盖区间。
- 初始路由与状态：打开带面包屑和多个筛选项的列表页。
- 测试数据：现有数据。
- 准备方法：记录 100% 缩放页面外观。
- 操作步骤：在 1512×982 和 1440×900 下分别设置 100%、125%、150% 缩放，或使用对应等效视口 1209×786、1152×720、1008×655、960×600；每次重载页面并切换一次侧栏菜单。
- 预期结果：每个缩放档位均进入与有效 CSS 宽度一致的断点；页面高度使用动态视口单位，不因浏览器 chrome 变化留下不可达底部；没有双纵向滚动、页面级横向滚动、按钮覆盖、面包屑与系统图标重叠或侧栏遮挡主区。
- 恢复/清理：恢复 100% 缩放和原窗口尺寸。

### WR-LIFECYCLE-01 尺寸切换与路由

- 风险/目的：P1，确认不刷新时改变窗口与切换路由仍应用新断点。
- 初始路由与状态：中等有效视口的工单列表。
- 测试数据：现有列表数据。
- 准备方法：展开一个侧栏分组。
- 操作步骤：连续从宽屏缩到 960px、再恢复宽屏；通过侧栏切换三个复用列表页；使用浏览器前进后退；刷新当前页。
- 预期结果：侧栏和工具栏实时重排，无尺寸残留或布局闪跳；路由切换、前进后退和刷新后均只有一个工作区滚动上下文，展开分组和当前菜单状态正确。
- 恢复/清理：恢复原页面和视口。

## Cleanup

- 清空所有列表搜索条件并恢复第一页。
- 恢复 Chrome 100% 缩放与原窗口尺寸。
- 本流程不创建或删除业务数据。

## Skip Conditions

- 账号缺少某页面权限时跳过该列表，以另一个复用 `table-list-layout` 的可访问页面替代。
- 列表无分页数据时仍验证分页容器和工具栏；多页导航标记为 SKIP。
- 无法设置精确视口时使用浏览器缩放的等效 CSS 宽度；两者均不可用时记录该断点覆盖缺口。
