# 达梦表编辑器默认值、虚拟列与标识符

## Purpose

验证达梦表编辑器能够在普通默认值、自定义默认值和虚拟列模式之间正确传递字段状态并生成 SQL，重点防止
`defaultOpt` 被通用转换层提前拒绝、默认值丢失、虚拟列表达式退化为 `DEFAULT NULL`，以及 schema 和表名被重复添加定界符。

## Scope

- 页面与路由：SQL 工作台 `/#/sql` 中的达梦新建表或编辑表页签。
- 入口：隔离的达梦数据源 → Schema → 新建表，或现有测试表 → 编辑表。
- 关联接口与状态：`POST /api/entry/editor/table/generateScript`、字段详情弹窗、普通默认值/虚拟列模式、SQL 预览。
- 关联源码：`TableEditorUiDataUtils.java`、`DmTableEditorUiPanelFactory.java`、`DmTableEditorUiDataSpi.java`、`DmTypeUtils.java`、`AbstractSqlBuilder.java`。
- 不覆盖：点击“立即执行”、真实创建或修改表、达梦 JDBC 驱动安装、生产数据源兼容性。

## Preconditions

- 本地 `DmAloneLauncher` 已通过 IDEA 启动，`http://127.0.0.1:8222/healthcheck` 返回 `ok`。
- 本地或其他明确隔离的 DM8 实例可连接；默认本地地址为 `127.0.0.1:5236`。
- Chrome 已登录具备 SQL 查询和表编辑入口权限的测试账号，任务标签页位于 `codex` 标签页组。
- 数据源树中可进入一个允许生成 DDL 预览的测试 Schema；本流程只预览 SQL，不执行 DDL。
- 每次从重新加载后的新建表页签开始，字段列表为空，避免上一次未保存状态影响结果。

## Suites

### DTE-SMOKE-01 普通默认值生成 SQL

- 风险/目的：P0，确认达梦合法的 `default` 模式不会在通用转换层触发 `UnsupportedOperationException`。
- 初始路由与状态：进入 `/#/sql`，打开隔离达梦 Schema 的新建表页签，字段列表为空。
- 测试数据：D01。
- 准备方法：点击“新增”，保留默认的 `VARCHAR` 类型与“普通默认值”模式。
- Chrome 操作：
    1. 点击“预览变更”。
    2. 等待 SQL 预览完成并检查浏览器 Console。
- 预期结果：
    1. 页面进入“SQL 预览”，没有错误弹窗或持续 loading。
    2. SQL 包含目标字段、`VARCHAR(255)` 和 `DEFAULT NULL`。
    3. Console 不出现 `UnsupportedOperationException` 或本流程新增的错误。
- 恢复/清理：返回“列信息”，不点击“立即执行”。

### DTE-MAIN-01 自定义默认值保留到 SQL

- 风险/目的：P0，防止插件专属的 `customDefault` 子字段在转换时丢失或退化成 NULL。
- 初始路由与状态：D01 字段位于“列信息”，尚未执行 DDL。
- 测试数据：D02。
- 准备方法：打开字段“详情”，保持“默认值类型”为“普通默认值”，在“默认值”中选择“自定义”。
- Chrome 操作：
    1. 在“自定义值”输入 `codex_default` 并点击“确定”。
    2. 点击“预览变更”。
- 预期结果：
    1. SQL 生成成功且包含 `DEFAULT 'codex_default'`。
    2. SQL 不得显示 `DEFAULT NULL`，也不得遗漏默认值子句。
    3. Console 无本流程相关错误。
- 恢复/清理：返回“列信息”，保留同一未保存字段供后续场景切换。

### DTE-MAIN-02 虚拟列表达式保留到 SQL

- 风险/目的：P0，确认 `defaultOpt=virtual` 能映射为达梦 `DEFAULT_OPTION` 属性，表达式不会被普通默认值覆盖。
- 初始路由与状态：D01 字段位于“列信息”，尚未执行 DDL。
- 测试数据：D03。
- 准备方法：打开字段“详情”，将“默认值类型”切换为“虚拟列”。
- Chrome 操作：
    1. 在“虚拟列表达式”输入 `UPPER('codex')` 并点击“确定”。
    2. 点击“预览变更”。
- 预期结果：
    1. SQL 生成成功并包含 `AS (UPPER('codex'))`。
    2. 同一字段不再包含 `DEFAULT NULL` 或先前的自定义默认值。
    3. Console 无本流程相关错误。
- 恢复/清理：返回“列信息”，不执行 SQL。

### DTE-MAIN-03 Schema 与表名只格式化一次

- 风险/目的：P0，防止公共 SQL builder 和数据源方言对同一标识符重复添加双引号。
- 初始路由与状态：进入 `/#/sql`，打开隔离达梦 Schema `PIKA` 的新建表页签，字段列表为空。
- 测试数据：D05。
- 准备方法：表名保持 `table_name`，新增 `id` 和 `column_name` 两个 `VARCHAR(123)` 字段，将 `id` 设为主键。
- Chrome 操作：
    1. 点击“预览变更”并等待 SQL 预览完成。
    2. 检查 `CREATE TABLE` 的 schema、表名、字段名和主键引用。
- 预期结果：
    1. SQL 包含 `"PIKA"."table_name"`，且包含 `"id"`、`"column_name"` 和 `PRIMARY KEY("id")`。
    2. SQL 不得包含 `""PIKA""`、`""table_name""` 或其他双层定界符。
    3. 页面无错误弹窗，Console 无本流程相关错误。
- 恢复/清理：不点击“立即执行”，刷新页签清理未保存表单。

### DTE-BOUNDARY-01 NULL 与空字符串默认值

- 风险/目的：P1，确认放行数据源扩展选项后，共享的 `NULL` 和 `EMPTY` 语义没有回归。
- 初始路由与状态：D01 字段位于“列信息”，尚未执行 DDL。
- 测试数据：D01、D04。
- 准备方法：在字段“详情”中使用“普通默认值”模式。
- Chrome 操作：
    1. 选择 `(NULL)`，确认后预览 SQL。
    2. 返回字段详情，选择 `(EMPTY STRING)`，确认后再次预览 SQL。
- 预期结果：
    1. NULL 场景包含 `DEFAULT NULL`。
    2. 空字符串场景包含 `DEFAULT ''`。
    3. 两次预览均不出现内部异常，模式切换后不会残留虚拟列表达式。
- 恢复/清理：刷新新建表页签，将未保存字段恢复为空列表。

### DTE-EXTREME-01 空字段列表与单字段列表

- 风险/目的：P1，确认 schema 修正后空列表和单字段状态可稳定进入，不产生重复默认值控件。
- 初始路由与状态：新建表页签已刷新。
- 测试数据：空列表、D01。
- 准备方法：先观察空字段列表，再只新增一个字段。
- Chrome 操作：
    1. 确认空状态显示“共 0 个字段”。
    2. 新增一个字段并打开“详情”。
- 预期结果：详情中只出现一个“默认值类型”控件；普通默认值模式下只出现一个对应的默认值选择控件；不再同时出现冲突的顶层默认值单选组。
- 恢复/清理：关闭详情弹窗并刷新页签。大量字段、响应式断点和性能不属于本次字段契约修复，除非后续改动涉及列表渲染，否则不扩展本场景。

### DTE-REPEAT-01 连续预览与模式反复切换

- 风险/目的：P1，防止重复预览或快速切换后旧模式覆盖新模式。
- 初始路由与状态：存在一个未保存的 D01 字段。
- 测试数据：D01、D02、D03。
- 准备方法：按 Main Flow 配置目标模式。
- Chrome 操作：
    1. 对同一配置连续点击两次“预览变更”，每次等待请求完成。
    2. 按“自定义默认值 → 虚拟列 → 普通 NULL”的顺序切换，每次确认后预览。
- 预期结果：每次只显示当前模式对应的单份 SQL；最后一次模式决定最终 SQL，旧的自定义值和虚拟表达式不会残留；无重复 toast 或错误队列。
- 恢复/清理：刷新页签清理未保存表单。

### DTE-FAILURE-01 后端不可用后的恢复

- 风险/目的：P1，确认生成脚本失败不会破坏字段表单，服务恢复后可重试。
- 初始路由与状态：存在未保存的 D02 字段；仅允许在本地环境控制 `DmAloneLauncher`。
- 测试数据：D02。
- 准备方法：记录当前表单可见值，通过 IDEA 停止本地后端，不停止达梦容器。
- Chrome 操作：
    1. 在后端不可用时点击“预览变更”，观察统一错误反馈。
    2. 通过 IDEA 重启后端并等待 `/healthcheck` 返回 `ok`。
    3. 刷新后重新构造 D02，再次点击“预览变更”。
- 预期结果：不可用期间不显示成功 SQL；页面没有永久 loading；服务恢复并重新构造表单后可生成 `DEFAULT 'codex_default'`，WebSocket 或其他页面错误不应掩盖请求结果。
- 恢复/清理：保持后端运行，刷新页签清理表单。

### DTE-LIFECYCLE-01 刷新后重新进入流程

- 风险/目的：P1，确认刷新会重新加载最新达梦插件 schema，不复用旧的冲突字段定义。
- 初始路由与状态：任一 SQL 预览已完成。
- 测试数据：D01。
- 准备方法：不执行 DDL。
- Chrome 操作：刷新 `/#/sql`，重新进入现有新建表页签或重新打开新建表入口，再新增一个字段并打开详情。
- 预期结果：页面重新加载完成；字段列表回到稳定初始状态；详情仍只有一个“默认值类型”控件；普通默认值预览继续成功。
- 恢复/清理：关闭详情并刷新页签。

### DTE-PERMISSION-01 查询权限与 DDL 权限边界

- 风险/目的：P0，确认修复没有绕过现有 `DM_QUERY_CONSOLE` 与数据源 DDL 权限判断。
- 初始路由与状态：分别使用具有 DDL 权限和仅查询权限的测试账号进入同一隔离达梦 Schema。
- 测试数据：D01。
- 准备方法：权限由管理员预先配置，本流程不修改权限。
- Chrome 操作：两类账号分别进入新建表入口并尝试生成 SQL 预览，不点击“立即执行”。
- 预期结果：有权限账号可按 Main Flow 预览；仅查询账号保持当前产品定义的缺少 DDL 权限提示或执行限制，不因 `defaultOpt` 放行而获得额外权限；两者均不得出现内部异常。
- 恢复/清理：退出测试账号，不修改角色或权限。

### DTE-STATE-01 表单、插件属性与 SQL 一致

- 风险/目的：P0，确认当前可见模式、输入值和生成 SQL 三者一致。
- 初始路由与状态：存在一个未保存的 D01 字段。
- 测试数据：D01、D02、D03、D04。
- 准备方法：逐一配置四种数据。
- Chrome 操作：每次从“列信息”进入详情确认当前模式和值，然后进入“SQL 预览”检查对应 SQL，再返回详情切换下一种模式。
- 预期结果：NULL、空字符串、自定义值和虚拟表达式分别映射为 `DEFAULT NULL`、`DEFAULT ''`、`DEFAULT 'codex_default'` 和 `AS (UPPER('codex'))`；切换后不存在跨模式残留；Console 无相关错误。
- 恢复/清理：刷新页签，确认“共 0 个字段”。

## Cleanup

1. 不点击“立即执行”，不向达梦提交任何 DDL。
2. 刷新新建表页签，确认字段列表恢复为“共 0 个字段”。
3. 保持 `DmAloneLauncher` 和本地达梦容器处于测试前的运行状态。
4. 恢复临时网络条件、账号会话和 Chrome 视口；关闭不再需要的测试弹窗。

## Skip Conditions

- 没有可用的隔离达梦数据源或 5236 端口不可达时，浏览器场景标记为 `SKIP`；可用模块构建和 SPI 映射检查作为补充，但不能替代真实 SQL 预览。
- Chrome 未登录或账号没有 SQL 工作台入口时，标记为 `BLOCKED`，不得读取认证数据或切换浏览器绕过。
- 没有仅查询权限账号时，`DTE-PERMISSION-01` 标记为 `SKIP`，并明确保留权限覆盖缺口。
- 无法安全控制本地后端生命周期时，`DTE-FAILURE-01` 标记为 `SKIP`；不得在共享或生产环境注入故障。
- 本流程禁止执行 SQL；若必须验证真实建表结果，应另行获得用户授权并使用可删除的隔离 Schema 与唯一表名。
