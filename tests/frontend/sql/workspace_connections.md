# SQL 工作台连接操作

## Purpose

验证数据源右键菜单中的打开连接、断开连接和重新连接，以及工作台状态、查询页签和会话释放的一致性。

## Scope

- 路由：`/#/sql`；入口：左侧数据源实例节点右键菜单和页签中的连接操作按钮。
- 状态：未连接、正在连接、已连接、正在断开、正在重连、连接失败。
- 接口：`query/createSession`、`query/closeSession`、元数据浏览接口及查询 WebSocket。
- 实现：SQL 工作台、DataSourceTree、SqlViewer、Operators、StructView、LuckySheetDataView 和 QueryEditorController。
- 操作仅针对当前工作台选定数据源的页签会话；不关闭其他数据源、其他用户、导出、工单或定时任务的会话。

## Preconditions

- 完成相关后端编译、测试及 `cd package && ./all_build.sh web`。
- 后端通过 pika-idea-control 启动，健康检查和嵌入 Worker 初始化完成；修改后端后确认加载的是新 JAR。
- 前端源码验收使用 `npm run serve:dm` 输出的 Local URL；打包入口验收使用 `http://localhost:8222`。`all_build.sh web` 只构建资源，打包入口验收前还需执行 `cd backend && ./gradlew :cgdm-web:jar` 并通过 IDEA 重启后端，确认 HTTP 返回的 SQL 资源与本次 JAR 中的资源哈希一致。在 [@Browser](plugin://browser@openai-bundled) 登录测试账号。
- 只使用隔离测试数据源和数据；故障注入只停止本次创建的数据库容器。
- 记录原有页签、语言和视口，保持用户草稿不变。不得检查浏览器认证存储。

## Suites

### WORKSPACE-CONNECTION-SMOKE-01 打开、断开、重连

- 风险/目的：P0，确认状态来自元数据读取、事务会话创建或查询结果，断开释放所选会话，重连不重放 SQL。
- 初始状态：WC01 实例未连接；菜单的“打开连接”可用。
- @Browser 操作：右键实例打开连接；分别双击同一实例的两个 schema 打开查询页签，在一个执行 `SELECT 42`，另一个保留未执行草稿。右键断开连接；通过菜单打开连接，再选择重新连接。
- 预期：操作期间显示进度，冲突操作不可用；成功后实例与所有相关页签状态一致，中文状态提示为“已连接”，英文为“Connected”。断开后提示“连接已断开”或“Disconnected”；执行、事务、数据编辑操作不可用，正文、结果和页签保留。再次打开关系型实例后，展开节点能看到重新加载的数据库/schema 列表，不能因断开时清空子项而永久失去展开入口。已有查询页签在打开和重连后获得新会话标识，自动提交仍按需连接，手动事务会话由原接口建立，原草稿不会自动执行，重新执行查询成功。
- 证据：初始菜单、断开状态、重连成功截图；数据库连接及后台会话关闭记录。
- 三角恢复：断开关系型实例后，子节点清空、实例折叠，但左侧展开三角保留。点击三角应重新建立连接并加载数据库列表，继续展开可加载 schema，不能重复插入子节点或在实例层新增查询页签。再次断开并刷新后仍显示三角，页面恢复展开状态本身不自动重连；主动点击能恢复。连接失败时保留折叠三角，恢复数据库后再次点击可以重试；操作期间重复点击不产生并发连接。实例层即可查询的数据源仍无展开三角。
- 双击恢复：断开后双击实例名称。关系型实例应重新建立连接并展开数据库列表，不在实例层误建查询页签；继续双击数据库/schema 可重新进入查询。实例层即可查询的数据源按原有流程打开查询页签并按需访问；访问失败时显示错误并保留页签草稿；连接操作期间重复双击不产生并发连接。刷新后仍断开的实例也应能通过主动双击恢复，后台刷新本身不自动连接。
- 清理：关闭本次查询页签。

### WORKSPACE-CONNECTION-LAZY-01 按需访问和状态来源

- 风险/目的：P0，防止额外探测、配置状态或仅分配会话编号就标记已连接，以及元数据失败被后续成功提示覆盖。
- 初始状态：数据源列表已加载；WC01 有未连接实例及可查询数据库，WC03 可选。
- @Browser 操作：展开 WC01，再打开查询窗口执行只读 `SELECT 42`；刷新对象列表。断开后点击保留三角或双击实例恢复，再执行查询。停止隔离 WC01 后执行强制刷新或显式重连，恢复容器再重试。检查恢复前后的状态与草稿。
- 预期：只调用原有元数据、会话和查询接口，不调用 `query/openConnection` 或管理端连接测试。展开／对象列表成功、手动事务会话创建成功、查询返回结果时更新已连接；元数据或会话创建失败显示失败，不被数据源配置中的 Normal 状态改回已连接。自动提交仅分配会话编号，不因此提前点亮实例图标。显式重连时对象列表失败会使整个操作失败，清理新建会话并保留显式重试要求；SQL 不被自动执行。
- 实例层数据源：未打开查询页签时，打开操作仅解除手动断开限制，保持未连接图标且不提示已连接；双击进入查询后由实际操作结果更新状态，不为测试连通而创建、丢弃临时连接。
- 请求检查：Browser 工具支持时检查相关请求名称；工具不支持时以源码调用和 task-local 探针补充，不检查认证参数。
- 清理：恢复隔离实例；仅关闭本次页签，不改变原有事务默认配置。

### WORKSPACE-CONNECTION-TABLE-DETAIL-01 表详情读取后的连接状态

- 风险/目的：P0，防止表详情读取成功后误标连接失败，导致对象列表消失、查询按钮禁用。
- 初始路由与状态：`/#/sql`，WC01 已连接并打开查询页签，对象列表已加载；记录原有 SQL 草稿。
- 测试数据与准备：使用 WC01 的 `connection_probe`，以及同一隔离库中已有的另一张表；没有第二张表时跳过跨表切换。
- @Browser 操作：单击表并展开列分组，随后双击表生成查询 SQL；连续双击同一张表，再切换另一张表并双击。重新连接后重复，刷新工作台后再次展开并双击；不自动执行生成的 SQL。
- 预期：表、列及索引正常加载，对象列表保留，实例保持已连接，Run/运行按钮可用；双击仅插入 SQL，不出现“无法打开工作台连接，请检查数据源或重试”。重连和刷新后行为一致，原有草稿保留。
- 失败与竞态：复用 WORKSPACE-CONNECTION-FAILURE-01 的隔离故障环境，读取失败仍显示失败状态；慢响应复用 `workspace_loading.md` 的代理，在表详情未返回时断开或重连，旧响应不得恢复已断开的连接或覆盖新连接状态。
- 恢复/清理：撤销本次双击插入的 SQL，恢复原草稿和连接状态，关闭本次查询页签；不删除已有表或数据源。

### WORKSPACE-CONNECTION-APPEARANCE-01 连接提示条

- 风险/目的：P0，防止深色连接失败提示使用浅色背景和白色文字，或窄屏重连按钮挤压正文。
- 初始路由与状态：`/#/sql`，已有隔离测试库查询页签及草稿；用已不可用的隔离数据源或已有连接失败页签验证，不停止共享数据库。
- 操作：查看连接失败提示，切换浅色、深色；点击重新连接，等待结果；通过数据源右键断开检查普通断开提示，再打开恢复。分别在 1440×900、1024×768、390×844 检查提示与按钮。
- 预期：失败提示使用错误语义底色、红色边线和可读正文，警告与普通状态各用对应配色；重连按钮是清晰的次级按钮，文案不被压缩，提示正文可换行。主题切换不改变连接状态和草稿；重试失败后仍可再次操作，恢复成功后提示消失。
- 清理：恢复原主题、视口及连接状态；仅关闭本轮临时页签，不执行 SQL、不改数据源配置。

### WORKSPACE-CONNECTION-MAIN-01 中断查询和事务回滚

- 风险/目的：P0，防止未确认中断、隐式提交或查询仍执行时提前释放会话。
- 初始状态：WC01 已连接，事务模式可设置。
- @Browser 操作：执行 `SELECT pg_sleep(20)` 后选择断开，先取消确认，再重复并确认。切换手动事务，插入测试行后重连；先取消，再确认。
- 预期：取消时会话、查询及事务不变；确认内容明确说明中断和回滚。确认后等待查询停止再关闭会话。事务测试行回滚，不被提交或重放；新会话仍保留手动事务设置。停止失败时显示失败并保留会话标识供重试。
- 证据：确认弹窗、执行结束状态、数据库独立连接查询测试行不存在。
- 清理：显式回滚尚未结束的测试事务，关闭本次页签。

### WORKSPACE-CONNECTION-FAILURE-01 失败重试及断开持久化

- 风险/目的：P0，防止失败显示已连接，以及后台恢复覆盖手动断开。
- 初始状态：WC01 已连接，页签有未执行草稿。
- @Browser 操作：断开后刷新、切换其他页签并重新进入工作台；在断开状态下停止 WC01 容器，尝试打开连接；刷新失败状态。恢复容器后显式打开连接并执行查询。
- 预期：手动断开及失败后的恢复限制在刷新、后台可见性恢复、WebSocket 重连后保持；没有自动创建查询会话。连接不可用时显示失败而不是已连接；行内错误提示显示可读文本，不显示 HTML 标签或实体编码。恢复数据库后显式重试成功，草稿保留且仅按用户执行操作运行。
- 证据：断开刷新和失败提示截图、重试成功结果、后台连接日志。
- 清理：恢复隔离容器可用状态。

### WORKSPACE-CONNECTION-REPEAT-01 重复操作和会话隔离

- 风险/目的：P0，防止重复会话及关闭范围扩大。
- 初始状态：WC01、WC02 各有查询页签，WC02 执行耗时查询。
- @Browser 操作：快速重复打开 WC01 菜单并点击连接动作，在操作期间切换页签；断开、重连 WC01；确认 WC02 查询正常完成。可用时在另一个已授权测试用户工作台运行查询。
- 预期：同一数据源操作串行，菜单在操作期间禁用冲突动作。只有 WC01 当前工作台页签的会话被关闭；WC02、其他用户、导出及后台任务不受影响。
- 清理：等待或显式停止本次查询，关闭本次页签。

### WORKSPACE-CONNECTION-PERMISSION-01 查询权限和连接配置

- 风险/目的：P0，避免要求数据源管理权限或绕过查询授权。
- @Browser 操作：使用 WC04 查询账号打开已有可查询数据源；无权限账号不能看到或操作该实例。可用时使用隔离 SSH/SSL 数据源打开、重连。
- 预期：有查询权限即可操作，不调用管理端 `datasource/testConnect`。归属及查询权限继续由原有元数据和查询接口检查；SSH/SSL 使用原有配置。
- 清理：恢复原登录账号，不修改用户权限或连接设置。

### WORKSPACE-CONNECTION-EXTREME-01 布局、编辑内容和语言

- 风险/目的：P1，覆盖 Boundaries、Extreme、State Consistency 和页面恢复。
- @Browser 操作：打开连接或刷新实例元数据，使节点加载子项；折叠实例并选中节点。在 1440×900、1024×768、390×844 查看实例状态、右键菜单和确认弹窗；通过页面入口切换中英文。断开时切换查询、结构和数据页签，再重连；可用时验证 WC03。
- 预期：菜单和弹窗动作可达；打开、断开、重连分别显示连接、断链、刷新图标，大小和对齐一致，禁用项的图标随文字变淡。数据源树不显示子项数量，实例名称右侧只显示连接状态图标；折叠、展开、选中及窄屏时不重叠，名称空间不足时省略，状态仍完整可见。长名称正常换行，状态和确认文案有中英文翻译。SQL 编辑内容仍可编辑；结构和数据页签保留表单及结果，连接恢复前不可提交或执行。实例层查询的数据源不额外探测；没有实际访问时不提前显示已连接，进入查询后由原有元数据或查询操作更新状态。
- 清理：恢复原语言和视口，保留用户草稿。

### WORKSPACE-CONNECTION-I18N-01 事务隔离级别与操作提示

- 风险/目的：P1，避免缓存启动语言或复用 WebSocket 线程导致中英文串用。
- 初始路由与状态：`/#/sql`，使用支持手动事务的隔离测试数据源，新建查询页签；不操作已有业务事务。
- 测试数据与准备：只执行 `SELECT 1`，不写入业务表。应用已加载本次后端改动。
- @Browser 操作：切换英文，打开事务菜单检查隔离级别名称；切换手动模式，执行查询后提交，再查询后回滚，最后恢复自动模式。切换中文并重复，再切回英文；刷新、关闭重开查询页签后再次检查。条件允许时使用两个不同语言的浏览器会话交替操作，检查语言隔离。
- 预期：英文显示 DEFAULT、READ UNCOMMITTED、READ COMMITTED、REPEATABLE READ、SERIALIZABLE 等当前数据源支持的级别；中文显示对应中文名称。每次操作新生成的事务模式、提交、回滚提示与当前界面语言一致；历史执行消息保持生成时的语言。切换语言不改变数据库支持的隔离级别及事务行为，不污染另一会话的标签或新提示。
- 清理：回滚本次尚未结束的事务，关闭测试页签，恢复原界面语言；不修改数据源默认事务配置。

## Skip Conditions

- 登录未完成、@Browser 不可用或数据库 fixture 未确认隔离时，依赖场景标记 BLOCKED，不使用应用 API 或状态注入代替浏览器操作。
- 没有第二用户、导出/后台任务或 SSH/SSL fixture 时，对应运行场景标记 NOT RUN；会话作用域和权限的代码级验证只作补充。
- 缺少 WC03 时，非关系型实例连接的真实运行验证标记 NOT RUN。
- 视口、语言或数据库独立连接验证不可用时，明确记录未覆盖项，不宣称整个验收通过。

### WORKSPACE-CONNECTION-TX-INIT-01 自动提交状态同步

- P0；使用本地隔离 CockroachDB / PostgreSQL 数据源，保留已有页签和 SQL。
- 新建自动提交查询页签，执行 `SELECT 1;`；在事务菜单中重复选择自动提交，再执行只读查询。切换手动事务，执行只读查询，再切回自动提交并执行查询；刷新恢复后再次执行。
- 预期：初始化和重复自动提交状态同步不调用显式提交、不关闭原有自动提交会话，不出现 `Cannot commit when autoCommit is enabled.`；真正手动转自动时仍完成原有提交/会话切换，后续查询成功。
- 清理：只使用只读 SQL，不创建业务数据；恢复自动提交模式，仅关闭本轮临时页签。
