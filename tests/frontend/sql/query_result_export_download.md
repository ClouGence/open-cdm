# SQL 查询结果导出下载文件名

## Purpose

验证 SQL 查询结果导出完成后，下载入口会先显示文件名确认弹窗；弹窗默认回显服务端生成的随机文件名，允许用户只修改文件主体名，并始终保留导出格式对应的文件后缀。防止文件名丢失、重复下载、结果页签切换和下载失败恢复造成错误下载。

## Scope

- 页面与路由：`/#/sql`。
- 关联接口：`/api/entry/query/exportResult`、`/api/entry/query/downloadResult`。
- 关联状态：结果页签 `exportState.downloadFile`、导出进度、下载文件名弹窗和下载 loading。
- 关联源码：`frontend/src/views/sql/components/Result.vue`、`frontend/src/locales/zh.json`、`frontend/src/locales/en.json`。
- 不覆盖：导出转换器内部实现、服务端临时文件清理策略、浏览器下载目录设置和超大文件下载性能。

## Preconditions

- 本地 `DmAloneLauncher` 已启动，访问地址为 `http://127.0.0.1:8222/`。
- 验证前端源码时使用 `npm run serve:dm` 输出的 Local URL，并确认 API 代理指向本地后端。
- Chrome 已登录具备 SQL 查询和查询结果导出权限的测试账号。
- 已连接一个允许执行只读 `SELECT` 的测试数据源。
- Chrome 允许当前站点下载文件；验证前记录浏览器下载目录中是否已有同名文件。

## Test Data

| 编号 | 数据说明 | 构造方式 | 清理方式 |
|---|---|---|---|
| QRD01 | 单行查询结果 | 执行 `SELECT 1 AS id, 'download_name_test' AS value` | 关闭结果页签 |
| QRD02 | 默认导出文件 | 对 QRD01 选择 CSV 或当前环境支持的默认格式并等待导出进度达到 100% | 删除本地下载文件，关闭结果页签 |
| QRD03 | 自定义文件主体名 | 使用 `query-result-下载测试` | 删除本地下载文件 |
| QRD04 | 非法文件主体名 | 依次使用空白、`.`、`..`、`query/result`、`query\\result`、`query*result` | 不产生文件，无需清理 |
| QRD05 | 两个可下载结果页签 | 分别执行 QRD01 两次并完成导出 | 删除本地下载文件，关闭两个结果页签 |

## Suites

### QRD-SMOKE-01 下载入口打开文件名弹窗

- 风险/目的：P0，确认导出完成后的下载入口不再直接请求文件。
- 初始路由与状态：进入 `/#/sql`，QRD02 导出进度为 100%。
- 测试数据：QRD02。
- Chrome 操作：点击结果区右下角“下载”。
- 预期结果：显示“下载文件”弹窗；弹窗只有文件名输入项、取消和下载按钮；输入框回显非空随机文件主体名；右侧固定显示与导出格式一致的后缀；尚未产生浏览器下载记录。
- 恢复/清理：点击取消关闭弹窗。

### QRD-MAIN-01 保留默认名称下载

- 风险/目的：P0，确认用户不修改名称时可以直接下载，行为与改造前一致。
- 初始路由与状态：同 QRD-SMOKE-01，下载弹窗已打开。
- 测试数据：QRD02。
- Chrome 操作：不修改输入框，点击“下载”，等待浏览器下载完成。
- 预期结果：按钮请求期间进入 loading 且不能重复提交；弹窗在下载响应成功后关闭；下载文件名等于弹窗中回显的主体名加固定后缀；文件可以正常打开并包含 QRD01 查询结果。
- 恢复/清理：删除下载文件，保留结果页签供后续场景使用。

### QRD-MAIN-02 使用自定义名称下载

- 风险/目的：P0，确认自定义名称仅改变浏览器下载名，不改变文件格式。
- 初始路由与状态：QRD02 导出进度为 100%。
- 测试数据：QRD03。
- Chrome 操作：打开下载弹窗，将文件主体名改为 `query-result-下载测试`，点击“下载”。
- 预期结果：下载文件名为 `query-result-下载测试` 加原固定后缀；文件内容与 QRD-MAIN-01 一致；页面仍保持导出完成状态，可以再次点击下载。
- 恢复/清理：删除下载文件。

### QRD-BOUNDARY-01 空名称和非法字符

- 风险/目的：P0，阻止生成空名称或跨平台不可用的文件名。
- 初始路由与状态：下载弹窗已打开。
- 测试数据：QRD04。
- Chrome 操作：依次输入 QRD04 中的值并点击“下载”；每次错误后重新输入下一项。
- 预期结果：空白值显示“文件名不能为空”；其他值显示“文件名包含非法字符”；弹窗保持打开；不调用有效下载、不产生浏览器下载记录；修改输入内容后错误提示清除。
- 恢复/清理：输入合法名称或取消弹窗。

### QRD-BOUNDARY-02 Unicode、空格和固定后缀

- 风险/目的：P1，确认常用可识别名称可用，且用户不能将文件伪装成其他格式。
- 初始路由与状态：下载弹窗已打开。
- 测试数据：主体名 `  查询结果 2026 数据  `。
- Chrome 操作：输入测试名称并下载。
- 预期结果：首尾空格被移除，中间空格和中文保留；下载文件仍使用原导出后缀；输入框没有编辑后缀的入口。
- 恢复/清理：删除下载文件。

### QRD-EXTREME-01 长文件名与窄视口

- 风险/目的：P1，确认长名称和窄视口不会破坏弹窗布局。
- 初始路由与状态：下载弹窗已打开。
- 测试数据：重复 `查询结果_` 形成明显超过输入框可视宽度的主体名。
- Chrome 操作：在 1024×768 和 150% 浏览器缩放下输入长名称，移动光标至首尾，观察弹窗和固定后缀。
- 预期结果：输入内容在输入框内部滚动；后缀、错误区域和 footer 按钮保持可见；弹窗不超出视口、不遮挡确认操作。是否能写入本地文件受操作系统文件名长度限制，本场景不据此认定前端失败。
- 恢复/清理：取消弹窗。

### QRD-REPEAT-01 连续确认只发起一次下载

- 风险/目的：P0，防止大文件下载期间重复请求和重复文件。
- 初始路由与状态：下载弹窗已填写合法名称。
- 测试数据：QRD02。
- Chrome 操作：快速双击下载按钮，随后在 loading 期间按 Enter。
- 预期结果：只出现一个有效下载请求和一个浏览器下载记录；下载按钮在请求期间保持 loading；取消按钮不可用。
- 恢复/清理：删除下载文件。

### QRD-LIFECYCLE-01 取消并重新打开

- 风险/目的：P1，确认上一次未确认的编辑不会污染下一次默认值。
- 初始路由与状态：QRD02 导出进度为 100%。
- 测试数据：先输入 `discarded-name`。
- Chrome 操作：打开弹窗、修改名称后取消；再次点击“下载”。
- 预期结果：首次取消不产生下载；重新打开时恢复 QRD02 的随机默认主体名和原后缀，不回显 `discarded-name`。
- 恢复/清理：取消弹窗。

### QRD-STATE-01 多结果页签名称互不污染

- 风险/目的：P0，防止不同结果页签复用同一弹窗时显示或下载错误任务的文件名。
- 初始路由与状态：QRD05 两个结果页签均已导出完成，当前选中第一个。
- 测试数据：QRD05。
- Chrome 操作：在第一个页签打开弹窗并记录默认名，取消弹窗；切换到第二个页签并再次打开弹窗，记录默认名并确认下载。
- 预期结果：两次打开分别回显各自导出任务的随机名；第二次下载使用第二个页签的名称和文件内容，不沿用第一个页签的输入或任务 ID。
- 恢复/清理：删除下载文件并关闭两个结果页签。

### QRD-FAILURE-01 文件失效后恢复

- 风险/目的：P0，确认临时文件过期或下载接口失败时不会伪造成功状态。
- 初始路由与状态：准备一个已超过系统结果缓存时间的导出任务，或在隔离测试环境将本次 `downloadResult` 响应替换为 500。
- 测试数据：已失效的 QRD02。
- Chrome 操作：打开下载弹窗并确认下载；观察失败提示后，重新执行 QRD01、完成导出并再次下载。
- 预期结果：失败时不产生有效下载文件，弹窗保持打开且按钮退出 loading；新导出任务可以重新打开弹窗并成功下载，不受旧失败状态影响。
- 恢复/清理：恢复接口响应，删除新下载文件并关闭结果页签。

### QRD-PERMISSION-01 无导出权限

- 风险/目的：P1，确认新增弹窗不绕过既有导出权限。
- 初始路由与状态：使用有查询权限但无查询结果导出权限的账号进入 `/#/sql`。
- 测试数据：QRD01。
- Chrome 操作：执行查询并尝试进入导出流程。
- 预期结果：既有权限控制阻止导出任务生成；无法通过文件名弹窗调用下载接口；页面显示现有权限提示。
- 恢复/清理：退出受限账号并恢复原测试账号。

- 关闭本流程创建的 SQL 结果页签。
- 如果调整过测试账号权限或替换过接口响应，恢复原权限和本地服务配置。
- 将浏览器缩放恢复到常用值。

## Skip Conditions

- 本地后端、可查询数据源或文件转换 worker 不可用时，可以执行静态构建、国际化检查和弹窗组件级检查，但主流程、真实文件内容和失效恢复必须标记为覆盖缺口。
- 无法安全调整缓存时间或构造 500 响应时，QRD-FAILURE-01 可以跳过破坏性准备，仅验证前端对非 Blob 响应退出 loading 的代码路径，并明确未完成真实接口失败验证。
- 无法取得无导出权限账号时，可以通过代码核对既有 `DM_QUERY_EXPORT` 权限链路替代 QRD-PERMISSION-01，但不得标记为浏览器实测通过。
