# SQL 数据源连接异常提示

## Purpose

验证连接异常弹窗清楚标识实际失败的数据源：正文仅显示对应数据库图标和“数据源「名称」连接异常”，不展示服务端原始错误详情；底部只保留关闭按钮，关闭不触发连接测试。

## Scope

- 页面与路由：`/#/sql` 的连接异常弹窗。
- 入口：展开不可用数据源、读取其数据库对象或恢复其查询会话。
- 关联接口与状态：浏览对象/创建查询会话接口、`SET_DATA_SOURCE_STATUS`、`connectedInstance`。
- 关联源码：`frontend/src/views/sql/index.vue`、`frontend/src/services/http/request.js`、`frontend/src/components/function/CustomIcon.vue`。
- 不覆盖：数据库连接驱动、故障修复、查询执行结果和通用错误队列。

## Preconditions

- 本地前端资源已构建，DM 已通过 IDEA 重启且 `/healthcheck` 返回 `ok`。
- 使用 [@Browser](plugin://browser@openai-bundled)，其中已登录具有 SQL 查询权限的测试账号。
- 已有一个明确不可用的隔离测试数据源，已知其显示名称和数据库类型；不停止用户数据库或修改连接配置来制造故障。
- 只执行元数据浏览，不执行 SQL、不修改收藏或用户草稿。

## Test Data

| 编号 | 数据说明 | 准备方法 | 标识与清理 |
|---|---|---|---|
| CE01 | 不可用的测试数据源 | 从当前环境选择已确认连接失败的隔离数据源，记录页面显示名称与类型 | 按名称定位，不依赖固定 ID；不删除数据源 |
| CE02 | 不同类型的另一个不可用数据源 | 可用时选择另一已有隔离数据源 | 用于核对名称和图标切换；不删除数据源 |
| CE03 | 长名称、Unicode、HTML 特殊字符和缺少错误详情 | 优先使用已有隔离 fixture；无法安全构造时使用源码渲染检查 | 不重命名用户数据源、不修改服务端响应 |

## Suites

### DS-CONN-SMOKE-01 简洁提示与数据库图标

- 风险/目的：P0，防止提示为空、名称来自错误页签或泄露内部错误详情。
- 初始路由与状态：`/#/sql`，弹窗关闭，记录当前查询页签及正文。
- 测试数据：CE01；准备方法见 Test Data。
- @Browser 操作：先在数据源搜索框按 CE01 的显示名称筛选，等待树节点稳定，再展开 CE01，读取其数据库对象以触发连接异常；观察弹窗。
- 预期结果：标题为“错误”；正文仅有对应数据库类型图标和包含 CE01 显示名称的连接异常提示；没有内部数据库标识、原始错误详情或重复提示行；底部仅有居中的“关闭”按钮，不展示“重新连接”；原查询正文不变。
- 恢复/清理：点击“关闭”，确认弹窗消失。

### DS-CONN-MAIN-01 关闭与连续错误

- 风险/目的：P0，防止关闭触发额外连接请求，以及连续异常时名称和图标残留。
- 初始路由与状态：CE01 的异常弹窗已打开。
- 测试数据：CE01、可选 CE02；准备方法见 Test Data。
- @Browser 操作：点击底部“关闭”，确认弹窗消失；重新浏览 CE01；若有 CE02，关闭弹窗后浏览 CE02。
- 预期结果：关闭仅收起当前弹窗，不发起 `/api/entry/datasource/testConnect` 请求；再次触发错误后仍只显示一份简洁提示；切换到 CE02 时名称和图标同步更新，不残留 CE01 的名称或原始详情。
- 恢复/清理：关闭测试弹窗，保留既有数据源和查询页签。

### DS-CONN-EXTREME-01 视口、名称和国际化

- 风险/目的：P1，覆盖 Boundaries、Extreme 和 State Consistency，防止图标收缩、长名称溢出和无详情时空白。
- 初始路由与状态：连接异常弹窗已打开。
- 测试数据：CE01、可选 CE03；准备方法见 Test Data。
- @Browser 操作：分别在 1440×900、1024×768 和 390×844 视口查看提示；通过页面语言入口切换中英文后重新触发错误。
- 预期结果：图标和提示作为一组在弹窗正文区域水平居中，图标清晰可见且不收缩；长文案自然换行并居中对齐，关闭按钮居中且可达；两种语言都只显示数据源名称和简洁异常提示；特殊字符按文本展示，缺少错误详情仍有完整提示。
- 恢复/清理：恢复语言和视口，关闭弹窗。

### DS-CONN-LIFECYCLE-01 关闭、刷新和重新进入

- 风险/目的：P1，防止弹窗残留或恢复后退回旧版详情展示。
- 初始路由与状态：`/#/sql`，CE01 的弹窗已打开。
- 测试数据：CE01；准备方法见 Test Data。
- @Browser 操作：分别使用“关闭”和右上关闭图标退出；重新浏览 CE01；刷新页面，再次触发连接异常。
- 预期结果：关闭后无残留遮罩；每次重新触发均显示同一个正确的数据源名称及数据库图标，原始详情始终不显示；刷新不丢失用户查询正文。
- 恢复/清理：关闭弹窗，恢复原查询页签。

Failure And Recovery 覆盖不可用数据源的错误提示、关闭与重新浏览；Repeat And Concurrency 覆盖连续触发，不进行数据库并发压力测试。Permission 不适用新增权限矩阵：本改动未修改入口、接口或权限判断，沿用账号既有查询权限。

## Cleanup

1. 关闭本流程的错误弹窗及本次新建的空查询页签，清除数据源搜索条件，恢复原查询页签、语言和视口。
2. 不删除或重命名已有数据源，不改动查询正文、收藏或连接配置。
3. 确认没有测试 SQL、事务或临时网络限制遗留。

## Skip Conditions

- @Browser 未登录时暂停依赖登录的场景，请用户完成登录。
- 没有明确不可用的隔离数据源时，真实错误弹窗标记 BLOCKED；代码级事件和渲染检查仅作补充。
- 没有第二种类型或 CE03 fixture 时，对应场景标记 SKIP，并保留图标绑定、名称转义及无错误详情的代码检查。
- 当前工具不支持视口、语言或请求检查时，记录未覆盖项，不得用未执行的浏览器断言替代。
