# AI 引擎配置与 SQL 助手

## Purpose

验证实例级 AI 配置、查询工作台助手、授权边界与生成结果使用流程，防止未配置模型仍可发送、草稿丢失、未确认结果被插入或 SQL 自动执行。

## Scope

- `/#/settings/ai`：引擎列表、统一 CCModal 表单、连接测试。
- `/#/sql`：AI 助手入口、Editor/AI 切换、上下文、历史、生成、停止和插入。
- `createSession` 是普通同步 JSON 接口；新建会话不查询远程库表，不占用模型或元数据运行名额。数据库上下文自动检索通过生成过程中的工具调用完成。
- 会话及轮次接口统一使用 `/api/entry/ai/turn` 前缀，包括 `getCapabilities`、`createSession`、`switchSessionModel`、`listSessions`、`getSession`、`cancelTurn`、`deleteSession`、`streamTurn`、`resumeTurn`；引擎管理接口使用 `/api/entry/ai/engine`。
- 不用本流程证明模型准确率、跨节点一致性、出站网络限制；这些需要独立后端/部署验证。

## Preconditions

- 按 `test-open-cdm` 流程启动 IDEA 中的 DmAloneLauncher，等待完整初始化和嵌入 worker 插件完成，健康检查返回 `ok`。
- 前端源码使用 `npm run serve:dm` 实际输出的本地地址；打包资源另用 8222 验证。
- 新安装通过 `V202609300001__ai_sql_assistant` 直接创建最终 7 张 AI 表。
- AI 数据使用 DM 通用加密，与平台其他模块采用相同配置。AI 接口沿用平台登录和业务权限，不需要单独配置浏览器来源白名单。
- @Browser 已登录实例管理员。权限场景另需已授权的测试账号/角色，不修改现有业务角色来制造条件。
- 主流程需已配置并连接测试通过的模型，以及允许将测试结构发给该服务的隔离数据库。密钥由用户在设置页填写，不放入测试文档或截图。
- 不依赖模型的场景可在没有引擎的本地实例执行。不得为得到空列表删除已有引擎。

## Test Data

- 表单测试名称使用 `ai_ui_<唯一标识>`，模型 ID 以供应商实际配置为准，上下文预算在实例统一配置中维护。缺 Key 校验不填写假 Key、不提交真实模型请求。
- 当前字段范围：名称 80、模型 ID 128、URL 2048、Key 8192 字符。独立上下文配置：大小 8192–1048576 tokens，默认 256000（256k）；不显示输出上限。
- 草稿使用“仅用于本地界面草稿，不发送模型。”；请求上限为 16384 UTF-16 字符。
- 权限检查使用已有隔离查询账号，不需要授予任何 AI 使用标签。
- 生成流程使用隔离数据库的只读 SELECT 需求。DML/DDL 不在本 UI 流程执行。

## Suites

### AI-HTTP-01 HTTP 下打开助手与生成请求标识

- 目的/优先级：P0，防止局域网 HTTP 缺少 `crypto.randomUUID` 时助手初始化、发送或重新生成失败。
- 初始路由/状态：使用当前本地测试机的局域网 IP，通过 `http://<本机IP>:8222/#/sql` 登录；另用 localhost 作为对照。不得关闭浏览器安全限制或把 HTTP 来源配置为安全来源。
- 测试数据/准备：复用可访问的查询页签；草稿使用“仅用于本地界面草稿，不发送模型。”。生成分支仅使用已获准的隔离模型和常量 SELECT，不发送业务结构或执行 SQL。
- 操作：点击 AI 助手，核对模型和输入框；输入草稿，关闭再重开，清空后刷新并重新打开。模型可用时新建独立测试会话生成常量 SELECT，结束后重新生成，再刷新恢复该会话；localhost 重复打开与关闭检查。
- 预期：两种访问方式均能打开完整助手，草稿关闭重开保持、清空后发送禁用；控制台没有 `crypto.randomUUID is not a function`。发送和重新生成使用不同且满足后端校验的小写 UUID v4 请求标识，均能进入生成并恢复终态，不自动执行 SQL。
- 恢复/清理：清空本次草稿、关闭助手与测试标签；仅清理本次独立测试会话，不改动原有查询、模型或浏览器配置。
- 跳过条件：没有有效隔离模型时跳过真实生成与重新生成，保留打开、草稿、关闭重开和刷新验证；没有非回环 HTTP 访问条件时该回归场景标记 BLOCKED，不能只以 localhost 通过替代。

### AI-PLATFORM-WIRING-01 平台 Console / DAO 装配

- 目的/优先级：P0，验证 AI 业务通过 DM 默认组件扫描、Mapper 扫描、Web 拦截器和国际化入口装配，防止模块迁移后漏注册或重复注册。
- 初始状态：按 `test-open-cdm` 完整构建，IDEA 刷新 Gradle 工程后启动 DmAloneLauncher；等待 FULL 模式、嵌入 worker 完成及健康检查通过。后端仅使用 `cgdm-console` / `cgdm-dao` 中的 AI 业务类。
- 操作：从工作台进入 AI 配置，核对已有引擎和搜索，打开新增表单触发必填校验后取消；进入数据查询，打开助手和历史，恢复一条已完成的授权会话，再刷新并重开。新建独立测试会话，请求只通过生成工具交付常量 `SELECT 37601;`，不读取表、不执行 SQL；输出过程中刷新重开，确认恢复至终态。另一独立会话在生成中停止，再刷新；使用已有隔离无权限账号检查设置/生成被拒绝，不修改角色权限来构造条件。
- 预期：引擎列表、历史与模型正常加载；文案可翻译、必填校验生效；SSE 能持续输出并正常关闭，刷新恢复没有持续等待或重复执行；已完成 SQL 与取消终态保留。权限拒绝继续走 DM 统一响应，SQL 执行仍需用户明确操作。
- 后端补充：分别验证 Alone / Console 启动配置的扫描范围、13 个 AI 方法的 RequestAuth、7 个 Mapper 的 XML 与 BaseMapper 映射、AI 文案及新 Controller 标签；检查 DAO 无 Console 依赖、模型协议与供应商源码不变、提示词内容不变。复用隔离 MySQL 的重复请求、事件序号及终态竞态验证。
- 清理：关闭复测标签，只删除本次创建的独立会话；不改既有会话、引擎、角色或业务库。没有可用模型或隔离无权限账号时分别标记对应场景 SKIP，不能用历史读取代替真实生成验收。

### AI-SHARED-01 通用分页、JSON 与国际化

- 目的/优先级：P0，确认 AI 使用 DM 的分页与国际化基础设施后，列表筛选、页码和错误提示保持一致。
- 初始状态：`/#/settings/ai`，已有管理权限的本地登录账号；只读使用既有引擎，不新增、删除或修改模型配置。
- 操作：进入配置页核对引擎和总数；使用已有完整名称或模型 ID 搜索，核对命中记录；使用不匹配的唯一关键词搜索，核对空列表，再清空关键词查询并刷新。数据超过 20 条时切换下一页并返回第一页，确认筛选后回到第一页。
- 预期：列表接口请求使用 `page: {pageNum, pageSize}`，响应采用 DM 通用分页字段 `records/current/size/pages/total`；前端直接读取 `records`，不保留 `items` 兼容分支。未指定分页时默认第一页、每页 20 条；页码范围 1–10000、每页范围 1–100，越界请求被拒绝。
- 错误与 JSON：后端 AI 文案由 `DmI18nUtils` 加载并按当前请求语言读取，保留原 AI 错误码；逐项校验中英文资源与原文一致。JSON 编解码直接使用 `JsonUtils`，不保留 AI 专用包装类、Mapper 副本或额外注入；工具参数继续由通用工具执行器和 Bean Validation 校验。存储解析错误走 DM 通用异常流程，模型流与工具参数的协议错误仍由对应协议层处理。SSE 的 `deadline` 和元数据 `schemaReadAt` 在数据边界保持 ISO 字符串，共享 Mapper 的全局配置不变。
- 恢复：进入 SQL 助手，从历史恢复已有只读测试会话；刷新后重新打开，确认消息、SQL 和日期可读，不重新生成、不执行 SQL。
- 元数据类型：后端对象与历史引用直接使用 DM `UmiTypes`。表/视图候选仍只来自 Table、View；不读取其他元数据类型。恢复变更前的历史引用，刷新后表/视图类型、列、外键引用及授权复核一致；JSON 名称保持 Table/View，不增加兼容分支或数据迁移。
- 时间与输入：数据库时间沿用 DM 的 `java.util.Date` 与 MyBatis 内置处理器，分页游标通过 `Date.from(Instant)` 绑定；接口时间仍为原 ISO 绝对时间，历史排序、跨页边界和运行超时判断保持一致。在 UTC、Asia/Shanghai、America/Los_Angeles 的 JVM 时区和 UTC、+08:00、-08:00 的数据库会话时区组合下，核对 DM 默认 JDBC 映射的读写、接口绝对时间、毫秒精度及空验证时间。原始 DATETIME 使用共用 JDBC 的表示，不要求各 JVM 时区下字面值相同。浏览器 IANA 时区、偏移回退、UTC 默认值及半小时时区保持原协议。UUID 校验和工具 schema 共用现有常量，合法小写 UUID 可用，非法值仍拒绝。
- 加密存储：模型、历史消息、SQL、提问答案和时间正常读取，刷新后内容一致。新建/编辑引擎保存 API Key 后正常读取，留空 API Key 的编辑保留原凭据。仅对隔离 fixture 做连接测试，不发送业务数据。
- HTTP 复用：普通 AI 请求通过 DM 通用请求层，提示词与 SQL 首尾空白不被裁剪；历史搜索、引擎查询、打开/取消编辑均结束加载。流式请求共用 DM 的登录失效、操作密码和 HTTP 错误处理；保留受理/闲置超时与取消。登录失效或权限不足使用隔离账号验证，不修改现有账号权限制造场景。
- 清理/缺口：清空筛选、关闭临时标签。无超过 20 条的既有引擎时，多页 UI 标记 SKIP，以服务层分页边界和真实第一页/空列表读取补充，不批量写入业务配置。

- 超时配置补充：解析全部 AI Mapper 并检查事务元数据，默认分别不设置语句超时与事务超时；设置 DM 全局 SQL/事务默认值后应直接继承。隔离库持有目标行锁超过 5 秒后释放，等待操作应继续完成；事务使用 DM 的 `rollbackFor = Throwable.class, propagation = Propagation.REQUIRED`；在隔离 Spring 代理中于真实写入后分别抛出受检异常、运行时异常和 Error，模型/供应商、会话/历史/运行及事件序号均应完整回滚。模型版本冲突、会话互斥、事件序号和取消终态保持一致。普通接口在超过原 40 秒后仍等待 DM 默认期限，用户取消仍中断请求；流式超时只重订阅原请求，不自动创建新轮次。

- 后端补充：批量首条历史逐项对比修改前 SQL，覆盖多轮、空会话、无对应运行的历史；每个非空页按当前页会话 ID 批量读取历史标识和运行，在 Java 中选择最早的有效历史，再批量读取正文；不逐会话查询，空页不执行 IN 查询。使用真实 MyBatis、Spring 事务和实际数据库验证 20+10 页、租户/用户隔离和角色拒绝。历史、运行、会话和事件 Mapper 均只读单表；运行与历史一对一，状态过滤和结果/答案装配在 `AiTurnStore` 中执行，超时查询按 deadline 排序并限制条数。对比修改前 SQL 的逐字段结果、分页及顺序，覆盖历史与运行一对一、重新生成使用新历史/运行 ID、过期候选顺序与条数，以及缺少运行记录的历史；重复 history_id 由唯一索引拒绝。
- 引擎查询补充：模型与供应商分别查询，在现有引擎服务中批量组装；模型名称和模型 ID 搜索的总数、顺序、页码与修改前查询一致，缺少供应商的模型不计入总数或占用页位置。供应商为空时返回空页，不生成空 IN，选择器仅读取四个公开字段，不读取凭据，也没有停用、隐藏和排序配置分支。编辑后的新版本和验证重置字段由 Java 准备；编辑重置旧验证信息，过期版本的探测结果不能写回。
- 引擎事务补充：每个引擎创建独立供应商配置；删除按模型版本条件删除模型后直接删除所属供应商，无共享引用检查。使用真实 Spring 事务，分别在可重复读和读已提交下验证同版本编辑/编辑、删除/删除和编辑/删除竞争；只允许一方成功，不死锁、不留下孤立凭据，失败方不覆盖获胜方凭据。供应商更新或删除失败时，模型修改也必须回滚；不同引擎仍可独立提交。模型与供应商读取之间提交一次编辑，普通读取不能拼出混合版本。
- 时间计算补充：数据库会话时区分别为 UTC、+08:00、-08:00，验证运行截止时间为 Java 使用数据库绝对毫秒时间加上配置秒数；事件毫秒时间来自同一数据库时钟，过期扫描绑定同一时钟构造的 Date。验证完成/取消/超时竞争只能落入一个终态，不能由于数据库与 JVM 时区不同延长或提前结束。数据库不保存节点或心跳，也不执行续写；完成、取消和超时的条件更新仍有效。不修改用户数据库的全局时区。

- 清理：清空筛选、关闭测试页，保留用户模型、会话和权限，不新增 migration。浏览器无足够数据时，多页及拒绝场景由隔离数据库与服务验证补充，并明确记录覆盖边界。

### AI-SESSION-ISOLATION-01 生成中切换与新建会话

- 目的/优先级：P0，防止旧流消息、工具结果、SQL 和异步加载状态覆盖当前会话。
- 初始路由与状态：`/#/sql`，已登录并配置有效模型，助手可用；只使用本次创建的隔离测试会话，不改用户历史或模型配置。
- 测试数据/准备：会话 A 请求先生成一条带 A 标记的常量 SQL，再生成长批次；会话 B 使用不同常量标记，短回复即可。均要求调用 generateSql、不读表、不执行 SQL。
- 操作：A 首批工具完成且仍生成时，新建会话，确认空态后发送 B；若单用户并发限流返回忙碌，确认 B 不出现 A 的消息，等待 A 结束后再发送 B，不修改限流配置。B 完成后从历史切回 A，检查生成中恢复或已结束结果；A 已结束时可重新生成 A 以继续验证切换。A 仍在生成时再从历史切到 B，核对消息、工具过程、SQL 和 URL 会话 ID；回到 A 停止并刷新，再切 B。A、B 输入框分别留不同未发送草稿，来回切换检查各自恢复。新建后留在空态，确认旧流结束不会出现消息或 SQL。
- 预期：新建立即断开旧订阅并清空可见轮次，不取消旧会话的后台生成。B 只显示 B 的内容；切回 A 只恢复 A 的过程，运行中 SQL 隐藏，终态后只显示 A 的已成功批次。停止 A 不改变 B；刷新后双方记录与各自终态一致。草稿按会话恢复，新会话为空。
- 竞态补充：使用实际组件方法控制异步返回顺序，让 A 的 send 完成或退出恰好发生在 B 的加载/新会话初始化期间；busy 必须保持到对应加载完成，自动续接在 loading/busy 期间暂停。验证 A→B→A 后旧 A 的确认响应仍被旧连接身份拦截；旧流迟到的正文、工具完成、结果、终态事件不能改写当前会话或结束当前活动轮次。加载运行中的 B 完成后只恢复 B。无受控网络故障环境时，这些排序通过隔离检查覆盖，不宣称浏览器故障注入通过。
- 清理：停止本次测试仍运行的轮次，清空各自草稿，关闭测试标签页；不执行生成 SQL，不修改编辑器，不删除用户已有会话。
- 跳过条件：无有效模型或浏览器登录不可用时说明真实生成验证缺口；模型过快结束时不得声称覆盖生成中切换，改用分批长输出重新验证。

### AI-DYNAMIC-CONTEXT-01 会话独立与数据库动态切换

- 目的/优先级：P0，会话不再永久绑定创建时的数据库、schema 或查询标签页。
- 初始状态：已配置可用模型；在同一工作台打开两个授权隔离查询 A/B，数据库或 schema 不同。已有历史会话用于升级回归。
- 操作：在 A 打开助手并发送“动态上下文验证 <唯一标识>：只说明当前数据库名称，不读取表、不执行 SQL”；保持同一会话切到 B，检查消息与未发送草稿保留，再发送“现在当前数据库是什么？”。再次在 A 发送并立即切到 B，等待完成。关闭原查询后，从其他查询恢复此历史；刷新后再次恢复。在当前查询插入一条只读 SQL，再撤销；确认期间切页检查取消插入。无数据库的 SQL 草稿页可用时发送通用 SQL 问题；不可构造时记录跳过，不伪造页面状态。
- 预期：A/B 中均显示同一聊天记录和草稿，无“绑定其他查询”“返回原编辑器”“原数据库/schema”限制。每条请求携带独立 levels，重试复用原快照；B 的新请求使用 B，发送后切页不会改变正在生成的 A 请求。历史在任意 SQL 查询页恢复，无须打开原库。旧回复保留原 SQL 方言，重生成使用当前库。SQL 插入只写点击时目标，不执行 SQL。未选择数据库时不暴露元数据工具，可回答通用问题或要求选择数据库。
- 权限与压缩：每轮历史及摘要仍按其原数据库快照校验权限，不能把不同库同名表的引用合并到当前库；上下文压缩保留各轮数据库归属。数据库切换不会造成 CONTEXT_REVOKED，真实撤权仍禁止外发。
- 存储：合并后的 migration 直接创建请求级 context_json，会话表没有固定数据库字段；已有开发实例整理后，各轮原数据库上下文、聊天记录、摘要与模型选择保留。
- 重复与边界：同一 requestId 改 levels 返回 REQUEST_CONFLICT；相同快照重试不重复生成；生成中切库不清空回答，不启动第二轮；插入确认期间切页不会误写其他编辑器。
- 响应式：1440×900、1024×768、390×844 检查切页后聊天仍可达，无额外数据库配置控件或溢出。
- 清理：清空测试草稿，不执行 SQL；保留用户既有查询、历史与模型配置，仅按授权清理本次测试会话。

### AI-FAILURE-01 停止、断线与恢复

- 目的/优先级：P0，防止流中断后显示虚假成功或自动重复请求。
- 初始状态：获准故障注入的隔离实例、有效引擎。
- 操作：生成中停止；在页面 A 发起带唯一标识的较长常量 SELECT 文本生成，页面 B 从历史恢复同一正在运行的会话，观察从“思考中”自动变为最终结果；另一次生成中关闭助手再打开、新建另一会话后从历史返回、整页刷新后重新打开；另一次断开浏览器网络并恢复，等待页面自动同步原请求状态；仅确认请求未受理时手动重试原请求；后端重启期间尝试打开查询，待就绪后重入。使用获准故障注入的模型网关分别返回半截工具参数、缺失 `[DONE]`、纯文本 `stop`，观察助手终态。
- 预期：停止后进入单一终态；中断时没有未经确认的插入按钮；不显示“刷新”按钮或“正在确认保存状态，不会自动重新生成。”说明；恢复使用 `resumeTurn` 重新订阅原请求，先显示快照中的已有文本、阶段、工具活动和上下文占用，再接收增量；关闭助手、新建会话、切换历史和刷新不取消后台生成，只有停止按钮取消。路由的 `aiSession` 保存当前会话，刷新重开可恢复；旧会话的迟到事件或请求完成回调不能改动新会话，同一会话重新订阅后旧回调也不能覆盖新订阅。终态后恢复操作，刷新和后端重启后历史仍保留工具活动与上下文占用；超时、失败或停止后只显示一条提示：有具体错误时显示错误，无具体错误时显示状态，不重复展示“已超时”和“本轮生成已超时。”；显示可用的重新生成图标，点击后沿用原问题与引用 SQL；同 ID 重试不重复生成；半截工具参数、缺失模型终态不能成为成功结果；合法纯文本 stop 可完成普通回答，完整 sql 围栏恢复复制/插入操作，普通回答不显示空 SQL 容器，随后可新建正常请求；查询配置未加载时不创建可渲染的残缺页签，服务恢复后可正常继续。
- 清理：恢复网络和服务，确保没有运行中的测试请求。
- 存储与恢复：在隔离数据库准备包含提问卡片、已选答案、分批 SQL、已完成及失败轮次和压缩摘要的历史；从原 `aiSession` 链接打开，原问题、答案、工具过程、完整 SQL 和摘要约束均保留。继续按先前选择的常量生成 100 条 SELECT，要求 generateSql 分两批各 50 条交付；生成期间刷新再打开助手，预期同一请求继续、生成时不展示 SQL 卡片，终态后两批在一个 SQL 卡片中合并展示、没有空行或重复语句，再次刷新仍可恢复。引擎列表、名称＋模型联合唯一和全局 256000 配置保持一致。
- 存储加密补充：在隔离数据库验证供应商凭据、消息、回答、编辑器选区、库表引用、摘要、历史事件和流式事件的非空存储值均为 DM 通用密文。所有字段通过 `StrSecretTypeHandler` 写入加密、读取解密，原始文本与 SQL 的首尾空白保持一致，结果和用户答案分别读取为明文 JSON，由现有会话服务组装页面与流式结果；模型历史回放直接读取独立答案，数据库映射不合并业务数据。刷新后核对完整 SQL、提问卡片的已回答状态和原答案、工具回放和压缩约束；恢复已回答轮次的 SSE 结果也必须带原答案。未回答问题仍可作答，已回答问题拒绝重复提交，模型续接使用原答案而不重新提问。避免明文落库、重复加密或漏解密。
- 存储层补充：在隔离数据库覆盖并发事件追加的序号唯一与顺序、重复日志回放、50 万字符 SQL 原文保留、终态后拒绝迟到进度、重新生成时关联历史/运行/两类事件一起清理、用户答案独立保存与重新绑定。模拟本节点没有运行对象时，读取其他节点的日志并追踪后续进度；终态已提交但最后事件尚未发布时仍应收敛到结果，权限失效或连接关闭后结束追踪。删除已完成的测试会话后，关联数据清理且存在删除标记；运行中删除应拒绝，不改变正在运行的请求。
- 连续断线补充：在本地临时故障代理中，第一条 `toolCompleted` 送达后切断 SSE，同时让状态确认暂时失败；第一次 `resumeTurn` 只送达 `started`，在 `snapshot` 前再次切断。预期已显示的说明、工具记录及内部保存的 SQL 不被清空，运行中仍不显示 SQL 卡片。恢复连接后，完整快照替换已有过程，再接收新事件；最终合并 SQL 逐行核对数量、顺序和唯一性。初始 `streamTurn` 只有一次，重连均使用原 sessionId/requestId 的 `resumeTurn`，不触发重新生成。
- 超时补充：第一批 SQL 返回后，故障代理保持连接但停止发送事件和心跳超过 40 秒，后台生成保持运行。前端超时后查询原轮次；已完成则直接显示保存结果，仍运行则重新订阅，均不得自动新建轮次。若服务端轮次本身已进入 EXPIRED，则停止恢复并保留已成功生成的 SQL，只有用户主动点击重新生成才开启新生成。受理超时后确认请求不存在时保留原 requestId 等待手动重试；确认失败或确认已受理不能自动重发初始生成请求。验证后关闭临时故障代理并恢复正常网络。
- 协议补充验证：浏览器受理等待 60 秒、流闲置 40 秒，10 秒注释心跳也计入活动；受理前错误是无轮次身份的 SSE `ERROR`（`code/msg/error/requestId`），正常已受理事件含 sessionId/requestId/turnId/seq；恢复首帧为 started，随后 snapshot，序号按本次订阅从 1 开始。通过临时传输与 Spring MVC 验证补充分片 UTF-8/CRLF、缺终态、受理错误、闲置超时、心跳续期；检查稳定 streamClientId 替换旧订阅以及迟到回调隔离，不新增测试类。

### AI-GLOBAL-ERROR-01 全局异常与 SSE 错误协议

- 目的/优先级：P0，确保普通接口保留既有全局异常协议，仅 AI 的 streamTurn/resumeTurn 补充 SSE 错误支持。
- 初始路由/状态：本地 `#/sql`，有效引擎，新建 AI 会话，测试用临时代理仅在本地修改一次请求；不执行 SQL。
- 数据准备：通过 generateSql 返回一条带唯一标识的常量 SELECT；临时代理分别从第一条 streamTurn 请求中移除 engineId，以及将 JSON 改为半截 `{`，不记录认证信息或请求正文。
- 操作：从页面正常发送，经代理触发真实后端校验。观察具体校验提示，确认没有新增已受理轮次或自动重复生成；恢复代理后点击“重试此请求”，等待结束，复制 SQL 核对内容并确认只有一个消息与 SQL 块。另一次发送触发半截 JSON，观察解析错误消息数组；恢复网络后手动重试。成功后刷新重开助手检查正文、工具活动和 SQL。
- 预期：错误事件名为 `ERROR`，全局错误内容包含 `code/msg/error/requestId`；具体校验提示及任意业务错误码/文案保留，前端优先展示后端消息，不能误报为网络错误。受理后运行错误仍保留 sessionId/requestId/turnId/seq 事件字段，内容使用同一错误字段，随后正常收敛到终态。停止、刷新恢复和 SQL 终态展示规则不变。
- 补充验证：用临时 Spring MVC 调用核对原来的五类全局处理：普通业务错误保留 code/msg；未知异常仍返回原来的 JSON 消息数组；@Valid 仍返回全部校验消息的 JSON 数组；日志和 Sentry 上报沿用原实现。不再单独处理 405、上传超限、绑定校验或 ConstraintViolationException，不强制普通响应 Content-Type，不重置响应；EOF 不再被全局认作客户端断开。普通请求未声明 SSE 时保持原返回；声明 SSE 时走与 ReAkh 相同的通用流式输出。
- 流式边界：与 ReAkh 的 writeErrorIfNecessary/isSseRequest 一致，Accept 包含 text/event-stream 或响应 Content-Type 为 text/event-stream 时输出 ERROR。不再保留 writeAiStreamError、AiStreamInterceptor.preHandle、AI 流式请求标记或专用 requestId 属性。流式 payload 的 requestId 使用原错误响应对象的 requestId，业务 code/msg 和未知异常消息沿用普通接口原实现；参数解析前的失败依靠 Accept 判断。成功与错误流使用同一响应头工具，包含显式 Content-Type；已提交的 SSE 可追加 ERROR，写入失败被捕获。普通非流式接口仍保留原有五类异常处理、消息数组和日志/Sentry，不引入响应重置或额外异常分支。
- 浏览器错误注入：内置浏览器允许访问本地测试代理时执行；若代理地址被浏览器拦截，标记错误注入 UI 复测为 BLOCKED，保留真实 Spring MVC 协议检查结果，不改用其他浏览器绕过。临时代理只修改第一次 streamTurn 的参数，分别删除 engineId 和截断 JSON。缺少参数显示校验消息数组，非法 JSON 显示原来的解析错误消息数组，两次都出现手动重试入口；代理日志确认仅用户点击发送/重试时发生 streamTurn，没有模型调用。点击“新建会话”清除本次未受理请求，关闭代理和测试标签页。已有数据源列表的 URL 构造错误不计作 AI 协议错误，单独记录。
- 运行错误回放：隔离元信息执行器抛出不属于 AiError 的业务错误与 CancellationException。业务异常保留原错误码、描述和原因；取消不能改成 METADATA_FAILED，物理许可均释放。终态保存、实时 ERROR、resumeTurn、历史 getSession 使用已经保存的 error_code/error_message，不再通过 AiError.valueOf 重建文案。超过截止时间时，状态、错误码及描述一起改为超时。
- 供应商异常：通过本地临时模型响应覆盖 HTTP 401/403、404、400、408、429、503、DNS 解析失败、读取超时及非法 SSE/JSON。预期直接使用 DM `ThirdPartyApiException`，分别保留既有 PROVIDER_AUTH、PROVIDER_MODEL_NOT_FOUND、PROVIDER_INVALID_REQUEST、PROVIDER_TIMEOUT、PROVIDER_RATE_LIMIT、PROVIDER_UNAVAILABLE、PROVIDER_UNRESOLVED_SERVER、MODEL_PROTOCOL；内容审核仍按 MODEL_CONTENT_FILTERED 处理。异常 cause 不丢失，没有 ChatError、ChatStreamException 或错误枚举映射。核对探测返回、运行 ERROR、失败终态及刷新恢复的 code/msg 一致；未知插件 messageKey 与参数按 DM 国际化机制原样处理，不归并 INTERNAL_ERROR。主动取消仍为 CANCELLED，轮次截止仍为 EXPIRED，连接和物理名额最终释放。
- HTTP/协议边界：代理返回 HTTP 503 且 JSON 不完整时，保留 HTTP_503；HTTP 200 的流式请求却返回半截 JSON 时，识别为 STREAM_PROTOCOL，不能冒充 NETWORK_ERROR。JSON 解析错误保留原始 cause，后台维护、终态发布和事件回放失败记录真实异常栈；连接 EOF/Broken pipe 只记普通断连。
- 恢复权限：第一批工具成功后切断订阅，同时让 getSession 返回 403/FORBIDDEN。预期停止自动重连、停止按钮消失、输入禁用，未确认的 SQL 不显示；日志在至少两个重连退避周期内没有新的 resumeTurn。确认 NOT_FOUND、HTTP 401/403/404 时相同；临时 503、断网和超时继续恢复原 requestId。恢复正常代理后通过刷新或历史重新进入，核对最终保存的 SQL，不重新生成。故障只修改本地代理响应，不修改真实账号权限。
- 清理：恢复代理为正常转发，等待已受理轮次结束，关闭测试标签页和临时代理；保留 SQL 编辑器原文。

### AI-TURN-SERVICES-01 轮次服务拆分回归

- 目的/优先级：P0，确认受理与运行、模型生成、订阅恢复的拆分不改变权限、幂等和终态语义。

- 生成行为补充：对拆分前后输入相同的文本、工具分批、提问、截断、空回复、缺失工具、工具上限、请求上限、内容过滤和压缩响应，比较请求消息、实际工具执行、事件、保存结果和模型 usage；contextUsage 使用既有估算算法，JDK 不可变 Map 顺序导致的 JSON token 估算差异单独核对。
- 清理：停止临时响应服务，删除本次临时会话和引擎，关闭测试标签页；不更改真实引擎、账号权限或数据库内容。

### AI-SQL-RECOVERY-01 停止、刷新与事件去重

- 初始状态：有效模型、新会话；使用不读表、不执行的常量 SQL，只改测试会话。
- 正常恢复：要求先生成一条常量 SELECT，再写较长正文，最后生成不同的第二条 SELECT。第一批工具完成且停止按钮仍显示时刷新并重开助手。恢复期间只显示工具过程和正文，SQL 代码块始终隐藏；等待完成后两条合并展示，刷新后行数、顺序和内容不变。
- 停止恢复：另一会话采用相同步骤，首批完成后刷新恢复并点击停止。只展示停止前已成功保存的 SQL；再次刷新保持一致，不出现下一批、不重复第一批，不恢复生成。停止后在同一测试会话发送新的常量 SQL 请求，确认可以再次生成并正常结束，随后刷新确认各轮状态与 SQL 独立保留。
- 关闭重开：首批成功且停止按钮仍显示时关闭助手，确认面板已卸载，再从工具栏重开；核对 URL 的 aiSession 未变、用户消息只有一份，工具前后的标记正文完整，成功工具记录不重复，生成中 SQL 仍隐藏。另一次在首批后关闭，让剩余批次在后台完成，再打开应直接显示终态，不重新生成。
- 完整结果核对：采用一条独立常量加连续编号的长批次，完成后通过“复制 SQL”与预期逐行比对；关闭重开和刷新后再次复制，三份内容必须完全相同、顺序一致且没有空批次或重复行。展开思考过程核对实际成功调用数，模型自行拆批时按日志中的实际调用数核对，不把多次合法调用当作重复恢复。日志中相同 requestId 仅有一次生成启动。
- 拦截器装配：`AiStreamInterceptor` 由共享 `WebConfigurer` 的 `@Bean` 方法注册，使用请求中的 `AiEventSink` 属性识别响应，不依赖接口路径过滤。重启后核对实际加载的类来自当前 Console 输出目录；在正常生成和生成中刷新恢复两条路径中，都应持续收到 SSE 并正常进入终态，停止后释放连接且不影响后续请求。
- 生命周期隔离补充：通过实际卸载钩子确认关闭会中断订阅和未完成 HTTP 请求，迟到正文、工具与终态事件不再更新旧组件；重开从 store、刷新从路由恢复相同会话。关闭期间的工具结果和最终答复仍被记录；重连以快照替换后再接收增量，重复快照和日志序号不累计内容。加载历史中再次关闭时忽略旧响应。
- 竞态补充：隔离事件记录器使工具完成记录在停止后被拒绝，内存状态必须保持写入前快照；重复回放同一事件序号不重复 SQL，终态后忽略迟到事件。快照接续下一批与完整日志回放得到相同 SQL。
- 前端补充：通过实际组件方法和 SSE 解析器验证 result 先于 done 到达时仍隐藏；完成后迟到的 RUNNING 确认响应不能隐藏 SQL 或重新激活恢复；加载更早消息的旧响应不能清除当前生成请求；重复 snapshot 和 SSE 序号只保留一份 SQL。主动中断的旧连接不得继续处理事件。
- 失败检查：请求出错后恢复使用同一 requestId，不重新调用模型；没有成功完成的工具参数不作为 SQL 展示。无有效模型或无法模拟的网络故障标记跳过，不把隔离验证等同于真实断网测试。
- 清理：关闭测试页；不执行生成 SQL、不修改模型、数据库或用户查询。
