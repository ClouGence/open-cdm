# SQL 工作台右键菜单

## Purpose

验证 SQL 工作台所有右键菜单具有清晰、统一的操作间距，并确保样式调整不会改变菜单分组、动作顺序或危险操作语义。

## Scope

- 页面与路由：`/#/sql`。
- 入口：数据库根节点、Schema 节点、表对象节点、查询页签、结果页签和结果数据行。
- 关联状态：右键菜单定位、菜单项间距、分隔线、图标对齐、视口边缘避让和重新打开。
- 关联源码：`frontend/src/views/sql/components/DataSourceTree.vue`、`TableList.vue`、`Result.vue`、`frontend/src/views/sql/index.vue` 与 `frontend/src/styles/global.less`。
- 不覆盖：建表、清空表、删除表等实际数据库写入结果。

## Preconditions

- 本地 `DmAloneLauncher` 已通过 IDEA 启动，访问地址为 `http://127.0.0.1:8222/`。
- Chrome 已登录具备 SQL 查询权限的测试账号。
- 已连接一个至少包含一张表的隔离测试数据源。

## Suites

### TCM-SMOKE-01 数据库树菜单间距与分组

- 风险/目的：P0，确认右键菜单不再紧凑，所有操作仍按原分组展示。
- 初始路由与状态：进入 `/#/sql`，数据源和数据库树已加载。
- 测试数据：D03。
- Chrome 操作：依次右键数据库根节点和 Schema 节点，检查菜单首尾、图标、文字和各分隔组；每次按 `Escape` 关闭后再次打开。
- 预期结果：菜单最小宽度 176px，菜单项最小高度 36px、水平内边距 16px、垂直内边距 8px；图标占位宽 28px且与文字对齐；鼠标悬停时显示选中底色和手型光标，禁用项仍显示不可用状态；分隔组上下各保留 4px；菜单顺序、危险操作颜色与重新打开行为不变。
- 恢复/清理：按 `Escape` 关闭菜单，不点击清空表或删除表。

### TCM-SMOKE-02 表对象、页签和结果区统一样式

- 风险/目的：P0，防止共享样式只覆盖某一类节点或菜单入口。
- 初始路由与状态：表对象列表已加载，查询页签已打开，并通过只读 SQL 产生一项查询结果。
- 测试数据：D01、D04。
- Chrome 操作：依次右键表对象、查询页签、结果页签和结果数据行；检查菜单尺寸、内边距和点击区域。
- 预期结果：四类菜单均使用与数据库树相同的 176px 最小宽度和 36px 最小行高；悬停非禁用项时均显示手型光标和选中底色；单项菜单不会退回紧凑样式；菜单内容和触发动作保持原有语义。
- 恢复/清理：仅用 `Escape` 关闭菜单，关闭为验证创建的查询页签，不触发导出或数据库写入。

### TCM-BOUNDARY-01 视口边缘与长文案

- 风险/目的：P1，防止加大间距后菜单越出可视区域或裁切文案。
- 初始路由与状态：数据库树和表列表已加载，并可将目标节点滚动到列表顶部、底部附近。
- 测试数据：D01、D02、D03。
- Chrome 操作：在 1440×900、1024×768、390×844 下分别打开数据库根节点、Schema 和表对象菜单，检查最长文案和菜单边缘避让。
- 预期结果：桌面和平板视口下菜单完整可见，必要时自动调整展开方向；文案不换行、不截断，图标不挤压文字；手机宽度若受 SQL 工作台既有最小宽度限制，只验证菜单自身尺寸未被压缩且无新增布局错位。
- 恢复/清理：恢复原视口并关闭菜单。

### TCM-STATE-01 非危险菜单动作保持可用

- 风险/目的：P1，确认样式类隔离没有破坏菜单点击事件。
- 初始路由与状态：普通表节点右键菜单已打开。
- 测试数据：D01。
- Chrome 操作：点击“属性”或“获取DDL语句”等非写入动作，确认对应弹窗打开并正常关闭；随后重新打开表菜单以及数据库树菜单。
- 预期结果：点击区域覆盖整行，目标动作只触发一次；弹窗关闭后所有入口的右键菜单均可再次打开。
- 恢复/清理：关闭弹窗和右键菜单，不执行任何数据库变更。

## Cleanup

2. 恢复 Chrome 原视口。
3. 确认未点击或提交建表、清空表、删除表等写入动作。

## Skip Conditions

- 无可用数据源、表节点或查询结果时，对应浏览器场景标记为 `SKIP`，但必须以源码清点确认所有 `ContextMenu.showContextMenu` 入口均使用共享样式类。
- 手机宽度下 SQL 工作台既有桌面最小宽度导致对象列表不可完整操作时，不执行菜单动作，只记录菜单尺寸与布局状态。
