# 数据源分类与快捷查询

## Purpose

验证数据源分类元数据能被 SQL 工作台读取，防止枚举序列化变化导致键值数据源或关系型数据源的快捷查询模板失效。

## Scope

- 路由：`/#/sql`，数据源列表、对象列表、双击对象生成的快捷查询。
- 后端契约：`DsConfig.classify` 来自 `DataSourceType.getClassify()`，枚举 `DsClassify` 序列化为字符串。
- 分类：`RDB`、`CACHE`、`DOCUMENT`、`MQ`、`SEARCH`；Etcd 保持 `CACHE`。
- 不覆盖数据源新增、证书上传、权限配置或写命令执行。

## Preconditions

- 本地 CloudDM 可访问，后端及插件已加载本次代码；@Browser 已登录具有实例读取权限的账号。
- 主流程需要预先配置可读取的隔离 Etcd 和关系型测试数据源；不得将生产实例当作测试实例。
- 使用现有配置，测试中不更改账号、连接或证书。

## Test Data

- 由环境维护者在隔离 Etcd 中准备 `codex_classify_<唯一标识>` 和带空格的键及已知值。
- 在隔离关系型实例中准备同前缀的表，使用明确存在的 Catalog / Schema。
- 数据准备和清理由环境维护者负责；浏览器复测仅执行读取操作。

## Suites

### DS-CLASSIFY-01 — 工作台加载与筛选恢复（P0）

- 初始状态：`/#/sql`，已登录，数据源列表加载完成。
- 数据准备：使用已有读取权限的数据源，无需创建数据。
- 操作：确认工作台和数据源列表可见；在数据源搜索框输入目标实例名称，再清空；刷新页面。
- 预期：筛选只显示匹配实例，清空后恢复列表；刷新后工作台正常加载，无新增 JavaScript 错误或持续加载状态。
- 清理：清空搜索框，恢复初始选中窗口。

### DS-CLASSIFY-02 — Etcd 键快捷查询（P0）

- 初始状态：`/#/sql`，隔离 Etcd 实例尚未打开，使用实例读取账号。
- 数据准备：维护者准备上述普通键、带空格的键和已知值。
- 操作：从数据源树打开 Etcd；双击普通键及带空格的键，观察生成的查询和读取结果；刷新后重试。
- 预期：生成 `get` 命令时替换为实际键名，无残留 `%%KEY%%`，带空格键保持完整引用；读取结果对应所选键；无 Schema 属性缺失异常。
- 清理：关闭本次打开的窗口，由维护者删除本次前缀的键。

### DS-CLASSIFY-03 — 关系型对象快捷查询（P0）

- 初始状态：`/#/sql`，隔离关系型实例尚未打开，使用实例读取账号。
- 数据准备：维护者准备上述测试表和可辨认的记录。
- 操作：打开实例及测试表所在的 Catalog / Schema，双击表生成快捷查询；刷新后再次进入。
- 预期：查询对应所选表和 Schema，无残留 `%%TABLE%%`、`%%SCHEMA%%`；正常读取测试记录，不进入键值模板分支。
- 清理：关闭本次打开的窗口，由维护者删除本次测试表。

## Cleanup

清空搜索框，关闭本次新建的查询窗口；保留原有窗口及 SQL。维护者仅清理本次唯一前缀的测试对象。

## Skip Conditions

- 未登录或服务未就绪：依赖场景标记 BLOCKED，不绕过登录或替换浏览器。
- 无隔离 Etcd / 关系型数据源或缺少读取权限：对应主流程标记 SKIP，不连接未经确认的实例。
- 分类、克隆、JSON 序列化检查与模块测试可补充验证契约，不能替代真实数据源交互。
