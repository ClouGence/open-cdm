# SQL 工作台分区加载

## Purpose

验证数据查询工作台先占位再分区加载，避免空态闪现、侧栏宽度变化、未初始化编辑器被操作，以及刷新时清空已有列表。

## Scope

- 路由 `/#/sql`；数据源树、查询页签恢复、对象列表、SQL 编辑器初始化。
- 状态：首次加载、列表刷新、连接校验、加载完成、真实空列表、接口失败、离开页面及重新进入。
- 接口：`browse/listLevels`、`browse/listLeaf`、`query/fetchDsStatusConf`、异步任务 dock；SQL 执行协议保持原有流程。
- 不覆盖结构/数据编辑器表单的独立加载流程，复用对应流程文档进行其业务回归。

## Preconditions

- 已通过前端 lint、国际化检查及 `cd package && ./all_build.sh web`。
- 后端通过 IDEA 运行于 8222；前端开发服务使用 `npm run serve:dm` 输出的地址，@Browser 已登录查询账号。
- 记录原有页签、SQL、选中状态、侧栏展开/收起、语言、视口和前端服务启动方式；不能删除用户草稿或读取认证存储。
- 打包入口验证前运行 `cd backend && ./gradlew :cgdm-web:jar`，通过 IDEA 重启并确认 HTTP 资源与新 JAR 一致。

## Test Data

- 优先使用已有本地测试数据源和空 schema，仅浏览元数据，不执行 SQL。保留原始 SQL 作为“不自动执行、不覆盖草稿”的检查点。
- 非空对象列表使用隔离测试 schema，或已有可查询且无需修改的本地元数据；不要在共享数据库中创建大量数据。
- 如 Browser 没有网络限速能力，可使用 `fixtures/workspace_loading_proxy.cjs`。它只监听回环地址，透明转发至 127.0.0.1:8222，不读取、输出或保存认证数据、请求体或响应内容。
- 在临时 JSON 文件中配置 `delays`（键为下列接口完整路径，值为毫秒）及可选 `failRoot: true`（`browse/listLevels` 返回 HTTP 503）。正常模式使用 `{}`。不把该配置加入仓库，不修改项目环境文件。

```json
{
  "delays": {
    "/api/entry/browse/listLevels": 4000,
    "/api/entry/query/fetchDsStatusConf": 2500,
    "/api/entry/browse/listLeaf": 15000,
    "/api/entry/asynctask/dockTask/listDockTask": 30000
  }
}
```

```bash
# From the repository root; choose a free loopback port and a task-owned JSON file.
node tests/frontend/sql/fixtures/workspace_loading_proxy.cjs /tmp/open_cdm_loading_mode.json 6089
# Restart only the task-owned frontend server, retaining its port/login origin.
cd frontend
CLOUDDM_BACKEND_URL=http://localhost:6089 npm run serve:dm -- --port 8081
```

## Suites

### WL-SMOKE-01 首次进入与分区就绪

- P0；初始 `/#/sql`，已有查询草稿，侧栏展开；使用慢响应配置。
- 刷新或从工作台入口进入。骨架出现后读取数据源栏、对象栏及编辑器的边界；继续观察页签和编辑器先恢复、对象列表后完成。
- 预期：数据源栏从首帧占据 250px，已保存的收起状态除外；查询区域有固定的页签、工具栏、编辑区和结果区域占位；恢复前不闪出 SQL 空态。
- 连接配置和对象数据未完成时不显示“暂无数据”或结果数量 0；对象栏通常为 260px，窄视口按照现有最小宽度收缩。编辑器区域横向起点和默认 250px 高度与骨架一致。
- 数据到达后只更新对应区域，骨架全部消失；原页签和 SQL 保留，不自动执行。异步任务 dock 的慢响应不阻塞工作台恢复。
- 清理：恢复正常代理模式和原视口。

### WL-MAIN-01 刷新保留原列表

- P0；初始元数据加载完成，有非空数据源/对象列表；延迟对应列表接口。
- 点击数据源树和对象列表的刷新，观察请求完成前后的内容与宽度。
- 预期：已有内容保持可见；数据源刷新按钮暂时禁用，对象列表刷新显示原有局部进度；首次尚未取得对象数据时使用骨架；已经确认的空列表在刷新时保留空态和局部进度，不重新显示模拟行。重复刷新不可并发提交。完成后恢复操作并显示新列表。
- 清理：等待请求完成，恢复原选中节点与搜索条件。

### WL-BOUNDARY-01 空态、收起与编辑器准备

- P1；使用真实空 schema，另用无保存页签的测试账号检查初始 SQL 空态。
- 观察空 schema 加载；收起侧栏后刷新；通过现有按钮再展开。检查编辑器准备阶段的 loading 状态及操作控件。
- 预期：真正的空列表仅在加载完成后显示；无保存页签时最终显示 SQL 空态。收起偏好保留，不能被骨架展开。Monaco 准备好前控件不可触发执行，准备好后占位淡出且草稿正确。
- 清理：恢复原账号和侧栏设置，不关闭或修改原有用户页签。

### WL-EXTREME-01 视口、主题与减少动态效果

- P1；在 1440×900、1024×768、390×844 重复查看首屏和完成状态，再通过产品入口切换明暗主题及中英文。
- 预期：骨架不产生额外线框、背景卡片或溢出；工具栏和面板位置沿用现有布局。loading 标签使用既有国际化文案；颜色使用主题 token。
- 如果 Browser 支持减少动态效果模拟，打开后检查脉动和淡入动画均停止，数据仍立即显示；不人为延迟正常响应。
- 清理：恢复主题、语言、视口和动态效果设置。

### WL-FAILURE-01 失败和恢复

- P0；加载完成后启用 `failRoot: true`，刷新数据源树；再刷新页面检查首次加载失败的收尾。
- 预期：已加载的数据源在失败刷新时保留；错误按既有错误提示展示，加载和刷新禁用状态能结束。首次失败时也不能永久显示骨架。切换正常模式并通过刷新按钮重试，列表恢复。
- 清理：恢复正常配置，关闭本次错误弹窗并等待恢复完成。

### WL-LIFECYCLE-01 离开、重入及连接操作

- P0；在加载期间通过返回工作台离开，再进入查询；元数据准备好后使用隔离查询页签执行已有 `workspace_connections.md` 的打开/断开/重连场景。
- 预期：重入从正确初始状态加载，旧响应不产生无法关闭的骨架；快速切换不同查询页签/对象类型时，先返回的旧请求不能提前结束当前请求的加载状态。连接操作期间占位宽度稳定，断开提示可见，重新打开可以浏览数据库/schema，SQL 不被自动执行。
- 清理：恢复原路由、原展开节点及查询草稿。

## Cleanup

1. 将代理模式改为 `{}`，等待本次请求结束。
2. 停止本次前端进程，按原方式重新启动（不设置本次 CLOUDDM_BACKEND_URL）；确认原 URL 可用。
3. 停止本次代理进程，删除本次临时 JSON 文件；不停止或修改无关服务。
4. 恢复原页签、选中项、侧栏、搜索、语言、主题与视口。若还要验证 8222 的打包资源，遵循 Preconditions 的打包和 IDEA 重启步骤。

## Skip Conditions

- 登录或 Browser 不可用时暂停依赖场景，不用状态注入替代。
- 代理/限速能力不可用时，慢响应和 HTTP 503 场景明确标记未执行；普通刷新和代码级异步收尾验证只能补充。
- 没有独立测试账号时，无保存页签及无数据源账号场景未执行；不删除用户内容构造空态。
- Browser 不支持主题/动态效果模拟或浏览器缩放时，对应项未执行，不能用 CSS 静态检查宣称浏览器验证通过。
