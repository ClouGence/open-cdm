# SQL 工作台 WebSocket 重启恢复

## Purpose

验证浏览器保持 SQL 工作台打开时，CloudDM 后端短暂不可用或重启后 WebSocket 会持续重连，并在服务恢复后自动恢复数据源状态、查询会话以及执行相关操作，防止必须刷新页面才能继续查询的回归。

## Scope

- 页面与路由：`/#/sql`。
- 入口：登录 CloudDM 后进入“数据查询”，打开一个已连接数据源的 SQL 查询页签。
- 关联接口与状态：`/api/entry/ws/channel`、WebSocket 关闭码 `1008`、`WS_SYS_STATUS`、`SOCKET_CONNECTION_OPEN`、`RECOVER_STATUS`。
- 关联源码：`frontend/src/services/socket.js`、`frontend/src/views/sql/index.vue`、`backend/clouddm-platform/cgdm-console/src/main/java/com/clougence/clouddm/console/web/global/ws/WsChannel.java`。
- 不覆盖：数据库服务本身故障、SQL 执行结果正确性、后端进程升级和数据迁移。

## Preconditions

- 本地 `DmAloneLauncher` 已通过 IDEA 启动，访问地址为 `http://127.0.0.1:8222/`。
- Chrome 已登录具备 SQL 查询权限的测试账号。
- 存在一个连接正常、允许浏览元数据和执行只读查询的数据源。
- 测试人员可以停止并重新启动同一个后端运行配置，且后端恢复后 `/healthcheck` 返回 `ok`。
- 测试期间不得刷新或重新打开 SQL 工作台标签页，除非场景步骤明确要求。

## Test Data

| 编号 | 数据说明 | 构造方式 | 唯一标识 | 清理方式 |
|---|---|---|---|---|
| WSR01 | 已连接的 SQL 查询会话 | 选择可用数据源和 schema，打开查询页签并输入一条只读 `SELECT` | 查询页签名称与选定 schema | 不执行写入；测试后关闭查询页签 |

## Suites

### WS-REC-001 初始连接可用

- 风险/目的：P0，建立重启前的可用基线。
- 初始路由与状态：进入 `/#/sql`，后端和测试数据源均可用。
- 测试数据：WSR01。
- Chrome 操作：
    1. 打开已连接数据源的 SQL 查询页签，等待 schema 和表列表加载完成。
    2. 在编辑器中保留一条只读 SQL，观察“执行”和“执行计划”按钮。
- 预期结果：
    1. 数据源、schema 和表列表正常展示。
    2. “执行”和“执行计划”按钮可用，查询页签和编辑器内容稳定。
- 恢复/清理：保留当前页面和查询会话，继续执行 WS-REC-002。

### WS-REC-002 后端重启后自动恢复

- 风险/目的：P0，确认后端不可用超过重连间隔时不会永久关闭 WebSocket 重连。
- 初始路由与状态：WS-REC-001 已通过，SQL 页面保持打开。
- 测试数据：WSR01、WSR02。
- Chrome 操作：
    1. 不刷新页面，停止当前后端运行实例并等待至少 3 秒。
    2. 确认执行相关操作进入不可用状态。
    3. 使用同一运行配置启动后端，等待健康检查和插件初始化完成。
    4. 继续保持页面不刷新，等待 WebSocket 自动重连。
- 预期结果：
    1. 后端中断时“执行”“执行计划”和“中断”按钮禁用，页面本身不崩溃。
    2. 后端恢复后，无需刷新页面，“执行”和“执行计划”自动恢复可用。
    3. 原查询页签、编辑器内容、数据源、schema 和表列表仍在；数据源状态刷新和会话恢复流程被触发。
    4. 恢复后浏览器不再持续产生连接失败错误。
- 恢复/清理：保持恢复后的页面，继续执行 WS-REC-003。

### WS-REC-003 重复中断不会产生僵死连接

- 风险/目的：P1，验证连续后端重启仍能由同一页面恢复，且不会因重复 WebSocket 实例导致状态抖动。
- 初始路由与状态：WS-REC-002 恢复完成，执行按钮重新可用。
- 测试数据：WSR01、WSR02。
- Chrome 操作：重复一次 WS-REC-002 的停止、等待和启动过程，全程不刷新页面；恢复后继续观察至少两个重连间隔。
- 预期结果：第二次中断期间按钮按预期禁用；服务恢复后按钮仅恢复一次并保持可用；数据源和查询会话仍正常；没有持续重连、重复通知、重复页签或明显状态闪烁。
- 恢复/清理：确认最后一个后端实例健康运行。

### WS-REC-004 退出登录终止重连

- 风险/目的：P0，确认明确的未登录状态不会继续建立 WebSocket。
- 初始路由与状态：SQL 页面已连接，测试账号允许重新登录。
- 测试数据：无需数据库数据。
- Chrome 操作：通过页面退出登录，等待至少两个重连间隔并观察页面与网络状态。
- 预期结果：页面进入登录态流程；现有 WebSocket 被主动关闭；不会继续尝试连接 `/api/entry/ws/channel`；重新登录并进入 SQL 工作台后只创建一个有效连接。
- 恢复/清理：重新登录测试账号，关闭本场景产生的查询页签。

### WS-REC-005 无效会话终止重连

- 风险/目的：P0，确认 WebSocket 自身鉴权拒绝连接时停止重连，不依赖登录查询接口判断连接生命周期。
- 初始路由与状态：两个 Chrome 标签页均已登录同一测试账号；标签页 A 停留在已连接的 SQL 工作台，标签页 B 可执行退出登录。
- 测试数据：WSR01。
- Chrome 操作：
    1. 在标签页 B 通过页面退出登录，使服务端会话失效。
    2. 保持标签页 A 不刷新，停止并重新启动同一个 `DmAloneLauncher`，等待健康检查和插件初始化完成。
    3. 观察标签页 A 的 WebSocket 连接状态至少两个重连间隔。
- 预期结果：服务端拒绝未授权 WebSocket 并以策略违规关闭码 `1008` 关闭连接；标签页 A 收到该关闭码后停止重连，不再持续请求 `/api/entry/ws/channel`；页面不会创建重复 WebSocket 实例。
- 恢复/清理：重新登录测试账号，关闭场景产生的查询页签和额外标签页。

## Cleanup

1. 确认最后一次启动的 `DmAloneLauncher` 健康运行，没有遗留旧 execution。
2. 关闭测试查询页签，确认未执行数据库写入。
3. 若执行了退出登录场景，恢复测试账号的登录状态。
4. 确认没有遗留轮询脚本或用于测试的额外浏览器标签页。

## Skip Conditions

- 无法控制后端运行实例时，WS-REC-002 和 WS-REC-003 标记为 `SKIP`，不得用刷新页面替代断线恢复验证。
- 没有可用数据源或账号缺少 SQL 查询权限时，只验证 WebSocket 生命周期，不得将数据源和会话恢复标记为通过。
- 不允许中断当前环境服务时，保留代码检查和构建结果，并在可隔离测试环境补做真实停启。
- 不便重新登录时可跳过 WS-REC-004，但必须通过源码确认明确未登录与退出登录路径仍会主动关闭 WebSocket，并记录该覆盖缺口。
- 无法安全恢复登录状态时，WS-REC-005 可使用不带认证信息的 WebSocket 客户端确认服务端以 `1008` 关闭，并检查前端关闭码分支；不得将未执行的多标签页浏览器流程标记为通过。
