# SQL 工作台 WebSocket 重启恢复

## Purpose

验证 WebSocket 断开后持续重连，连接可用后仅恢复数据源和会话状态，不补发 SQL、提交或回滚，也不新建旧查询的结果轮询。Worker 会话仍有效时保留其会话和事务；Worker 已重连或请求发起 Console 已退出、旧批次结果无法继续交付时，用户核对实际执行结果并显式重新连接。后端进入初始化模式时，旧页面识别系统状态并停止普通通道重连。

## Scope

- 页面与路由：`/#/sql`、`/#/initialization`。
- 入口：登录 CloudDM 后进入“数据查询”，打开一个已连接数据源的 SQL 查询页签。
- 关联接口与状态：`/api/entry/ws/channel`、`/api/entry/dmGlobalSettings`、查询会话 `closeSession` / `createSession`、WebSocket 关闭码 `1008`、`WS_SYS_STATUS`、`SOCKET_CONNECTION_OPEN`、`RECOVER_STATUS`。
- 关联源码：`frontend/src/services/socket.js`、`frontend/src/utils/dmGlobalSettings.js`、`frontend/src/views/sql/index.vue`、`backend/clouddm-platform/cgdm-console/src/main/java/com/clougence/clouddm/console/web/global/ws/WsChannel.java`。
- 不覆盖：数据库服务本身故障、SQL 执行结果正确性、后端进程升级和数据迁移。

## Preconditions

- 本地 `DmAloneLauncher` 已通过 IDEA 启动，或使用用户明确授权的隔离多节点测试部署；远程故障测试通过实际负载均衡入口访问，逐台停止 Console，确认另一节点就绪后再继续。
- @Browser 已登录具备 SQL 查询权限的测试账号。
- 存在一个连接正常、允许浏览元数据和执行只读查询的数据源。
- 数据源已选择实际安装的驱动族和版本，Console 与独立 Sidecar 均可读取对应驱动；先确认 namespace 列表可加载。
- 测试人员可以停止并重新启动同一个后端运行配置，且后端恢复后 `/healthcheck` 返回 `ok`。
- 初始化模式场景必须使用已确认可丢弃的空测试数据库，禁止清空或替换现有业务数据库。
- 测试期间不得刷新或重新打开 SQL 工作台标签页，除非场景步骤明确要求。

## Test Data

| 编号 | 数据说明 | 构造方式 | 唯一标识 | 清理方式 |
|---|---|---|---|---|
| WSR01 | 已连接的 SQL 查询会话 | 选择可用数据源和 schema，打开查询页签并输入一条只读 `SELECT` | 查询页签名称与选定 schema | 不执行写入；测试后关闭查询页签 |

| WSR03 | 初始化模式数据库 | 预先配置一个已确认可丢弃且无 CloudDM 表的空数据库 | 测试数据库名 | 测试后恢复原测试配置，不删除或重置其他数据库 |
| WSR04 | 可选的执行次数探针 | 仅在独立可丢弃测试库建立计数表，初始值为 0；不得使用现有业务表 | 测试库名和本次唯一表名 | 核实执行结果后清理本次创建的探针表 |

WSR04 可用于证实 SQL 没有重放。为本次测试生成唯一表名，建表并插入一行计数为 0 的数据；在编辑器中输入以下脚本后，必须全选两个语句再点击“执行”，避免只执行光标所在语句：

```sql
UPDATE <probe_table> SET executions = executions + 1 WHERE id = 1;
SELECT SLEEP(60);
```

本场景需要测试账号对隔离探针表具有写权限。计数变为 1 后再中断 Console；后续仅查询计数，不再次执行 UPDATE。

## Suites

### WS-REC-001 初始连接可用

- 风险/目的：P0，建立重启前的可用基线。
- 初始路由与状态：进入 `/#/sql`，后端和测试数据源均可用。
- 测试数据：WSR01。
- @Browser 操作：
    1. 打开已连接数据源的 SQL 查询页签，等待 schema 和表列表加载完成。
    2. 在编辑器中保留一条只读 SQL，观察“执行”和“执行计划”按钮。
- 预期结果：
    1. 数据源、schema 和表列表正常展示。
    2. “执行”和“执行计划”按钮可用，查询页签和编辑器内容稳定。
- 恢复/清理：保留当前页面和查询会话，继续执行 WS-REC-002。

### WS-REC-002 WebSocket 恢复后核对原会话状态

- 风险/目的：P0，确认后端不可用超过重连间隔时不会永久关闭 WebSocket 重连。
- 初始路由与状态：WS-REC-001 已通过，SQL 页面保持打开。
- 测试数据：WSR01、WSR02。
- @Browser 操作：
    1. 不刷新页面，停止当前后端运行实例并等待至少 3 秒。
    2. 确认执行相关操作进入不可用状态。
    3. 使用同一运行配置启动后端，等待健康检查和插件初始化完成。
    4. 继续保持页面不刷新，等待 WebSocket 自动重连。
- 预期结果：
    1. 后端中断时“执行”“执行计划”和“中断”按钮禁用，页面本身不崩溃。
    2. 后端恢复后 WebSocket 自动重连，服务返回就绪后恢复数据源状态，并通过 `RECOVER_STATUS` 核对旧会话状态；状态恢复不发送 SQL、提交或回滚。
    3. 原查询页签、编辑器内容和已显示结果保留。Worker 会话仍有效时不因单纯 WebSocket 断开强制换 ID；恢复状态不重建原查询的结果消费者，也不保证补齐断线期间的结果。原 Console 已退出或 Worker 会话已失效时，核对旧 SQL/事务实际结果，再通过显式重新连接先关闭旧 ID、后创建新 ID；关闭失败不创建替代会话。
    4. 恢复后浏览器不再持续产生连接失败错误。
- 恢复/清理：保持恢复后的页面，继续执行 WS-REC-003。

### WS-REC-003 重复中断不补发旧操作

- 风险/目的：P1，验证连续后端重启仍能由同一页面恢复，且不会因重复 WebSocket 实例导致状态抖动。
- 初始路由与状态：WS-REC-002 已完成，已核对原 Worker 会话或显式重新连接，执行按钮可用。
- 测试数据：WSR01、WSR02。
- @Browser 操作：重复一次 WS-REC-002 的停止、等待和启动过程，全程不刷新页面；恢复后继续观察至少两个重连间隔。
- 预期结果：每次中断期间按钮禁用；若离线发送入口发生拒发，展示已有的“连接已断开”提示并结束本次 loading，不另设专用文案；服务就绪后只恢复状态。有效 Worker 会话不被单纯断线废弃；确实失效或遗留不可继续消费批次时显式重连。没有重复页签、SQL 补发或新的旧结果轮询。
- 恢复/清理：确认最后一个后端实例健康运行。

### WS-REC-004 退出登录终止重连

- 风险/目的：P0，确认明确的未登录状态不会继续建立 WebSocket。
- 初始路由与状态：SQL 页面已连接，测试账号允许重新登录。
- 测试数据：无需数据库数据。
- @Browser 操作：通过页面退出登录，等待至少两个重连间隔并观察页面与网络状态。
- 预期结果：页面进入登录态流程；现有 WebSocket 被主动关闭；不会继续尝试连接 `/api/entry/ws/channel`；重新登录并进入 SQL 工作台后只创建一个有效连接。
- 恢复/清理：重新登录测试账号，关闭本场景产生的查询页签。

### WS-REC-005 无效会话终止重连

- 风险/目的：P0，确认 WebSocket 自身鉴权拒绝连接时停止重连，不依赖登录查询接口判断连接生命周期。
- 初始路由与状态：两个 @Browser 标签页均已登录同一测试账号；标签页 A 停留在已连接的 SQL 工作台，标签页 B 可执行退出登录。
- 测试数据：WSR01。
- @Browser 操作：
    1. 在标签页 B 通过页面退出登录，使服务端会话失效。
    2. 保持标签页 A 不刷新，停止并重新启动同一个 `DmAloneLauncher`，等待健康检查和插件初始化完成。
    3. 观察标签页 A 的 WebSocket 连接状态至少两个重连间隔。
- 预期结果：服务端拒绝未授权 WebSocket 并以策略违规关闭码 `1008` 关闭连接；标签页 A 收到该关闭码后停止重连，不再持续请求 `/api/entry/ws/channel`；页面不会创建重复 WebSocket 实例。
- 恢复/清理：重新登录测试账号，关闭场景产生的查询页签和额外标签页。

### WS-REC-006 初始化模式终止普通通道重连

- 风险/目的：P0，确认后端从完整模式切换到初始化模式时，旧页面不会无限重连普通 WebSocket 并持续产生 404 日志。
- 初始路由与状态：标签页 A 已在完整模式建立 `/api/entry/ws/channel`；后端可使用 WSR03 启动到初始化模式。
- 测试数据：WSR03。
- @Browser 操作：
    1. 保持标签页 A 不刷新，停止当前后端运行实例。
    2. 使用空测试数据库和同一个 `DmAloneLauncher` 配置启动后端，确认页面入口切换到 `/#/initialization`。
    3. 观察标签页 A 至少两个重连间隔，并另开初始化页面确认页面可达。
- 预期结果：
    1. 标签页 A 的普通通道断开后，前端通过 `/api/entry/dmGlobalSettings` 识别 `Initial` 或 `Upgrade` 状态并主动终止重连。
    2. 后端切换到初始化模式后最多出现状态识别前的瞬时失败，随后 `/api/entry/ws/channel` 的 `NoResourceFoundException` 不再按重连间隔持续增长。
    3. 初始化页面正常展示，专用 `/api/entry/init/ws/install-log` 通道不受影响。
- 恢复/清理：恢复原测试数据库配置并使用同一个 IDEA 运行配置重新启动后端；关闭额外初始化标签页。

### WS-REC-007 离线创建查询不保留残缺页签

- 风险/目的：P0，防止配置请求失败后仍创建缺少 support 的页签，使工具栏或对象列表渲染崩溃。
- 初始路由与状态：一个正常查询页签，左树已展开另一个本地测试 namespace；页面已刷新到当前构建。
- 测试数据：WSR01、WSR02，另一个 namespace 不含待保存的编辑内容。
- @Browser 操作：停止后端；双击另一个 namespace 尝试创建查询；确认错误提示后查看页签；重新启动同一服务并等待就绪，再双击相同 namespace；额外双击数据源实例层级。
- 预期结果：离线请求失败后不新增残缺页签，原查询保留；服务恢复后可以创建查询且工具栏/编辑器可见；实例层级若没有叶对象类型则不渲染对象列表，不出现 searchKey 或 autoCommit 的空引用错误。
- 恢复/清理：关闭本场景创建的空查询，确认后端健康运行。

### WS-REC-008 离线请求不排队

- 风险/目的：P0，防止连接建立期间或断开后补发 SQL、提交或回滚。
- 初始路由与状态：`/#/sql`，已连接 WSR01；可安全中断本地后端。
- 测试数据与准备：WSR01、WSR02，仅使用只读 SQL。
- @Browser 操作：停止后端，观察执行按钮禁用；服务恢复后等待 WebSocket 就绪，不点击重新连接，观察查询是否自动开始。随后明确重新连接数据源并执行一条新的只读 SQL。
- 预期结果：离线请求即时失败且不排队，服务就绪后只有状态恢复请求，没有旧 SQL、提交或回滚自动发送。有效会话可以由用户主动执行新查询；有遗留批次或失效会话时需显式重连，不自动抢占。
- 恢复/清理：确认后端正常，关闭测试查询页签。

### WS-REC-009 跨 Console 转发与结果中断

- 风险/目的：P0，验证请求经拥有 Worker 连接的 Console 转发，结果只由原发起 Console 消费；故障后不接管旧执行。
- 初始路由与状态：`/#/sql`；两个共享 MySQL 的 Console，Worker 连接 B，浏览器 WebSocket 连接 A；无粘性负载均衡可用。
- 测试数据与准备：隔离测试数据源，一条返回普通结果的只读 SQL 和一条可安全中断的慢只读 SQL；可选 WSR04 验证无重放。入口在 A 下线后应转发到 B，保持浏览器原地址且不刷新页面。
- @Browser 操作：
    1. 在 A 的工作台执行普通 SQL，观察结果、状态与执行结束。
    2. 执行慢 SQL，在接收期间停止 A；等待浏览器连至 B。
    3. 保持原 SQL 文本；重新连接前核对旧 `active_batch_id` 仍被保留，B 的状态恢复没有建立新结果消费者或重新发 SQL。明确重新连接数据源，再主动执行一条新的只读 SQL。
    4. 使用 WSR04 时，新查询读取探针计数，确认仍为 1；核对显式重连已关闭旧会话并创建不同的新 ID。
- 预期结果：普通 SQL 通过 A → B → Worker 返回 A 的 WebSocket，结果由发起方轮询一次。A 进程退出后旧批次认领保留，B 仅恢复状态、不补发 SQL、不新建旧结果消费者；必须显式关闭旧会话并建新会话才能重新执行。旧事务和执行结果需要人工核实，不承诺结果完整或事务已回滚。仅 WebSocket 断开而 A 和 Worker 均存活时，不强制废弃物理会话，原 A 的轮询仍是唯一消费者；本流程不提供断线结果补齐。
- 恢复/清理：确认慢查询实际结果，必要时由测试管理员显式清理旧数据库会话；恢复两个 Console 并关闭测试页签。

- 多节点补充核验：从代理连接日志确认本次浏览器通道确实连接到被停止的 Console，避免把停止其他节点算作通道恢复通过。旧 Worker 尚未完成重连时，显式重连可能提示无法释放会话；等待 Worker 新连接生效后重试，不重新执行写入探针。最终核对探针仍为 1、新只读查询成功、两个 Console 就绪且两个 Sidecar 在线。

- 异常退出补充核验：分别覆盖正常停止与直接向 Console 的 Java PID 发送 SIGKILL。先核对进程命令行及所属服务，不能把强杀 `catalina.sh` 等启动脚本当作 JVM 强杀；保留故障时间、实际 Java PID、Worker 所有者和连接代次。连接关闭或异步发送失败后，Sidecar 正在等待的 RPC Future 应及时失败，心跳继续按周期尝试，不能仍等待完整的 60 秒响应超时。旧所有者租约未过期时的注册拒绝属于连接隔离保护，不要求绕过租约立即接管。
- 执行与入口补充核验：在非事务工单第二条慢查询执行中强杀 Console，独立查询写入探针，最终逐条核对执行次数；未提交事务在故障后不得隐式提交，显式重连后确认旧连接释放和回滚。持续采样实际负载均衡入口，核对上游切换与响应耗时；已发送的写请求不得由代理重复提交。驱动就绪检查须分别实际命中两个 Console，核对各 Console 与 Sidecar 驱动文件一致，不能以一次请求成功代替多节点一致性。

### WS-REC-011 仅 WebSocket 断开保留有效 Worker 会话

- 风险/目的：P0，区分浏览器通道断开与真实 Worker 会话失效，状态恢复不能补发旧操作或建立第二结果消费者。
- 初始路由与状态：Console A/B 和独立 Worker 均保持运行，浏览器已建立空闲查询会话；仅可安全中断本次浏览器通道或隔离入口代理。
- @Browser 操作：记录当前 sessionId，执行只读查询；只断开浏览器 WebSocket 后恢复入口，等待服务就绪，再主动执行一条新只读查询。对慢查询重复通道中断，但不主动重发该查询。
- 预期结果：空闲会话恢复后 ID 不变，无 close/create 替换、旧 SQL/提交/回滚补发；慢查询仅有原发起 Console 消费结果，重连不创建旧结果轮询，已丢失的结果不承诺补齐。真实 Worker 仍保留原物理会话/事务；新查询只由明确用户操作发起，活动批次未结束时不能重复占用。
- 恢复/清理：核对慢查询实际结果后关闭本次查询页签，恢复隔离入口，不停止共享服务。

### WS-REC-010 Worker 换连接后拒绝旧会话

- 风险/目的：P0，验证不扩展 Worker 线上协议时，Console 仍会使旧连接上的 SQL 会话失效，避免隐式续用事务或重发 SQL。
- 初始路由与状态：`/#/sql`；独立 Sidecar 已连接，浏览器 WebSocket 所属 Console 保持正常；WSR01 已成功执行一次查询并建立物理会话。
- 测试数据与准备：WSR01，可选 WSR04；具备只停止本次隔离 Sidecar 实例的能力，不使用共享业务 Worker。
- @Browser 操作：
    1. 保持页面不刷新，仅重新启动隔离 Sidecar，等待 Worker 重新显示已连接。
    2. 不点击重新连接，直接在原页签点击“执行”。
    3. 观察旧会话拒绝提示，再明确点击“重新连接”，主动执行一条新的只读查询。
- 预期结果：Console 为 Worker 新连接记录新的 generation，并将原会话标为中断；第二步通过现有查询错误提示要求重新连接，不下发该次 SQL、不自动创建会话；第三步先关闭旧会话，再创建新会话并返回正常结果。使用 WSR04 时计数保持为 1。
- 恢复/清理：确认隔离 Worker 正常连接，核对旧 SQL 的实际结果后关闭测试页签；不修改其他 Worker 或已有数据库数据。

## Cleanup

1. 确认最后一次启动的 `DmAloneLauncher` 健康运行，没有遗留旧 execution。
2. 关闭测试查询页签；默认场景不执行写入。使用 WSR04 时，仅清理本次创建的隔离探针表，保留无重放核验结果，不修改其他数据。
3. 若执行了退出登录场景，恢复测试账号的登录状态。
4. 确认没有遗留轮询脚本或用于测试的额外浏览器标签页。

## Skip Conditions

- 没有双 Console、无粘性入口和独立 Sidecar 时，WS-REC-009 标记为 `SKIP`；单机停启不能代替跨节点验证。
- 没有可独立重启的隔离 Sidecar 时，WS-REC-010 标记为 `SKIP`，不得停止共享业务 Worker 代替测试。
- 无法安全制造执行中断时，WS-REC-008/009 对应中断步骤标记为 `SKIP`，保留构建及源码验证，不把未执行项写为通过。

- 无法控制后端运行实例时，WS-REC-002 和 WS-REC-003 标记为 `SKIP`，不得用刷新页面替代断线恢复验证。
- 没有可用数据源或账号缺少 SQL 查询权限时，只验证 WebSocket 生命周期，不得将数据源和会话恢复标记为通过。
- 不允许中断当前环境服务时，保留代码检查和构建结果，并在可隔离测试环境补做真实停启。
- 不便重新登录时可跳过 WS-REC-004，但必须通过源码确认明确未登录与退出登录路径仍会主动关闭 WebSocket，并记录该覆盖缺口。
- 无法安全恢复登录状态时，WS-REC-005 可使用不带认证信息的 WebSocket 客户端确认服务端以 `1008` 关闭，并检查前端关闭码分支；不得将未执行的多标签页浏览器流程标记为通过。
- 没有已确认可丢弃的空数据库时跳过 WS-REC-006，不得通过清空现有数据库制造初始化状态；必须保留前端状态探测分支的源码检查与构建结果，并记录旧页面生命周期覆盖缺口。
