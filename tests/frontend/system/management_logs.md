# 管理日志页

## Purpose

验证管理日志页使用统一的文字页签切换“操作审计”和“SQL审计”，防止审计类型下拉残留、页签状态与路由错位、快速切换旧响应覆盖，以及窄屏布局溢出。

## Scope

- 页面：管理 / 日志。
- 路由：`/#/manager/logs`、`/#/manager/logs/sql`。
- 功能：审计类型页签、操作审计筛选与列表、SQL 日志筛选与列表、分页、导出和日志设置入口。
- 权限：`CAT_RDP_OP_AUDIT`、`CAT_DM_SQL_AUDIT` 对应的页面可见性。
- 不覆盖：日志采集链路、导出文件内容正确性、日志留存任务执行和数据库中的审计数据生成。

## Preconditions

- 本地 `DmAloneLauncher` 已启动，访问地址为 `http://127.0.0.1:8222/`。
- Chrome 已登录 CloudDM，默认账号同时具备操作审计和 SQL 日志查看权限。
- 另准备仅具备其中一种日志权限的账号，用于权限场景；没有该账号时按 Skip Conditions 处理。
- 浏览器网络正常，操作审计和 SQL 日志接口至少各有一条可展示数据；空列表场景可使用无匹配结果的筛选条件构造。

## Test Data

- 操作审计：至少一条包含操作人、操作时间、资源类型和操作动作的记录。
- SQL 日志：至少一条包含操作人、数据源、执行状态和 SQL 内容的记录。
- 空结果：使用页面已有筛选条件输入不会命中记录的唯一文本，不修改或删除日志数据。
- 长内容：操作审计至少准备一条“操作资源”和“日志唯一信息”超出列宽的记录；SQL 审计使用已有的长用户名、长数据源名称或长 SQL
  记录。无法获得时只验证容器横向滚动，不伪造接口数据。
- 本流程仅查询和切换页面，不创建、更新或删除业务数据。

## Suites

### ML-SMOKE-00 页面与页签入口

- 风险/目的：P0，确认日志页可达且审计类型不再使用下拉框。
- 初始路由与状态：从侧边栏“管理”进入“日志”，账号具备两种日志权限。
- 测试数据：任意可加载的审计日志数据。
- 准备方法：确认侧边栏日志入口可见。
- 操作步骤：点击日志入口，观察页面顶部与第一行筛选项。
- 预期结果：URL 为 `/#/manager/logs`；内容顶部展示“操作审计”“SQL审计”两个文字页签；“操作审计”为激活态并仅在文字下方展示 2px 主色短下划线；页签区域没有满宽底边或下拉箭头；筛选栏直接从“操作时间”开始，页面标题、筛选栏、表格和分页均可见。
- 恢复/清理：无。

### ML-MAIN-01 审计类型切换

- 风险/目的：P0，确认页签、路由和页面内容保持一致。
- 初始路由与状态：`/#/manager/logs`，操作审计页签激活。
- 测试数据：操作审计和 SQL 日志各至少一条记录。
- 准备方法：等待操作审计列表 loading 结束。
- 操作步骤：点击“SQL审计”，等待列表加载完成；核对筛选项和表头；再点击“操作审计”。
- 预期结果：点击“SQL审计”后 URL 变为 `/#/manager/logs/sql`，仅“SQL审计”显示激活下划线，筛选项包含数据源、SQL 来源或 SQL 状态等 SQL 日志条件；返回“操作审计”后 URL 恢复为 `/#/manager/logs`，筛选项恢复为资源类型、操作动作等操作审计条件；两个页面均不显示审计类型下拉框，列表数据不会混用。
- 恢复/清理：停留在“操作审计”。

### ML-BOUNDARY-01 空列表与单权限页签

- 风险/目的：P1，防止空结果或仅一个可用审计类型时布局错位。
- 初始路由与状态：分别使用双权限账号和单权限账号进入日志页。
- 测试数据：无匹配筛选条件；仅具备操作审计或仅具备 SQL 日志权限的账号。
- 准备方法：双权限账号输入不命中数据的筛选条件；单权限账号重新登录后进入日志页。
- 操作步骤：查询空结果；再用单权限账号打开 `/#/manager/logs` 和另一审计类型的深链接。
- 预期结果：空结果时页签和筛选栏位置不跳动；单权限账号只展示被授权的页签；访问不可用审计类型时自动落到第一个有权限的页签和对应路由，不显示不可用页签或其数据。
- 恢复/清理：清空筛选条件，恢复双权限账号。

### ML-EXTREME-01 视口与长内容

- 风险/目的：P1，验证页签和日志表格在常见桌面及窄屏视口下可用。
- 初始路由与状态：操作审计列表已加载。
- 测试数据：包含长单元格内容的现有记录。
- 准备方法：保持浏览器缩放为 100%，确认操作审计中存在“操作资源”和“日志唯一信息”超出列宽的记录。
- 操作步骤：依次使用 1440×900、1024×768、390×844 视口检查两个页签和筛选栏；在操作审计和 SQL审计中分别将表格自身滚动区域滚动到最底部，查看最后一行及分页；返回操作审计长内容所在行，分别将鼠标移到“操作资源”和“日志唯一信息”上，再将鼠标移入完整内容浮层并选择其中一段文字复制。
- 预期结果：页签文字不重叠且可横向滚动；筛选项自然换行，查询和辅助操作可见；表格通过自身滚动区域查看超出内容，不撑破页面或产生双纵向滚动条；“操作资源”和“日志唯一信息”单行超长内容以省略号截断，鼠标悬浮时展示未截断的完整内容；鼠标移入浮层后浮层保持显示，文字可被选择和复制；滚动到底后最后一行完整可见且不被分页遮挡或裁切，分页始终完整位于表格下方；两个页签切换后布局高度稳定。
- 恢复/清理：恢复原视口。

### ML-REPEAT-01 快速连续切换

- 风险/目的：P1，防止快速切换时旧页面或旧请求覆盖当前路由。
- 初始路由与状态：`/#/manager/logs`。
- 测试数据：正常日志数据。
- 准备方法：等待初始页面加载完成。
- 操作步骤：快速依次点击“SQL审计”“操作审计”“SQL审计”，等待请求全部稳定。
- 预期结果：最终 URL、激活页签、筛选项和表格内容均属于“SQL审计”；页面只保留一个激活下划线，没有重复页签或异常 loading 遮罩。
- 恢复/清理：返回“操作审计”。

### ML-FAILURE-01 请求失败与恢复

- 风险/目的：P1，确认列表接口失败不会破坏页签和路由结构。
- 初始路由与状态：任一审计类型已正常加载。
- 测试数据：通过 Chrome 离线模式构造请求失败；无法稳定控制时标记 SKIP。
- 准备方法：记录当前 URL 和激活页签。
- 操作步骤：切换离线后触发查询或切换页签，观察错误；恢复网络后重新查询。
- 预期结果：失败时保留页签、筛选栏和当前路由，使用项目统一错误提示；恢复网络后列表可重新加载，激活页签与 URL 一致。
- 恢复/清理：恢复网络。

### ML-LIFECYCLE-01 刷新与前进后退

- 风险/目的：P1，确认深链接和浏览器历史恢复正确。
- 初始路由与状态：`/#/manager/logs`。
- 测试数据：正常日志数据。
- 准备方法：无。
- 操作步骤：切换到“SQL审计”并刷新页面；使用浏览器后退返回操作审计，再前进到 SQL审计。
- 预期结果：刷新 `/#/manager/logs/sql` 后“SQL审计”仍激活；后退和前进时 URL、激活页签和子页面同步变化，不短暂显示错误筛选栏或审计类型下拉框。
- 恢复/清理：返回操作审计。

### ML-PERMISSION-01 页面权限

- 风险/目的：P0，防止无权限审计类型通过页签暴露。
- 初始路由与状态：分别使用双权限、仅操作审计、仅 SQL 日志和无日志权限账号。
- 测试数据：不同权限账号。
- 准备方法：由管理员配置最小权限，测试结束后恢复。
- 操作步骤：进入日志页并尝试访问两个深链接。
- 预期结果：双权限账号显示两个页签；单权限账号只显示对应页签并自动修正不可用路由；无日志权限账号看不到侧边栏日志入口，直接访问时走项目统一无权限处理，不展示日志内容。
- 恢复/清理：恢复账号权限和登录状态。

### ML-STATE-01 筛选与页签状态一致性

- 风险/目的：P1，确认两个子页面的独立筛选状态不会与页签状态混淆。
- 初始路由与状态：操作审计页。
- 测试数据：两个页面均有数据。
- 准备方法：在操作审计中选择非默认查询类型并执行查询。
- 操作步骤：切换到 SQL审计，使用其筛选条件查询；再返回操作审计并刷新页面。
- 预期结果：每一时刻只展示当前路由对应的筛选字段和数据；页签不会因筛选请求改变；刷新后服务端数据、当前路由和激活页签保持一致，不出现另一审计类型的表头或结果。
- 恢复/清理：清空筛选条件。

## Cleanup

- 清空页面筛选条件并恢复操作审计页。
- 恢复 Chrome 网络、视口、缩放和测试账号权限。
- 本流程不创建或删除日志数据。

## Skip Conditions

- 没有双权限账号时，可验证当前有权限页签的样式和深链接刷新，双页签切换标记 SKIP。
- 没有单权限或无权限账号时，权限组合场景标记 SKIP，不用修改共享账号权限代替。
- 日志接口没有数据时，可验证页签、路由、筛选栏和空态，数据列内容场景标记 SKIP。
- 无法安全控制离线或接口错误时，失败恢复场景标记 SKIP，并保留正常网络下的刷新验证。
