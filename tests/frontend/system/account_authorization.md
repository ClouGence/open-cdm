# 账号资源授权

## Purpose

验证账号资源授权页在常规桌面、标准 MacBook 和浏览器高缩放下仍能完整选择资源、配置授权时间并进入预览，防止资源树、权限树和选项面板相互挤压或出现难以操作的横向页面滚动。

同时覆盖账号安全变更与 Web 会话契约：多设备撤销、正常 MFA、失效 MFA 的管理员恢复、预认证回调和部署路径，防止未完成 MFA 获得业务访问或管理员操作误撤销本人会话。

## Scope

- 页面：账号列表、单账号资源授权、批量授权的权限选择步骤。
- 路由：`/#/manager/account`、`/#/system/account/authdm/:uid`、`/#/manager/account/batch_authorization/permissions`。
- 状态：查看、编辑、授权预览、批量授权与批量移除。
- 账号资料与 MFA：本人修改邮箱/手机号、管理员修改子账号登录账号/邮箱/手机号后保持 TOTP 配置；个人资料路由 `/#/settings/profile`。
- 登录安全：`/#/login`、`/loginMfaValid`、`/loginMfaRecoveryStatus`、`/api/entry/user/manager/resetInvalidMfa`、`/logout` 与 `/api/entry/ws/channel`。
- 初始化：隔离空库的数据库配置、管理员登录配置、确认与执行；不再配置 JWT 密钥。
- 操作密码已移除：不提供设置/验证接口、弹窗、全局开关或 498/499 流程；历史操作密码审计仍可查看。
- 不覆盖：后端权限计算正确性、跨租户隔离、真实生产账号授权提交和数据源权限模型内部实现。

## Preconditions

- 本地 `DmAloneLauncher` 已启动，访问地址为 `http://127.0.0.1:8222/`。
- @Browser 已登录具备账号查看与 `RDP_AUTH_MANAGE` 权限的测试管理员。
- 至少存在一个可编辑的测试账号，以及包含实例、Schema 和表节点的测试数据源。
- 布局场景只浏览和选择资源，不点击最终“保存”；需要提交时只能使用隔离测试账号并在结束后恢复权限。
- 会话/MFA 场景使用独立元数据库和独立服务端口，加载内置授权插件；只向该隔离环境创建测试账号。浏览器按 `frontend/AGENTS.md` 执行；用户明确允许使用 `agent-browser` 时，同样使用独立浏览器会话，禁止读取真实 Cookie、Token、浏览器存储或认证器密钥。

## Test Data

- 选择一个显示名称带唯一标识 `codex_auth_<时间戳>` 的测试账号；不要依赖固定 UID。
- 资源树至少包含一个短名称数据源、一个超长中英文名称数据源、三层以上 Schema/表路径和一个空节点分支。
- 时间范围覆盖永久、一天、一周、一月、一年和自定义；自定义时间使用当前时间之后的有效区间。
- 批量场景使用两个可恢复权限的测试账号，预览后退出，不提交到共享环境。
- MFA 异常数据只在隔离库准备：由维护者定位本次唯一账号，分别将 `use_mfa` 设为 true 且无 MFA 配置，以及保留配置但状态为 `INVALID`；不得修改其他账号。正常 MFA 由测试操作者持有认证器，自动化环境可用自己新建的专用夹具密钥，不能从浏览器读取既有密钥。

## Suites

### AA-ROLE-01 自定义角色没有国际化别名

- 风险/目的：P1，防止自定义角色没有国际化别名时角色下拉框丢失名称，阻塞测试账号创建。
- 初始路由与状态：账号列表；管理员有创建账号权限。通过正常角色页面创建带唯一前缀的自定义角色；保留后端生成的角色名称和空国际化别名。
- 测试数据：一个内置角色和一个自定义角色；仅创建带唯一前缀的隔离账号。
- 操作：打开创建账号弹窗和角色下拉框；检查自定义角色的选项；选择正常角色并创建隔离账号。打开该账号修改弹窗，检查角色回显后取消。
- 预期：内置角色显示国际化别名，自定义角色显示真实 roleName，不显示数字角色 ID；下拉框可展开和选择，不出现 `toLowerCase` 或 Vue 组件更新错误；新账号角色与选择一致，修改弹窗回显不变。
- 恢复/清理：撤回测试资源授权后停用隔离账号；不修改既有角色。

### AA-MFA-CONTACT-01 账号标识变更保留 TOTP

- 风险/目的：P0，防止登录账号/邮箱/手机号仅作为认证器显示标识时，资料修改却撤销 TOTP 或导致下次登录跳过验证码。
- 初始路由与状态：个人资料 `/#/settings/profile`；管理员路径从 `/#/manager/account` 打开隔离子账号的修改弹窗。只使用维护者批准修改资料的隔离账号，MFA 已启用且状态为 `ACTIVE`。
- 测试数据与准备：分别覆盖 MFA 标识类型 `EMAIL`、`PHONE`、`ACCOUNT`；通过正常 MFA 设置流程准备，认证器由测试操作者持有，不读取或记录密钥、二维码内容、Cookie 或 Token。新登录账号和邮箱分别使用独立的 `mfa_contact_<唯一标识>`、`mfa_contact_<唯一标识>@example.invalid`，手机号由维护者分配，必须符合页面现有校验且不与其他账号冲突；记录原标识以便恢复。
- 操作步骤：本人分别修改邮箱、手机号、AK/SK 重置；管理员在不重置密码的前提下，分别修改目标子账号登录账号、邮箱、手机号，并覆盖一次同时修改三项。每次保存后刷新资料及安全页确认当前会话不被强制退出；最后单独退出并重新登录一次，由操作者使用当前登录账号和原密码输入认证器当前验证码。
- 预期结果：标识保存成功，不弹出“MFA 失效确认”；个人资料和管理员更新请求均不携带 `confirmMfaInvalid`。联系方式或 AK/SK 变更后当前登录会话保持有效，不出现退出登录或被踢回登录页；刷新后 MFA 仍启用且状态为 `ACTIVE`，不出现“重新启用”状态；下次登录仍要求 MFA，原认证器验证码仍可完成验证。认证器可能继续显示旧标识，不把显示不同当成失效。
- 边界与失败恢复：未启用 MFA 的账号修改联系方式仍按原流程完成；重复保存相同值不改变 MFA；非法格式、重复联系方式或保存失败时资料与 MFA 状态均不发生额外变更。需要确认失败最终状态时刷新页面，不仅依赖本地提示。
- 范围限制：主动重置/关闭 MFA、历史失效配置恢复不在本次变更范围，不借标识修改重置 MFA；外部账号未开启本地登录时不要求提供不存在的本地账号改名入口。
- 恢复/清理：通过相同资料入口恢复原登录账号/邮箱/手机号，确认恢复过程也不使 MFA 失效；不关闭或重置其他账号的 MFA。无获批隔离账号、认证器或可用 @Browser 时标记 SKIP，不修改现有账号制造场景。

### AA-MFA-RECOVERY-01 失效 MFA 恢复流程

- 风险/目的：P0，失效 MFA 账号登录必须走管理员恢复路径，不能绕过、不能导航到个人资料页自助处理。
- 初始路由与状态：登录页 `/#/login`；准备 `useMfa` 为 true 但 `mfaStatus` 非 `ACTIVE` 的隔离测试账号；管理员具备 `RDP_USER_MANAGE` 权限且不是目标账号本人。
- 测试数据：失效 MFA 目标账号；管理员账号；另一可登录账号作对照。
- 操作步骤：目标账号用密码提交登录进入失效 MFA 提示页；检查页面只显示联系管理员说明、恢复状态检查按钮和重新登录按钮，无验证码输入、无“稍后处理”、无个人资料入口；点击恢复状态检查，未处理时无页面迁移；管理员在 `/#/manager/account` 打开目标子账号修改弹窗，MFA 行出现“重置失效 MFA”按钮（仅 `useMfa` 且 `mfaStatus !== ACTIVE` 且非本人时显示）；确认弹窗后调用 `/api/entry/user/manager/resetInvalidMfa`；回到登录页重新点击恢复状态检查或直接重新登录。
- 预期结果：失效提示文案为联系管理员说明；恢复状态检查调用 `/loginMfaRecoveryStatus` 且响应 `recoveryRequired: true`，不签发任何会话；管理员确认文案明确说明会关闭失效 MFA、使目标全部会话退出、目标需重新登录并重新启用 MFA；成功后目标 `useMfa=false` 且 `mfaStatus` 清空，管理员本人会话不受影响；目标账号用密码可正常重新登录。操作者本人对自己的账号不显示该按钮。
- 边界与失败恢复：管理员取消确认不发起请求；重置失败时表单与列表状态不回退；`mfaStatus === 'ACTIVE'` 或无管理员权限时按钮不出现。
- 重复与并发：打开确认后切换或关闭编辑表单，请求仍只作用于确认时的账号；延迟响应不得覆盖另一个账号的表单。快速重复确认只发起一次在途重置。恢复状态检查遇到失效挑战或接口失败时回到新登录流程，不把旧挑战升级为业务会话。
- 正常 MFA 对照：密码通过后仍停留在验证码页；错误验证码留在该页，正确验证码才进入业务页面。测试维护者只核对隔离库的会话数量和挑战数量，不读取令牌或哈希；失败后不增加会话，成功后增加一个会话且对应挑战已消费。
- 恢复/清理：不关闭其他账号 MFA；目标账号如恢复启用 MFA，通过正常 MFA 设置流程重新完成。

### AA-SESSION-01 会话失效边界

- 风险/目的：P1，确认仅密码、禁用、删除、MFA 变更撤销目标会话，联系方式/角色/AK-SK 变更保留会话。
- 初始路由与状态：同一账号在两个浏览器会话分别登录；管理员会话独立登录。
- 测试数据：一个隔离子账号；一个管理员账号。
- 操作步骤：会话 A 修改本人手机号后连续操作；会话 B 由管理员修改角色并返回账号页；管理员修改目标密码、禁用账号、重置失效 MFA 分别独立验证；每次操作后刷新另一个会话的页面或调用 `queryLoginUser`。
- 预期结果：联系方式、角色、AK/SK 变更后其他会话与本人会话均保持登录；密码修改、禁用、删除、MFA 启用/重置/关闭后目标账号全部会话失效并回到登录页；操作管理员修改他人密码时管理员会话保持登录。
- 恢复/清理：恢复密码与启用状态；不遗留禁用账号。

### AA-SESSION-02 标签页共享与单设备登出

- 风险/目的：P0，登出必须撤销服务端当前会话，同浏览器标签页共享失效，其他设备不受影响。
- 初始路由与状态：同一隔离账号在浏览器 A、B 分别登录；A 再打开一个业务标签页。管理员使用独立浏览器 C。
- 测试数据与准备：本次唯一子账号，两个独立浏览器 Profile 或 `agent-browser --session`；禁止复制浏览器存储构造另一设备。
- 操作步骤：A 两个标签页均访问业务页面；在其中一个通过菜单退出账号，刷新另一个；刷新 B 的业务页面；再由 C 修改目标密码，等待保存成功后刷新 B。
- 预期结果：A 两个标签页均要求重新登录；A 登出后 B 仍可访问业务；管理员改密成功后 B 要求重新登录，C 刷新账号页仍保持登录。登出、验证码和被动 WebSocket 活动均不延长会话期限。
- 恢复/清理：使用新密码恢复隔离账号登录，退出测试会话；仅删除本流程独占的测试数据。

### AA-SESSION-03 回调清理、恢复布局与失败

- 风险/目的：P0，预认证回调数据应及时离开地址栏，失效 MFA 页面不能暴露业务入口或被异常响应绕过。
- 初始路由与状态：独立未登录浏览器，登录页；受控 Provider 测试环境可产生正常 MFA、失效 MFA 和补全注册资料的回调。
- 测试数据与准备：正常、失效 MFA 和首次 Provider 登录的隔离账号；无 Provider 时使用明确标识的虚拟回调仅验证页面状态，不据此宣称 SSO 端到端通过。
- 操作步骤：分别进入三类回调，等待页面加载，检查地址栏已恢复无回调查询的登录路由；失效 MFA 在 390×844、1440×900 和暗色主题下检查说明与按钮；点击恢复状态检查后刷新，再用后退/前进返回；在支持网络模拟的浏览器中分别让检查接口失败、超时，再恢复网络并重新登录。
- 预期结果：MFA 和恢复挑战、`completionToken` 均不残留地址栏；补全表单保留必要资料并提交 `completionToken` 字段，不发送已删除的 `token` 字段。失效页没有验证码输入、个人资料、“稍后处理”或进入工作台的按钮；说明、检查与重新登录按钮无溢出遮挡，检查按钮遵循主按钮样式。刷新丢失预认证状态后需重新登录，接口失败不进入业务页面。
- 恢复/清理：恢复网络、主题和视口，关闭仅为本流程创建的标签页。

### AA-SESSION-04 部署前缀与 WebSocket 生命周期

- 风险/目的：P0，Cookie 作用域与前端路径错配不能导致 HTTP 能登录而 WebSocket 无认证，撤销后旧连接不得继续传输数据。
- 初始路由与状态：分别使用根路径和 `/clouddm/` 的独立反向代理环境；前缀构建设置 `VUE_APP_BASE_URL=/clouddm/`，后端外部部署地址匹配该前缀。代理转发 HTTP 和 WebSocket，可将前缀剥离后转发给后端。
- 测试数据与准备：本次唯一账号、可只读查询的测试数据源；另一个独立设备作为撤销范围对照。不采集 Cookie、认证 Header、Token、哈希或 HAR 响应体。
- 操作步骤：在两个部署路径分别从登录页进入业务页面并刷新；通过查询区观察连接就绪，执行只读查询。检查请求的站点与路径，不检查认证内容；根路径连接 `/api/entry/ws/channel`，前缀路径连接 `/clouddm/api/entry/ws/channel`。断网后恢复、退出后重新登录；管理员独立修改目标角色或撤销目标会话，继续观察原连接。
- 预期结果：静态资源、登录、刷新和 WebSocket 都使用正确前缀，WebSocket URL 只附加语言参数。普通断网恢复可重连；1008 策略关闭停止重试，重新鉴权后创建新连接。撤销阻断后续业务校验，旧连接不再交付结果；跨节点被动推送最迟 30 秒停止，校验过旧或失败时不持续推送。角色变化不删除 Web 会话，刷新后按新权限生效。
- 恢复/清理：恢复角色、网络和代理配置；停止独立测试服务，清理本流程新建的元数据库与账号；保留共享开发服务。

### AA-SESSION-05 后台 HTTP 请求续期

- 风险/目的：P0，默认不设绝对上限，打开页面且持续有鉴权 HTTP 轮询时允许保持登录，仍须遵守续期阈值、活动过期、显式绝对期限和撤销边界。
- 初始路由与状态：隔离环境中已登录的业务页面；维护者按本次唯一账号定位其测试会话，只修改时间字段，不读取令牌或哈希。
- 测试数据与准备：默认窗口 24 小时、续期阈值 6 小时、最长寿命 `0`。准备首次登录超过 7 天但活动窗口仍有效、剩余 7 小时、剩余 1 小时、活动已过期和已撤销的独立会话；再在独立环境显式设置最长寿命 `604800`，准备距绝对期限 30 分钟的会话。每个场景重新登录准备，不依赖上一场景遗留状态；切换配置前撤销旧会话。
- 操作步骤：保持页面打开并等待既有后台 HTTP 轮询；需要稳定触发时，在同一登录上下文重复请求只读状态接口。维护者核对当前截止时间，重复一次请求；对照仅 WebSocket 握手、消息和被动推送。
- 预期结果：默认模式下，首次登录超过 7 天不影响仍有效的活动窗口；超过 6 小时阈值时不写数据库续期，剩余 1 小时时推进至当前时间加 24 小时，再次请求不重复推进。持续后台 HTTP 活动允许长期保持登录，浏览器持久化 Cookie 的期限随鉴权 HTTP 响应刷新。显式配置 7 天上限时，距绝对期限仅 30 分钟就最多推进至该期限，普通续期不重写 Cookie。活动过期、撤销或权限校验失败的请求不续期；WebSocket 活动不主动续期；清理任务在默认模式下不得仅因首次登录时间较早而删除会话。
- 恢复/清理：退出测试会话，清理本流程新建的数据，保留共享服务和其他账号。

### AA-SESSION-06 移除操作密码后保留鉴权

- 风险/目的：P0，删除操作密码链路后，查询与授权仍受会话、角色和资源权限约束，旧配置不得重新启用已删除流程。
- 初始路由与状态：独立服务加载最新构建，使用隔离元数据库；配置中故意保留旧 `clougence.rdp.console.oppassword=true`，不配置 `jwt.secret`。管理员和无授权测试账号均由本流程新建。

- 预期结果：仅本次登录方式与账号绑定方式都为 OIDC 时执行 IdP 跳转；本地会话在外部跳转前已撤销，失败、缺少 Provider 或重复退出不会恢复旧会话。回调返回部署首页，带前缀环境不会跳到站点根目录；回调不创建会话。仅检查导航的站点和路径，不读取或记录查询参数中的令牌、state、Cookie 或认证头。

### AA-KAFKA-01 Topic 独立授权与实例继承

- 风险/目的：P0，防止 Topic 授权写入实例路径或预览串用 Table 状态。
- 初始路由与状态：`/#/manager/account`，隔离测试管理员和可恢复权限的测试子账号；存在 Kafka 与关系型测试实例。
- 测试数据：两个 Topic；名称使用本次唯一标识，由环境维护者准备。
- 操作：进入子账号授权页，展开 Kafka 实例，选择一个 Topic，勾选读取并进入预览，检查路径后保存。重新进入查看，切换至关系型 Table 再切回 Topic；为同一 Topic 增加管理权限。最后在实例增加读取权限，查看 Topic 的继承状态。
- 预期：Kafka 实例下可选择 Topic，右侧显示“Topic 权限”和读取／管理权限；只展示 Topic 对象授权节点。Topic 授权路径仅包含该 Topic 名称，保存刷新后仍落在该对象上；关系型表仍显示“表权限”；实例读取权限显示为 Topic 的继承权限。
- 清理：恢复子账号原授权，由维护者清理本次对象；执行验证见 `../sql/kafka_object_browser.md` 的 KB-AUTH-02。

## Cleanup

- 不在共享环境提交授权；若隔离环境完成了保存，按测试前记录恢复测试账号原权限。
- 恢复 @Browser 100% 缩放、原窗口尺寸和账号列表筛选条件。
- 删除只为本流程创建的测试账号与测试资源时，必须确认其不被其他流程引用。

## Skip Conditions

- 无独立数据库、独立服务或内置授权插件时，不执行会改变密码、MFA、账号状态或会话时间的场景；不得改用共享开发库制造异常。
- 无真实 Provider、HTTPS 反代或双节点环境时，对应 SSO、Secure 传输和跨节点撤销标记 SKIP。虚拟回调、Cookie helper 检查与单节点测试只能作为补充，不能替代这些端到端场景。

- 没有 `RDP_AUTH_MANAGE` 权限时，可执行只读布局和路由场景；编辑、预览和提交标记为 SKIP。
- 没有可恢复的隔离测试账号时，不执行最终保存；预览验证不能替代服务端授权提交验证。
- 资源树没有 Catalog 或多层 Schema 时，对应页签和深层树场景可 SKIP，但必须保留长名称与多视口布局检查。
- 浏览器无法设置指定有效视口时，可用等效浏览器缩放和窗口大小替代，并记录未覆盖断点。
