# 发布流变更记录、级联进度与终态回收

## Purpose

验证发布流详情的变更记录能够稳定自动刷新，级联拓扑与工单事实一致，并重点防止“下游工单已关闭但级联批次仍被判定为运行中、触发变更长期禁用”的终态回归。

## Scope

- 页面：CI/CD 发布流列表、发布流详情、发布流变更进度弹窗、关联工单详情。
- 路由：`/#/cicd`、`/#/cicd/:id`、`/#/ticket/:id`。
- 状态：变更记录创建与轮询、父子发布流传递、下游成功/失败、工单关闭/取消、级联批次终态。
- 关联源码：`flowDetail.vue`、变更记录与进度组件、`ChangeApprovalHandler`、`ChangeCascadeServiceImpl`、变更批次与变更 Mapper。
- 不覆盖：生产数据变更、第三方审批平台内部状态机、大规模并发发布性能。

## Preconditions

- 本地 `DmAloneLauncher` 已启动，访问地址为 `http://127.0.0.1:8222/`。
- Chrome 已登录具备发布流查看、触发、拓扑和工单查看/关闭权限的账号。
- 准备一个可安全触发的内置根发布流和至少一个启用的下游发布流；目标必须是隔离测试数据库。
- 使用 `SELECT 1;` 等无副作用 SQL。不得在生产或共享数据源执行写入。

## Test Data

- 标准根发布流：名称带 `codex_cascade_<唯一标识>`，配置一个启用的下游发布流。
- 标准变更：通过页面触发，SQL 使用 `SELECT 1;`，变更名称由页面生成或带本次唯一标识。
- 终态失败链：根变更完成并创建下游工单后，通过正常工单入口关闭或取消下游工单。
- 列表边界：分别准备 0 条、1 条、刚好一页和超过一页 1 条记录；无法安全批量构造时按 Skip Conditions 处理。
- 清理时关闭未完成工单，等待级联批次进入终态，再删除仅为测试创建的发布流关系。

## Suites

### RF-SMOKE-01 页面、记录与操作入口

- 风险/目的：P0，确认发布流详情可达且核心记录操作没有丢失。
- 初始路由与状态：从 `/#/cicd` 进入一个测试根发布流详情。
- 测试数据：标准根发布流和至少一条历史变更。
- 准备方法：按唯一名称在 CI/CD 列表定位发布流并点击“详情”。
- Chrome 操作：核对发布流名称、状态、配置项、发布流拓扑、触发变更、发布目标和变更记录；打开首条记录的“进度”。
- 预期结果：URL 为 `/#/cicd/<数字ID>`；操作按权限显示；变更记录加载完成；进度弹窗可打开和关闭；无相关 Console 错误。
- 恢复/清理：关闭弹窗。

### RF-MAIN-01 新变更记录自动出现

- 风险/目的：P0，验证触发后无需刷新浏览器即可看到新记录。
- 初始路由与状态：测试根发布流详情已加载，“触发变更”可用。
- 测试数据：标准变更。
- 准备方法：记录当前首行名称和总数。
- Chrome 操作：点击“触发变更”，检查 SQL 编辑器字体样式后按页面要求提交 `SELECT 1;`；停留在详情页观察列表和状态。
- 预期结果：触发变更编辑器与“SQL 变更内容”弹窗使用同一份 Monaco 字体配置：Menlo/Monaco 等宽字体、14px、400 字重、21px 行高、0 字距；提交期间不会重复触发；成功后列表立即刷新，记录未生成时继续无整表遮罩轮询；新记录在后续刷新中出现，状态变化不导致列表闪烁或滚动跳动。
- 恢复/清理：保留该记录供后续级联场景使用。

### RF-MAIN-02 级联进度与工单链接

- 风险/目的：P0，确认进度树层级、状态和工单链接正确。
- 初始路由与状态：根变更已经传递到至少一个下游发布流。
- 测试数据：标准变更。
- 准备方法：等待变更记录出现“进度”操作。
- Chrome 操作：打开“进度”；核对根节点、下游层级、负责人、状态和工单链接；通过工单链接进入详情后使用浏览器后退。
- 预期结果：根与下游节点通过稳定连线呈现；层级、状态和负责人对应真实记录；工单链接进入 `/#/ticket/:id`
  ；后退后仍可重新打开进度；悬停不产生下边框、尺寸变化或布局抖动。
- 恢复/清理：返回发布流详情并关闭进度弹窗。

### RF-BOUNDARY-01 空列表与分页边界

- 风险/目的：P1，防止 0/1 条和分页边界出现重复或丢失。
- 初始路由与状态：分别进入没有变更、只有一条、刚好一页和超过一页一条的测试发布流。
- 测试数据：列表边界数据。
- 准备方法：使用安全 fixture 或已有隔离数据，不在 Chrome 中手工创建大量记录。
- Chrome 操作：检查空态、总数、上一页/下一页、翻页、刷新和搜索。
- 预期结果：0 条展示明确空态；1 条无多余可用分页；跨页记录不重复不丢失；刷新和搜索后页码、总数与服务端一致。
- 恢复/清理：恢复默认搜索和第一页。

### RF-EXTREME-01 视口、长名称与拓扑层级

- 风险/目的：P1，验证详情和进度弹窗在窄屏、长文本与多层级下可用。
- 初始路由与状态：包含长发布流名和至少一个下游节点的详情页。
- 测试数据：名称使用真实字段允许范围内的长文本；深层拓扑只通过安全 fixture 构造。
- 准备方法：打开发布流详情和进度弹窗。
- Chrome 操作：在 1440×900、1024×768、390×844 下检查详情、记录表格和进度弹窗；快速打开/关闭进度两次。
- 预期结果：页面无文档级横向溢出；表格按既有方式滚动；操作不被遮挡；长名称可辨识；进度节点和连线不重叠；重复开关不残留遮罩。
- 恢复/清理：恢复桌面视口并关闭弹窗。

### RF-REPEAT-01 轮询、重复操作与旧响应

- 风险/目的：P1，防止重复触发、轮询叠加和旧响应覆盖新状态。
- 初始路由与状态：可触发的根发布流详情。
- 测试数据：标准变更。
- 准备方法：打开详情，另开同一详情的第二个 `codex` 标签页。
- Chrome 操作：快速连续点击触发入口；在一个标签观察状态、另一个标签刷新；快速切换路由后返回。
- 预期结果：运行态限制只阻止真实运行批次；一次有效操作只产生一条变更；两个标签最终状态一致；旧响应不覆盖终态；离开后不残留重复轮询。
- 恢复/清理：关闭重复标签页。

### RF-FAILURE-01 请求失败与恢复

- 风险/目的：P1，确认列表/进度请求失败不误报成功或破坏页面。
- 初始路由与状态：详情和至少一条记录已加载。
- 测试数据：历史只读记录。
- 准备方法：在隔离环境临时离线，或让可控测试服务返回 500/超时。
- Chrome 操作：触发一次列表刷新或打开进度；观察失败状态；恢复网络后再次查询或打开。
- 预期结果：失败走项目统一错误提示；已有内容不被清空成错误成功态；loading 能结束；恢复后可获得最新记录和进度；没有叠加重试风暴。
- 恢复/清理：恢复网络条件。

### RF-LIFECYCLE-01 页面可见性与资源释放

- 风险/目的：P1，确认轮询只在页面需要时工作。
- 初始路由与状态：存在非终态记录的发布流详情。
- 测试数据：标准变更。
- 准备方法：停留详情直到至少一次自动刷新完成。
- Chrome 操作：切换到其他 Chrome 标签超过一个刷新周期；返回；进入配置项或离开详情；使用后退重新进入。
- 预期结果：页面隐藏期间停止无意义轮询，重新可见后立即刷新并恢复；组件卸载后不再请求列表；重新进入只有一组轮询，状态与服务端一致。
- 恢复/清理：返回发布流列表。

### RF-PERMISSION-01 查看、触发与工单权限

- 风险/目的：P0，防止只读用户执行触发或关闭工单。
- 初始路由与状态：分别使用完整权限、只读和无页面权限账号访问同一测试发布流。
- 测试数据：标准根发布流和下游工单。
- 准备方法：管理员为测试账号分配最小权限，测试后恢复。
- Chrome 操作：检查发布流入口、触发变更、配置项、进度、工单链接和关闭工单按钮；在登录失效后刷新。
- 预期结果：只读账号只能查看允许内容；无触发权限不显示或不能执行入口；无工单操作权限不能关闭；登录失效走统一登录处理，不泄露详情。
- 恢复/清理：恢复权限并重新登录。

### RF-STATE-01 下游工单关闭后的级联终态

- 风险/目的：P0，防止关闭/取消下游工单后批次永久停留 `RUNNING`。
- 初始路由与状态：根变更已完成，下游工单处于可关闭或可取消的非终态；根发布流的“触发变更”因该批次运行而禁用。
- 测试数据：终态失败链。
- 准备方法：从变更进度的下游节点进入关联工单。
- Chrome 操作：通过正常入口关闭或取消下游工单；返回根发布流详情；等待变更调度器下一次扫描并刷新页面；打开原记录“进度”；再次刷新或重新进入详情。
- 预期结果：下游节点保留“失败”事实；原批次不再被判定为运行中；“触发变更”恢复可用且不再出现“级联批次仍在运行”提示；刷新和重新进入后结果不回退；新的关闭/取消事件能立即进入终态，历史遗留记录可由调度补偿收敛。
- 恢复/清理：不要再次触发变更；关闭进度弹窗。

## Cleanup

- 关闭或完成本流程创建的测试工单，确认级联批次已进入终态。
- 删除仅为测试创建的父子发布流关系、发布流和本地下载文件；共享历史记录不直接删库。
- 恢复账号权限、Chrome 网络条件、缩放和窗口尺寸。
- 确认没有遗留运行中变更、重复标签页或进度弹窗遮罩。

## Skip Conditions

- 没有隔离数据源时，触发与级联推进必须 SKIP；只读历史进度不能替代主流程。
- 没有下游工单关闭权限时，RF-STATE-01 只能验证历史终态展示，关闭事件路径必须标记覆盖缺口。
- 没有多角色账号时，权限套件标记 SKIP，不得用管理员结果替代。
- 无法安全注入指定 HTTP 错误时，至少验证离线恢复，其他状态码报告未覆盖。
- 没有稳定 fixture 构造分页或深层拓扑时，相应边界/极限场景 SKIP，不能在 Chrome 中手工制造大量数据。
