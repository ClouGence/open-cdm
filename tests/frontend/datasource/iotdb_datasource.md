# IoTDB 工作台与测点授权

## Purpose

验证 IoTDB 按模型浏览、查询页签恢复、测点权限申请与授予，以及共享工作台和授权组件对现有数据源的兼容性。

## Scope

- 页面与路由：`/#/sql`、`/#/system/permission`、`/#/system/account/authdm/:uid?type=edit`。
- 接口：`browse/listLevels`、`browse/listLeaf`、`browse/rdbObjectDetail`、`query/createSession`、语言服务 WebSocket、`auth/listElementOfLeaf`、`auth/listUserElementOfLeaf`、权限定义、授权保存与权限申请接口。
- 契约：库节点的 `objAttr.leafTypes` 筛选对象分类；Tree 资源为模型、库、完整测点路径，Table 资源为模型、库、表名。视图不开放维护或团队授权入口。
- 实机执行时分别记录 V1（1.3.x Tree）、V2T（2.x Tree）、V2R（2.x Table），不得用另一版本的结果代替。

## Preconditions

- 用户已编译并启动加载最新前后端、IoTDB 插件及驱动的测试环境，再使用 [@Browser](plugin://browser@openai-bundled) 执行。开发阶段不启动平台，也不将构建或离线检查记作页面通过。
- 打包入口验收在 `cd package && ./all_build.sh web` 成功后，还需构建 `:cgdm-web:jar` 并重启服务，再重新加载页面；仅生成 Web 资源不代表运行中的服务已加载新资源。
- 内置浏览器已由用户登录。具备数据源所有者、可申请权限的子账号、可审批和授予权限的维护账号；数据库连接账号能读取全部隔离样本，以独立验证平台授权。
- IoTDB 插件和添加入口已开放，通过实例页选择 Apache IoTDB，分别配置对应版本的官方驱动和测试端点。
- 另有隔离 MySQL/PostgreSQL 和 Kafka 或 ES 实例，用于共享组件回归。记录已有草稿、权限、语言及视口。
- 不停止用户的远端容器；故障注入仅使用浏览器离线能力或本轮独立代理。

## Suites

### IOTDB-V1-BROWSE-01 — 单模型浏览与测点查询（P0，Smoke / Main Flow）

- 初始路由与状态：`/#/sql`，所有者账号，V1 实例未展开。
- 准备：D1、D3；记录 `SHOW DATABASES`、`SHOW DEVICES`、`SHOW TIMESERIES` 的只读对照。
- 操作：展开 V1 → TREE → 库，打开查询窗口；切换“设备”和“测点”，搜索普通及对齐设备，再双击两个设备的同名测点，主动执行生成的 SQL。
- 预期：V1 只有 TREE 分支；库下分类只有设备与测点，没有表或视图。设备及测点保留完整路径，双击只插入 SQL，执行后结果来自对应设备。库选择器和页签显示模型上下文。
- 恢复：撤销插入的 SQL，关闭测试页签。

### IOTDB-V1-AUTH-01 — 完整测点路径申请与授予（P0，Permission / State Consistency）

- 初始路由与状态：`/#/sql`，可申请权限的子账号；D5 目标尚未获平台查询权限。
- 准备：使用能读取 D1 全量样本的数据库连接账号，记录平台原授权。
- 操作：选中 temperature，在该对象行右键 → 申请权限；在申请页确认资源并选择查询权限，预览、提交。由审批账号处理，再在子账号授权页查看“测点权限”，单独授予或撤销该测点权限，保存并重新打开页面。
- 预期：申请页定位准确的实例、TREE、库和完整测点路径；未授权对象不自动勾选权限或提交，已授权对象回显现有权限。申请、预览、授权保存和重开保持同一资源。授权树在库下列出测点，不把设备作为授权对象。子账号工作台的“设备”只列出含已授权测点的设备，“测点”只列出已授权测点；包含引号内点号、转义反引号的测点仍归属准确的设备，不显示相邻设备。显式查询及 AS 别名可读，pressure、跨设备同名测点和条件中未授权测点被拒绝；通配符范围无法确定时拒绝。撤销后再次执行被拒绝。
- 恢复：关闭本轮申请、恢复原授权和账号；不变更数据库账号的原生权限。

### IOTDB-V2-TREE-01 — 2.x 树侧复测（P0，Main Flow / Permission）

- 初始路由与状态：`/#/sql`，V2 实例 TREE 分支。
- 准备：D1、D3、D5，记录 V2T 独立结果。
- 操作：在 V2T 重跑 IOTDB-V1-BROWSE-01 和 IOTDB-V1-AUTH-01。
- 预期：树侧对象、查询、申请和授权规则与 V1 一致；资源模型始终为 TREE，不出现 Table 样本。
- 恢复：恢复授权，关闭 V2T 测试页签。

### IOTDB-V2-MODEL-01 — 同实例双分支与页签恢复（P0，Main Flow / Lifecycle）

- 初始路由与状态：`/#/sql`，所有者账号，V2 实例已展开。
- 准备：D1、D2，模型两侧使用相同库名尾段。
- 操作：分别从 TREE 和 TABLE 打开查询页签，保留不同草稿，轮流执行只读查询；切换库、关闭重开页签、刷新页面，再断开和重连同一实例。分别执行适合当前模型的模式及当前库查询。
- 预期：一个实例下有 TREE、TABLE 两个分支；树侧只有设备/测点，表侧只有表/视图。页签并存、标题可区分模型；选择库不跨模型，草稿及返回结果不串页签。重开和重连后模式、Table 当前库正确，草稿不自动执行。Tree 不承诺原生当前库。
- 恢复：关闭测试页签，恢复原连接状态。

### IOTDB-V2-TABLE-01 — 表、视图与能力声明（P0，Main Flow / Permission）

- 初始路由与状态：`/#/sql`，V2 TABLE 库的查询页签。
- 准备：D2、D4；视图仅在版本支持时准备。
- 操作：双击表生成查询，展开列，切换视图分类并查询；检查表、视图右键菜单及编辑器工具栏，切换中英文。以子账号尝试经视图查询未获准 Tree 测点。
- 预期：表的快捷查询携带准确库名及引用；列属于当前对象。视图显示只读提示，没有修改、删除、结构编辑、数据编辑及权限申请入口；所有者可查询，团队访问继续被后端拒绝。编辑器支持执行、语言服务和带提示的取消，不暴露事务切换、执行计划或不支持的格式化；菜单文字无缺失 key。
- 恢复：撤销插入 SQL，关闭页签，由维护者清理本轮视图。

### IOTDB-V2-AUTH-01 — 跨库同名表和模型隔离（P0，Permission / State Consistency）

- 初始路由与状态：`/#/system/account/authdm/:uid?type=edit`，授权维护账号。
- 准备：D1、D2、D5，只授一个库的 motor_samples 查询权限。
- 操作：从表右键申请进入申请页，授予后检查授权树及保存结果；子账号分别查询同库表、跨库同名表、子查询中的 motor_private，再检查 TREE 中的测点授权。
- 预期：申请和授权完整保留 TABLE/库/表身份；仅目标表可读，跨库同名表及未授权子查询被拒绝；仅 DQL 授权不能执行 UPDATE 等 DML，维护者独立查询确认值未变化。TABLE 表权限不隐含 TREE 测点权限，反之亦然。只读视图未混入可授权表列表。选中 Table 叶子时使用既有“表”页签文案。
- 恢复：恢复原授权，关闭本轮申请和查询页签。

### IOTDB-BOUNDARY-01 — 完整名称与分页（P1，Boundaries / Extreme）

- 初始路由与状态：`/#/sql`，分别在 V1、V2T、V2R 加载 D3。
- 准备：D3；没有足够安全样本时记录未覆盖的分页边界。
- 操作：搜索长路径和带点号的引用名；用本轮 `_p0`、`_p1`、`_p100`、`_p101` 前缀依次筛选，切换对象分类、翻页、刷新；对特殊测点从右键进入申请，检查完整资源名；在两模型间切换。也可在 101 个测点列表中用 `sample_0`、`sample_100`、不存在的测点名，验证过滤后的 100/1/0 条边界。
- 预期：0/1/100/101 条对象计数和下一页状态正确；完整路径作为一个资源字段保存，不因点号或引用字符拆成目录。搜索、分页和右键目标一致，无相邻对象串用。
- 恢复：清空搜索，回第一页，恢复草稿。

### IOTDB-FAILURE-01 — 目标消失、断网和重试（P1，Failure And Recovery）

- 初始路由与状态：`/#/sql`，仅使用本轮可丢弃对象。
- 准备：D1/D2 临时对象；浏览器支持网络模拟时启用。
- 操作：打开菜单后由维护者删除目标，再点击申请；另在申请定位、列表刷新或查询中途模拟断网，恢复后重试。
- 预期：目标不存在时显示资源不可用，不自动选中同名的另一模型或相邻对象，不产生申请；失败不误报成功，恢复后可明确重试。写入结果未知时不自动重放。
- 恢复：恢复网络，维护者核对并清理本轮对象，关闭未提交申请。

### IOTDB-REPEAT-01 — 快速切换与多页签（P1，Repeat And Concurrency）

- 初始路由与状态：`/#/sql`，V2 两个查询页签，另开一个已有数据源页签。
- 准备：D1、D2，保留三份不同草稿。
- 操作：重复刷新对象列表，响应未返回时切换 Tree/Table；一侧查询中取消目标查询，另一侧执行短查询；返回工作台重复申请入口。
- 预期：旧列表和详情不覆盖另一模型，草稿及对象分类保持各自上下文；取消不关闭另一会话，不重放 SQL。一次申请只包含用户预览确认的资源。
- 恢复：停止测试查询，关闭新增页签及未提交申请。

### IOTDB-LAYOUT-01 — 桌面、窄屏与双语（P1，Extreme / Lifecycle）

- 初始路由与状态：`/#/sql`，再进入测点申请和子账号授权页。
- 准备：D3 长完整路径；记录原视口、缩放和语言。
- 操作：在 1440×900、1024×768、390×844 查看模型树、对象类型选择、搜索、右键菜单、资源面包屑及测点权限页签；切换中英文，再恢复桌面。
- 预期：沿用工作台对象抽屉；申请页在中等宽度将时间选项移到权限树下方，1024px 以下将资源树、资源与权限、时间选项纵向排列，内容区可滚动到每个区块。长名称能通过省略、提示或区域内滚动读取，页面不被撑出视口；申请、预览、保存和返回可达，页签和菜单不遮挡；恢复尺寸后无残留布局状态。分别检查新资源与已授权资源，布局变化不改变勾选或预览内容。
- 恢复：恢复原视口、缩放、语言和页面。

### IOTDB-REGRESSION-01 — 共享组件回归（P0，Smoke / Permission / State Consistency）

- 初始路由与状态：`/#/sql`，切换至既有 MySQL/PostgreSQL、Kafka 或 ES 数据源；授权和申请页使用 D5 子账号。
- 准备：D5，现有数据源不声明 `leafTypes`。
- 操作：按 `sql/table_context_menu.md`、`sql/workspace_connections.md`、`system/account_authorization.md` 复测普通对象浏览、页签恢复、表右键申请和授权保存；Kafka 按 `sql/kafka_object_browser.md` 复测 Topic 分类与授权，ES 复测索引查询。
- 预期：未声明能力的数据源分类保持原样；表沿用既有“表”页签文案，Kafka 显示“Topic 权限”，不出现测点页签；原生层级、菜单、查询和权限保存不变。右键申请定位其原有库表/Topic，不串到 IoTDB。
- 恢复：撤销本轮插入的 SQL 和权限变更，关闭新增页签及申请。

## Cleanup

恢复账号授权、语言、视口、网络和原草稿；关闭本轮申请及查询会话。撤销后重新进入子账号工作台，确认本轮资源不再可见，历史页签不能执行或通过重连恢复访问。仅删除本轮唯一标识的库、视图和账号；复用已有隔离库时只删本轮前缀对象，不删除父库。清理前核对实例及模型，清理后由维护者独立查询确认临时对象不存在、相邻基线样本未变。

## Skip Conditions

- 用户尚未编译启动、未登录、插件/驱动或账号缺失时，依赖的页面验证保持 NOT RUN/BLOCKED，不以构建或离线探针代替。
- 1.3.x 不支持 Table；2.x 目标版本不支持树转表视图时，仅跳过视图场景并记录版本，其他用例照常执行。
- 工具不支持视口或网络模拟时明确标记对应项 SKIP；缺少隔离大样本或共享数据源时记录具体回归缺口。
