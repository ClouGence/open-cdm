# TiDB SSH 握手失败诊断

## Purpose

区分 SSH 登录、本地端口监听、远端数据库连接和 MySQL 握手，防止把本地转发端口创建成功当作数据库已连通，或把首次连接失败误判为已有会话超时。

## Scope

- 新增 TiDB 实例的 SSH 通道配置、SQL 数据源树展开及 `/api/entry/browse/listLevels`。
- `SshTunnelManager`、`SessionManagerImpl`、`MySqlDsFactory` 和 TiDB 异常分类。
- 仅在本场景隔离实例中执行 `SELECT 1 AS ssh_repro`，不修改已有业务实例，不验证生产环境网络或真实 TiDB 集群特有行为。

## Preconditions

- 本地 CloudDM 已通过 IDEA 启动，健康检查成功，内嵌 Worker 插件加载完成。
- @Browser 已登录具有新增实例、管理 SSH 配置和浏览数据源权限的账号。
- 准备仅监听回环地址的隔离 SSH 服务，支持密码认证和 `direct-tcpip`；能够分别允许转发、返回连接失败、返回管理策略禁止。
- 如需正常握手对照，使用 localdb 文档指定的已有 MySQL Compose 环境。不要重启或停用共享数据库来制造失败。
- 确认故障目标端口没有监听者；SSH 服务应在目标连接失败时拒绝通道，而非模拟 MySQL 异常文本。

## Test Data

- 名称使用 `codex_issue404_<唯一后缀>`，SSH 配置使用同前缀。
- 数据库类型 TiDB，驱动 MySQL Connector/J 8.4.0；数据库地址为 SSH 服务可访问的本地测试地址。
- 正常对照使用可用 MySQL 端口和不存在的测试账号：预期收到握手后进入认证失败，不使用真实业务凭据。
- 故障实例指向已确认关闭的端口；第二场景使用禁止转发的独立 SSH 测试端口。
- 密码仅为隔离服务的临时测试凭据，不在截图或日志证据中记录。

## Suites

### TSSH-SMOKE-01 正常转发与认证错误对照

- 风险/目的：P0，证明测试 SSH 转发链路可以传输真实数据库协议。
- 初始路由与状态：实例新增页；测试数据库和允许转发的 SSH 服务均已就绪。
- 准备：按 Test Data 填写 TiDB、SSH、本地 MySQL 地址和不存在的数据库账号。
- 操作：通过 @Browser 进入实例 → 新增 → TiDB，填写常规参数，在 SSH/SSL 中选择测试通道，点击测试连接。
- 预期：数据库返回认证错误，不能出现 `readServerCapabilities` 阶段的零字节 EOF；SSH 服务记录目标通道请求。
- 恢复/清理：不保存正常对照实例，不更改已有账号。

### TSSH-FAILURE-01 目标拒绝连接时首次浏览失败

- 风险/目的：P0，复现本地转发成功、远端通道失败的握手 EOF。
- 初始路由与状态：实例新增页，无本场景已创建的查询会话。
- 准备：使用允许转发的 SSH 配置，但数据库端口指向已确认未监听的测试端口。
- 操作：保存隔离 TiDB 实例；进入数据查询，按唯一名称筛选，展开其数据源树；等待加载结束，记录异常图标和提示。只浏览元数据，不执行编辑器中已有 SQL。
- 预期：后端依次记录 SSH 配置 ID、真实 targetHost/targetPort、本地转发端口、创建会话失败和 `readServerCapabilities` → `beforeHandshake` 中的 0 字节 EOF。对象树不产生虚假的数据库节点，加载状态结束。
- 预期提示：TiDB 分类为 `ConnectionRefused`，后端保留 `DS_DISCONNECT_ERROR`，中文提示为“数据库{实例标识}连接失败，请检查连接配置或稍后重试”；英文为“Failed to connect to database {实例标识}. Please check the connection settings or try again later.”。均不得声称已有连接断开。前端可能只标记对象树异常，不显示原始文案。
- 恢复/清理：关闭提示（若出现），清除筛选，不改动原查询页签和正文。

### TSSH-FAILURE-02 SSH 策略禁止转发

- 风险/目的：P0，证明同一握手 EOF 无法唯一判定为目标数据库宕机。
- 初始路由与状态：实例新增页，使用独立的禁止转发测试 SSH 服务。
- 准备：SSH 登录允许成功，`direct-tcpip` 返回管理策略禁止；数据库目标可使用正常对照端口。
- 操作：按上一场景创建独立隔离实例，进入数据查询并展开其树。
- 预期：SSH 登录和本地转发端口创建成功，但通道被拒绝；驱动在认证前读取握手首包时出现相同 EOF。结合 SSH 侧通道拒绝原因判断故障，不能依赖 JDBC EOF 区分策略禁止和目标拒绝。
- 恢复/清理：同上一场景。

### TSSH-RECOVERY-01 测试连接成功后的查询树恢复

- 风险/目的：P0，防止 SSH 地址改写污染原始配置，导致同一请求的版本探测成功、随后的对象树连接却转发到已关闭的临时端口。
- 初始路由与状态：单机 FULL 模式，隔离 SSH 数据源已通过一次故障变为连接失败；使用独立 MySQL 测试环境，不停止共享服务。
- 准备：先让本场景独占的 SSH 服务拒绝转发，展开测试实例令连接失败；随后恢复转发。也可先将本场景临时实例指向关闭端口触发失败，再仅编辑该临时实例恢复到可用数据库地址。使用有效的隔离数据库测试账号。
- 操作：在编辑页点击测试连接，确认成功后保存；进入数据查询并展开同一实例。双击一个数据库节点并读取表列表，在新建测试页签执行 `SELECT 1 AS ssh_repro`；刷新页面后再次执行。不要执行其他页签已有的 SQL。
- 预期：测试连接、版本探测、对象树加载均成功，查询结果恰有一行，`ssh_repro` 为 `1`，刷新后仍可执行。版本探测和紧随其后的元数据会话可以使用不同的本地转发端口，但日志中的 targetHost/targetPort 必须始终等于真实数据库地址，不能变成上一次的本地转发端口。调用者原始配置的 host 不变，运行时副本保留具体数据源配置类型及其他连接参数。
- 恢复/清理：关闭本次新增的查询页签，恢复筛选；测试结束后停止本场景独占服务，保留其卷，不改动共享环境。

## Cleanup

- 保留用户原有实例、SSH 配置、查询正文和数据库数据。
- 仅按本次唯一前缀识别测试实例和 SSH 配置；需要保留给用户核对时明确列出，完成后通过正常实例管理和 SSH 配置管理流程清理。
- 停止本次启动的临时 SSH 服务，释放其监听端口；不停止共享数据库或无关服务。

## Skip Conditions

- 未登录时暂停页面操作，请用户在 @Browser 登录；不得读取认证数据绕过。
- 缺少隔离 SSH 服务时，页面场景标记 BLOCKED。可以用相同 JSch、Connector/J 和生产工厂/分类器进行底层补充验证，但不能将其称为真实页面复现。
- 没有 TiDB 测试库时，可用 MySQL 验证兼容协议握手故障，明确记录未覆盖 TiDB 集群特有行为。
- 工具无法读取接口响应时，以页面状态及相同请求时段的后端日志为证，不声称已捕获 HTTP 响应体。
