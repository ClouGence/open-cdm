# 实例列表测试连接

## Purpose

验证实例列表的连接测试按行独立维护 loading，避免一行测试导致全部测试按钮禁用、重复请求或其他行完成时清除仍在执行的 loading；验证 IPv6 地址在新增、保存、编辑回填及查询中保持一致。

## Scope

- `/#/datasource` 行内“测试”按钮与 `/api/entry/datasource/testConnect`。
- IPv6 套件另覆盖 `/#/datasource/add`、实例编辑及数据查询中的连接、元数据和只读 SQL。
- 普通按行测试不保存实例配置、不执行 SQL；IPv6 套件只创建和修改本次独立测试实例。

## Preconditions

- @Browser 登录本地环境，账号具有实例管理权限。
- 有两个已创建的隔离本地测试实例，至少一个能成功连接；失败路径可使用已有不可达的本地隔离实例，不改共享实例的连接信息。
- 执行 IPv6 套件时，测试 worker 必须能通过 IPv6 访问隔离数据库，准备可核对的地址与端口；同一目标还应有 IPv4 或域名连接作为对照。

## Test Data

- A、B：两个已有隔离实例，记录各自名称和网络地址定位，不依赖固定业务 ID。
- C：已有连接失败的本地隔离实例（可用时）；生命周期未达到 CREATED 的实例（可用时）。
- IPv6 实例：名称使用 `codex_ipv6_<数据库类型>_<唯一标识>`，分别准备 MySQL、PostgreSQL、Redis 中可用的隔离目标；只执行 `SELECT 1`，Redis 执行只读 `PING`，或读取一个已知测试键。
- IPv6 地址样本覆盖 `::1`、实际可达的压缩/完整地址和方括号地址；文档示例网段不能替代可达测试地址。失败目标使用本场景已确认未监听的隔离端口。
- 不操作生产连接；普通按行套件不创建、删除或保存配置。

## Suites

### DTC-MAIN-01 单行与多行并行

- 风险/目的：P0，防止全局禁用和不同请求相互清除状态。
- 初始状态：实例列表已加载，A、B 均可测试。
- 操作：点击 A 的“测试”，检查其他行；在 A 尚未完成时点击 B；A 执行期间再次点击 A；观察两个请求分别结束。
- 预期：仅正在执行的行显示 loading 并禁止重复点击；其他行仍为绿色可用，可独立发起测试。A/B 先后完成只恢复各自按钮，没有全表变灰或尚未完成的行提前结束 loading。成功显示既有成功提示，不保存配置。
- 清理：等待两个测试结束。

### DTC-FAILURE-01 失败与重试

- 风险/目的：P0，防止失败后 loading 残留。
- 初始状态：C 为已确认的本地隔离不可达实例。
- 操作：测试 C，等待失败提示后再次测试；同时观察可用实例的按钮。
- 预期：失败走既有错误提示，C 结束 loading 并可重试；其他实例按钮不受影响。连接失败不更改实例配置或生命周期。
- 清理：等待请求结束，不改变网络或配置。

### DTC-BOUNDARY-01 权限、生命周期和重复进入

- 风险/目的：P1，避免按行状态改造放宽原有权限或生命周期限制。
- 操作：确认非 CREATED 实例保持禁用；无管理权限账号不显示测试入口（已有对应数据/账号时）。测试结束后刷新、切换筛选再返回。
- 预期：原有权限与生命周期判断保留，刷新后无残留 loading；无新增相关 Console 错误。
- 清理：恢复原筛选状态。

### DTC-IPV6-MAIN-01 输入、保存、回填与查询

- 风险/目的：P0，防止 IPv6 最后一段被识别为端口、重复包裹方括号或提交时丢失端口。
- 初始路由与状态：`/#/datasource`，管理员已登录，IPv6 测试目标可达，没有本次测试实例。
- 测试数据与准备：为每个可用数据库类型选择独立名称、真实 IPv6 地址、默认端口及一个可用的自定义端口。地址和端口分开的表单使用裸 IPv6；合并地址或多节点表单使用 `[IPv6]:port`，不把裸 IPv6 的最后一段当作端口。
- @Browser 操作：
    1. 新增测试实例，填写裸 IPv6 和独立端口，执行“测试连接”，成功后保存。
    2. 在列表定位唯一名称，核对地址；打开编辑页，确认地址框和端口分别回填且没有截断或重复端口。
    3. 将同一个地址换成方括号写法，重复测试、保存和重新编辑；刷新页面后再次核对。
    4. 进入数据查询，按唯一名称定位并展开数据库和表；新建测试页签执行 `SELECT 1`。Redis 展开数据库并在新页签执行 `PING`，预期返回 `PONG`；也可读取预先约定的测试键，不执行其他页签遗留的命令。
    5. 对同一隔离目标使用 IPv4 或域名重复连接检查，确认原有连接仍可用。
- 预期结果：所有可达形式连接成功；IPv6 与端口在输入、保存及回填中保持同一语义，组合地址使用 `[IPv6]:port`；默认/自定义端口都正确。刷新后对象树和只读查询可继续使用，无相关 Console 错误或残留 loading。
- 清理：关闭本次查询页签，仅删除本次唯一名称的实例；保留原有连接和数据库数据。

### DTC-IPV6-FAILURE-01 失败提示与恢复

- 风险/目的：P0，防止地址格式错误或不可达后表单、连接测试及查询永久卡住。
- 初始路由与状态：IPv6 测试实例新增或编辑页，原始可达地址和端口已记录。
- 测试数据与准备：使用本场景独占的未监听端口；地址格式对照使用缺失结束方括号的输入，不修改共享实例。
- @Browser 操作：先输入不完整方括号地址测试，再输入正确 IPv6 与未监听端口测试；等待各次错误提示和 loading 结束，最后恢复真实地址端口并重新测试。保存后刷新，进入数据查询展开同一测试实例。
- 预期结果：错误走既有提示流程，不误报成功；按钮恢复可用。恢复真实地址后，连接、回填和元数据重新正常；失败请求不覆盖后续成功状态，不残留重复请求或临时 SSH 地址。
- 清理：恢复可达端口，按上一场景仅清理本次测试实例。

## Cleanup

等待所有连接测试完成，关闭提示；普通按行套件不更改实例。IPv6 套件仅清理本次唯一名称的实例和查询页签，保留权限、共享实例及数据库内容。

## Skip Conditions

- 接口返回过快导致无法从浏览器捕获并行中的状态时，明确区分最终状态检查和并行状态验证，以受控异步请求的组件方法验证补充乱序完成与重复请求检查。
- 无不可达的隔离本地实例、非 CREATED 实例或只读账号时，对应场景标记 SKIP，不修改共享环境来构造失败。
- 未授权测试外部实例时，不向外部数据库发起连接。
- worker 没有 IPv6 路由或没有隔离 IPv6 数据库时，IPv6 真实连接场景标记 BLOCKED；可用解析和地址生成回归补充，但不能替代连接、保存和查询验收。
- 某数据库驱动或测试实例不可用时，单独记录该类型未覆盖，不使用另一种数据库的成功结果代替。
