# Console 实例 ID 初始化

## Purpose

验证全新安装可以在向导中配置固定的 Console 实例 ID，避免数据库初始化完成后因缺少 ID 而无法启动。

## Scope

覆盖 Console 和 Alone 的 `/#/initialization`、服务配置、确认和初始化后启动，以及旧库升级时的实例 ID 配置。多节点容灾另行验证。

## Preconditions

- 使用待测版本的 Console 或 Alone 和独立的空 MySQL 库。安装目录与运行端口必须隔离。
- 使用能连接该测试库的专用账号和一次性的管理员登录信息。初始化状态无需 CloudDM 登录。
- 准备两种部署配置。一种未设置实例 ID，一种通过 `CONSOLE_INSTANCE_ID` 预设实例 ID。

## Test Data

- 有效 ID 使用 `console-init-<本次唯一后缀>`（非空字符串即可）。
- 无效输入为空串或纯空白字符。

## Suites

### INIT-ID-001 新装设置并保存实例 ID

- 优先级 P0。分别用 Console 和 Alone 从空库进入 `/#/initialization`。
- 在 @Browser 中测试数据库连接，填写登录配置，进入「服务配置」。未预设实例 ID 时应自动填入 `console-<UUID>`，且可以编辑。Alone 的这一页只显示实例 ID。
- 将鼠标移到「Console 实例 ID」标签旁的问号。提示应说明集群中的每个 Console 实例必须使用不同的 ID，其他字段应正常显示。
- 使用生成的 ID 进入确认页，核对 ID 一致后提交。等待页面退出初始化状态，核对 `/health/ready` 返回 200、配置文件中只有一条有效实例 ID 配置、元数据库登记的 ID 与提交值一致。
- 使用同一份配置重启服务，并核对登记的固定 ID。按 Cleanup 回收当次测试环境。

### INIT-ID-002 输入校验和确认页修改

- 优先级 P0。使用未配置 ID 的空库和独立安装目录，进入「服务配置」。
- 清空生成的 ID 或输入纯空白字符，再点击「下一步」。应显示必填提示且保留当前步骤。填入非空 ID 可进入确认页。
- 在确认页将 ID 清空并点击「确认」。应提示错误、停留在确认页，且空数据库没有被初始化。返回「服务配置」应保留表单中的修改。
- 刷新页面应从数据库配置重新开始。仅在计划验证实际持久化时才提交有效配置。

### INIT-ID-003 预设 ID 的安装

- 优先级 P1。使用通过环境变量预设 ID 的独立空库环境，进入「服务配置」，核对预填值与部署配置一致。
- 使用预填的 ID 完成初始化，确认登记的是该 ID。用另一个独立空库将 ID 改为其他有效值后提交，应返回部署配置冲突提示，库中没有初始化表。

### INIT-ID-004 升级前保存实例 ID

- 优先级 P0。分别准备 Alone 和 Console + Sidecar 的独立旧库，Flyway 应有待执行的多活迁移。分别使用未配置实例 ID 和已配置有效实例 ID 的部署。
- 在 @Browser 打开升级确认页。实例 ID 为空时应自动填入 `console-<UUID>` 且可编辑，已有 ID 时应显示原值。
- 清空 ID 或输入纯空白字符，点击确认。页面应留在确认步骤并显示必填提示，数据库的 Flyway 迁移历史和本地 ID 配置仍为提交前状态。
- 提交有效的实例 ID。核对相应配置文件已保存该 ID、Flyway 记录迁移成功、自动重启后 `/health/ready` 返回 200。Alone 应完成内置 Worker 初始化，独立 Sidecar 应重新连接并上报心跳。

## Cleanup

停掉测试服务，恢复或移走临时安装配置，按名称回收本场景创建的测试库和专用账号。测试记录中只保留可公开的实例 ID 和就绪结果。

## Skip Conditions

无法获得隔离空库时，可验证表单和格式提示。记录配置持久化及启动未覆盖。没有升级或生产实例的操作权限时无需启动该类实例。
