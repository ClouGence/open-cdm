# 本地新用户首次登录修改密码

## Purpose

验证管理员新建的本地账号首次登录时被强制停留在改密面板，改密成功后才会下发登录态；防止改密面板不出现、未改密即进入控制台、改密后仍被反复要求改密等回归。

## Scope

- 页面与路由：登录页 `/#/login`，改密面板复用登录页右侧面板。
- 入口：使用管理员新建的本地子账号在登录页输入账号与初始密码。
- 关联接口与状态：`POST /login` 返回 `needChangePwd=true` 且不下发 `dm_jwt_token`；`POST /loginPwdChange` 校验原密码、写入新密码并清除 `dm_auth_user.need_change_pwd`；改密成功后返回 `needChangePwd=false` 并下发登录态。
- 关联源码：`frontend/src/views/login/index.vue`、`frontend/src/services/http/api/user.js`、`LoginServiceImpl`、`RdpUserServiceImpl`、`DmHomeController`、`DmAuthUserMapper.xml`。
- 不覆盖：管理员重置密码接口、MFA 账号的二次验证链路、密码策略的后端实现细节、密码找回流程。

## Preconditions

- 本地 `DmAloneLauncher` 已启动，访问地址为 `http://127.0.0.1:8222/`。
- 使用 [@Browser](plugin://browser@openai-bundled) 内置浏览器，并已登录具备子账号管理权限的管理员。
- 数据库中 `dm_auth_user.need_change_pwd` 字段存在，MySQL 8.0+ 可正常访问。
- 允许在隔离测试库创建和删除测试账号，不操作共享环境数据。

## Test Data

| 编号  | 数据说明 | 构造方式 | 唯一标识 | 清理方式 |
|-----|------|------|------|------|
| D01 | 待首登改密的本地子账号 | 管理员在子账号页新建账号，记录账号与初始密码 | `codex_fp_<时间戳>` | 测试结束删除该子账号 |
| D02 | 已完成首登改密的本地子账号 | 用 D01 完成一次改密 | `codex_fp_<时间戳>` | 测试结束删除该子账号 |
| D03 | 被禁用的本地子账号 | 管理员新建后关闭启用状态 | `codex_fp_disabled_<时间戳>` | 测试结束删除该子账号 |

密码边界以当前后端策略为准：最小长度 8，强策略开启时需同时包含大写、小写和数字；不要在文档中记录真实密码。

## Suites

### FP-SMOKE-01 首登账号进入改密面板

- 风险/目的：P0，确认新账号首次登录被拦截在改密面板。
- 初始路由与状态：登录页，未登录。
- 测试数据：D01。
- 准备方法：管理员确认 D01 的 `need_change_pwd` 为 1。
- @Browser 操作：输入 D01 账号与初始密码，点击登录。
- 预期结果：页面标题变为「首次登录修改密码」，账号与密码输入框隐藏，出现新密码、确认密码两个输入框和「修改密码并登录」「重新登录」按钮；地址仍为 `/#/login`；刷新页面后需重新登录。
- 恢复/清理：点击「重新登录」回到普通登录表单。

### FP-MAIN-01 改密成功并进入控制台

- 风险/目的：P0，确认新密码生效且无需再次改密。
- 初始路由与状态：FP-SMOKE-01 的改密面板。
- 测试数据：D01、D02。
- 准备方法：准备一个满足策略的新密码。
- @Browser 操作：输入新密码与确认密码，点击「修改密码并登录」。
- 预期结果：请求成功并跳转到控制台首页；再次退出后用新密码登录不再出现改密面板；用旧密码登录返回密码错误。
- 恢复/清理：保留 D02 供重复验证，结束后删除。

### FP-BOUNDARY-01 表单与策略边界

- 风险/目的：P1，确认空值、两次不一致、密码过短和与原密码相同均被拦截。
- 初始路由与状态：改密面板。
- 测试数据：D01，空字符串、6/7/8 字符密码、与原密码相同的密码。
- 准备方法：每次验证后清空输入框，账号保持未改密状态。
- @Browser 操作：分别提交空表单、两次不一致、7 字符密码、与原密码相同的密码。
- 预期结果：空表单提示「密码不能为空」；两次不一致提示「两次输入的密码不一致」；7 字符提示最小长度 8 字符；与原密码相同提示不能与旧密码相同；以上失败均停留在改密面板且不下发登录态。
- 恢复/清理：清空输入框。

### FP-REPEAT-01 并发提交与重复提交

- 风险/目的：P1，确认同一账号并发改密只有一个请求生效。
- 初始路由与状态：改密面板，账号 `need_change_pwd=1`。
- 测试数据：D01，两个不同的合规新密码。
- 准备方法：使用两个标签页或两个并发请求同时提交不同的新密码。
- @Browser 操作：在两个标签页分别填写不同新密码并几乎同时提交。
- 预期结果：只有一个请求成功并进入控制台；另一个返回「该账号无需修改初始密码，请直接登录」类提示；数据库 `need_change_pwd` 为 0，且只有成功提交的新密码可以登录。
- 恢复/清理：关闭多余标签页，按需删除账号。

### FP-FAILURE-01 原密码错误与账号锁定

- 风险/目的：P1，确认改密接口沿用登录失败计数和锁定策略。
- 初始路由与状态：改密面板。
- 测试数据：D01，错误原密码。
- 准备方法：记录当前失败次数，连续提交错误原密码直到达到锁定阈值。
- @Browser 操作：重复提交错误原密码。
- 预期结果：每次失败提示密码错误；达到阈值后提示等待时间；锁定期内即使原密码正确也无法改密；锁定到期后可继续改密。
- 恢复/清理：等待锁定到期或由管理员重置测试账号状态。

### FP-STATE-01 禁用账号与已改密账号

- 风险/目的：P1，确认禁用账号不能改密，已改密账号不再显示面板。
- 初始路由与状态：登录页。
- 测试数据：D02、D03。
- 准备方法：D02 已完成改密；D03 已被禁用。
- @Browser 操作：分别用 D02、D03 登录。
- 预期结果：D02 直接进入控制台，不出现改密面板；D03 提示账号不可用，不出现改密面板。
- 恢复/清理：恢复 D03 状态并删除测试账号。

### FP-LIFECYCLE-01 重新登录与页面刷新

- 风险/目的：P2，确认面板状态可回退且不残留敏感输入。
- 初始路由与状态：改密面板。
- 测试数据：D01。
- 准备方法：在改密面板填写部分内容。
- @Browser 操作：点击「重新登录」；刷新页面再次登录。
- 预期结果：返回普通登录表单，账号、密码与新密码输入框均为空；刷新后未登录状态保持，需重新输入凭据。
- 恢复/清理：无。

### FP-PERMISSION-01 非首登账号不触发面板

- 风险/目的：P2，确认已有账号不受影响。
- 初始路由与状态：登录页。
- 测试数据：管理员账号或其他已存在且 `need_change_pwd=0` 的账号。
- 准备方法：无。
- @Browser 操作：正常登录。
- 预期结果：不出现改密面板，直接进入控制台。
- 恢复/清理：退出登录。

## Skip Conditions

- @Browser 不可用或未登录管理员账号时，依赖登录的场景标记为 SKIP，可用接口级验证覆盖「needChangePwd 返回、JWT 不下发、并发只成功一次」，并记录覆盖缺口。
- 需要真实 MFA 的环境不具备时，MFA 相关场景标记为 SKIP，不得以普通账号结果替代。
- 无法安全构造并发请求时，「并发提交」场景标记为 SKIP，并保留重复提交的单线程验证。
