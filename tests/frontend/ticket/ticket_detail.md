# 工单详情

## Purpose

验证工单列表检索入口、工单创建校验和工单详情完整生命周期，重点防止筛选项重复、资源标识不清、规则校验结果侵占编辑器、状态与处理人错位、步骤时间、分析结果和 SQL 预览错位，以及自动刷新、步骤切换和窄屏布局回归。

## Scope

- 页面：工单列表、工单创建、工单详情。
- 路由：`/#/ticket`、`/#/ticket_create`、`/#/ticket/:id`。
- 接口：工单列表、工单基础信息、数据库工单详情、SQL 分段预览、审批、执行确认、关闭工单以及自动执行任务相关接口。
- 状态：初始化、分析、等待审批、等待确认、待执行、执行中、完成、拒绝、失败、关闭、取消。
- 不覆盖：审批规则配置、SQL 解析器正确性、执行引擎性能和第三方审批系统内部页面。

## Preconditions

- 本地 `DmAloneLauncher` 已启动，访问地址为 `http://127.0.0.1:8222/`。
- Chrome 已登录具备工单查看权限的账号；审批、确认、执行等场景使用具备对应按钮权限的账号。
- 准备一个包含完整生命周期数据的数据库变更工单，以及一个处于非终态、可安全推进的测试工单。
- 所有写入和执行场景仅允许使用本地测试数据库，SQL 不得修改生产数据。

## Test Data

- 完整工单：包含创建、分析、审批、确认、执行步骤；分析至少包含行为分析和安全规则结果。
- 自动执行工单：分别准备一条 `DM_QUERY` 和一条 `DM_CHANGE` 工单，两者均通过自动执行生成任务和调度日志。
- 进行中工单：使用 `SELECT 1;` 等无副作用 SQL，工单名称或描述带唯一标识 `codex_ticket_<时间戳>`。
- 创建工单数据源：至少准备两个环境，每个环境至少包含一个当前账号有权申请的数据源实例，并记录实例名称与所属环境。
- 边界工单：描述为空、超长描述、无附件名的行内 SQL、单行 SQL、多行 SQL、含中英文与特殊字符的 SQL。
- 异常数据通过浏览器开发者工具的网络条件或可控测试服务返回构造，不直接修改生产或共享环境数据。
- 清理时关闭未完成工单，并删除测试发布流或测试数据源中仅为本流程创建的数据。

## Suites

### TD-SMOKE-00 工单列表检索

- 风险/目的：P1，确认列表检索项覆盖工单号、标题、描述和行内内容，附件内容不会进入高成本模糊搜索，工单状态不会以内部流程枚举重复暴露给用户。
- 初始路由与状态：打开工单列表并切换到“全部”。
- 测试数据：至少包含一条标题、描述和行内 SQL 各自带唯一关键词的行内工单，一条仅在附件 SQL 正文中带唯一关键词的附件工单，以及实例别名与实例 ID 不同的 SQL 或变更工单。
- 准备方法：记录目标工单的完整工单号，以及标题、描述、行内 SQL 和附件 SQL 正文中的唯一关键词。
- 操作步骤：查看检索栏默认状态；直接输入列表中的完整工单号查询；依次选择“标题”“描述”“内容(INLINE)”并输入对应关键词查询；用仅存在于附件 SQL
  正文中的关键词执行“内容(INLINE)”查询；依次切换“待办 / 我发起的 / 全部”。
-
预期结果：检索栏保留时间范围、查询类型、查询内容和查询按钮；查询类型默认选中“工单号”，输入框默认提示“请输入工单号查询”，不显示“等待分析 /
分析中 / 等待审批 / 执行准备”等内部状态；查询选项只包含“标题”“工单号”“描述”“内容(INLINE)”，不提供跨字段“全部”查询；选择“工单号”时请求只提交
`ticketBizId`，选择“标题”时只提交 `ticketTitleName`，选择“描述”时只提交 `ticketDescription`，选择“内容(INLINE)”时只提交
`ticketContent`，且不再提交 `ticketStatus` 参数；前三类模糊条件和工单号均可准确定位目标工单，内容查询只命中行内 SQL，附件 SQL 正文不参与搜索；列表默认每页展示 20
条，分页器显示 `20 条/页`；切换列表分类后按对应分类刷新数据；列表包含“描述”列，长描述单行省略为 `...`，悬停后出现可进入且不会在鼠标移入时消失的完整内容浮层，浮层内文本可选择并可通过“复制”按钮复制；SQL 与变更工单的资源列只展示数据库产品图标和实例别名，别名为空时回退实例 ID，数据源记录不存在时从工单资源路径回退实例 ID 并使用通用数据库图标，长别名单行省略且可悬停查看完整值；权限工单继续展示权限工单图标和原有资源信息；表格在可用宽度不足时允许其他字段横向滚动，“操作”列始终固定在右侧且不随主体列移出视口；列表表格只由外层表格容器绘制一圈
`1px` 边框，表头顶部不再叠加原生表格的第二条顶边，工单列表及其他复用 `DmTable` 的列表页保持相同发丝线粗细。
- 恢复/清理：清空时间和查询内容条件，关闭本流程创建的测试工单。

- 恢复/清理：未提交时直接离开；已提交时关闭本流程创建的测试工单。

### TD-MAIN-00 创建工单规则校验结果弹窗

- 风险/目的：P0，确认安全规则命中结果通过弹窗集中展示，不再挤占 SQL 编辑器，并保持阻断与建议的语义和提交路径一致。

- 初始路由与状态：完整工单详情已加载。
- 测试数据：创建、分析、审批、确认、执行均有数据的完整工单。
- 准备方法：打开完整工单。
-
操作步骤：先分别进入一条分析中的工单、一条已完成工单和一条填写了多行拒绝理由的已拒绝工单，记录首次选中的步骤；不手动切换分析中工单的步骤，在另一标签页将其推进到审批并等待至少两个自动刷新周期；再依次点击创建、分析、审批、确认、执行步骤，并在手动切换后等待至少两个自动刷新周期、点击刷新。
-

`-`，不补充虚构人员；已拒绝工单选中“审批”步骤时，在步骤摘要下方以和分析结果摘要一致的静态横向信息行显示接口返回的完整“拒绝理由”，该信息行不提供展开箭头或下拉交互，多行文本保留换行且长内容自然换行，切换到其他步骤后不显示该理由。
- 恢复/清理：重新选择分析步骤。

### TD-MAIN-02 分析结果与详情

- 风险/目的：P0，确认分析结果摘要和详细数据一致。
- 初始路由与状态：选择分析步骤。
- 测试数据：包含行为分析和安全规则结果的工单；另准备 PostgreSQL、ClickHouse 和 Doris 2.1.0 工单，各包含可解析到目标表的 `INSERT`、`UPDATE`、`DELETE`。
- 准备方法：等待分析完成或使用已有完整工单。
- 操作步骤：先进入一条正在执行 DML 影响行数分析的工单，观察“准备”和“获取计划”两个阶段；再进入已完成工单，核对每个分析项的名称、状态、结果和耗时；分别打开 PostgreSQL、ClickHouse 和 Doris 2.1.0 工单的数据分析明细，核对 `INSERT`、`UPDATE`、`DELETE` 行；在 Doris 2.1.0 控制台对同一条 `DELETE` 点击“执行计划”；点击行为分析行最前面的 `>`，再次点击同一箭头收起；再点击安全规则行最前面的 `>`。
- 预期结果：行为分析不区分准备阶段，分析时直接显示当前文件读取进度；DML 影响行数的“准备”阶段由词法器完整扫描文件并统计 DML，但仅将配置数量以内、尺寸合规且受支持的语句送入语法解析和 Explain 改写，超过数量限制的语句不再进入语法解析；进入有限语句的查询计划执行后切换为“获取计划”及已处理数量，过程状态都能随自动刷新更新且不会把准备阶段的 100% 误解为整个分析已完成；任一分析项处于分析中且尚无明细时，摘要行继续显示实时进度，展开区只显示“分析中...”，不重复摘要进度；分析完成后，行为分析摘要切换为 SQL、对象和动作汇总，DML 影响行数摘要切换为 SQL 数量和预计影响行数，并附带跳过和失败统计；步骤摘要下方直接展示分析项卡片，不额外显示“分析结果”层级标题；行为分析摘要行直接展示 SQL
  数、对象数和动作数的完整统计，展开区不重复显示同一统计；DML 影响行数分析没有 SQL 时摘要只显示“共 0 条 SQL”，不显示“影响行数暂无法估算”；PostgreSQL 和 ClickHouse 的 `UPDATE`、`DELETE` 以及 Doris 2.1.5 之前的 `DELETE`，即使数据库不支持影响行数 Explain，也必须保留在明细表中，状态显示“数据库不支持”，影响行数显示 `--`，不得静默丢弃或发起数据库 Explain；Doris 2.1.0 控制台对 `DELETE` 点击“执行计划”时直接提示不支持，不向数据库发送会触发空指针的 `EXPLAIN DELETE`；可由行为分析直接确定行数的 `INSERT` 仍正常显示估算结果；行为分析展开后表格直接衔接摘要行，不再套浅灰内容容器，整个分析项只保留一圈
  1px
  外框，摘要行和表格组件不重复绘制外框，表格内部行列分隔保留；页面没有全局“展开详情/收起详情”按钮；箭头位于每个分析项最前面，只控制所属分析项；展开与收起时箭头旋转、容器高度、内容透明度和轻微位移连续过渡，没有瞬间跳变；明细在该分析项容器内部、摘要行正下方展示；切换到另一项后原容器收起、目标容器展开，展开和收起不导致其他摘要行错位；系统开启“减少动态效果”时不播放明显过渡。
- 恢复/清理：收起分析详情。

### TD-MAIN-03 SQL 内容操作

- 风险/目的：P0，确认 SQL 内容可查看、复制和下载。
- 初始路由与状态：数据库工单详情已加载。
- 测试数据：包含多行 SQL 的完整工单。
- 准备方法：打开数据库工单。

## Skip Conditions

- 没有审批或执行权限账号时，可执行只读布局、步骤切换和 SQL 内容场景；权限按钮与真实审批/执行操作标记为 SKIP，并记录未覆盖权限路径。
- 没有可安全执行的隔离数据库时，审批、确认和执行写入场景必须 SKIP；可使用已有终态工单验证只读展示，但不能替代状态推进验证。
- 无法稳定构造 400/403/500 或超时时，异常恢复场景可用断网验证基础恢复，其他状态码路径标记覆盖缺口。
- 浏览器不支持目标断点模拟时，使用可调整窗口尺寸验证；仍无法覆盖极窄视口时明确标记 SKIP。
