# 工单详情

## Purpose

验证工单列表检索入口和工单详情完整生命周期，重点防止筛选项重复、状态与处理人错位、步骤时间、分析结果和 SQL
预览错位，以及自动刷新、步骤切换和窄屏布局回归。

## Scope

- 页面：工单列表、工单创建、工单详情。
- 路由：`/#/ticket`、`/#/ticket_create`、`/#/ticket/:id`。
- 接口：工单列表、工单基础信息、数据库工单详情、SQL 分段预览、审批、执行确认、关闭工单以及自动执行任务相关接口。
- 状态：初始化、分析、等待审批、等待确认、待执行、执行中、完成、拒绝、失败、关闭、取消。
- 不覆盖：审批规则配置、SQL 解析器正确性、执行引擎性能和第三方审批系统内部页面。

## Preconditions

- 本地 `DmAloneLauncher` 已启动，访问地址为 `http://127.0.0.1:8222/`。
- Chrome 已登录具备工单查看权限的账号；审批、确认、执行等场景使用具备对应按钮权限的账号。
- 准备一个包含完整生命周期数据的数据库变更工单，以及一个处于非终态、可安全推进的测试工单。
- 所有写入和执行场景仅允许使用本地测试数据库，SQL 不得修改生产数据。

## Test Data

- 完整工单：包含创建、分析、审批、确认、执行步骤；分析至少包含行为分析和安全规则结果。
- 自动执行工单：分别准备一条 `DM_QUERY` 和一条 `DM_CHANGE` 工单，两者均通过自动执行生成任务和调度日志。
- 进行中工单：使用 `SELECT 1;` 等无副作用 SQL，工单名称或描述带唯一标识 `codex_ticket_<时间戳>`。
- 边界工单：描述为空、超长描述、无附件名的行内 SQL、单行 SQL、多行 SQL、含中英文与特殊字符的 SQL。
- 异常数据通过浏览器开发者工具的网络条件或可控测试服务返回构造，不直接修改生产或共享环境数据。
- 清理时关闭未完成工单，并删除测试发布流或测试数据源中仅为本流程创建的数据。

## Suites

### TD-SMOKE-00 工单列表检索

- 风险/目的：P1，确认列表检索项保持精简，工单状态不会以内部流程枚举重复暴露给用户。
- 初始路由与状态：打开工单列表并切换到“全部”。
- 测试数据：至少包含一条可通过标题关键词定位的工单。
- 准备方法：记录目标工单的唯一标题片段。
- 操作步骤：查看检索栏默认状态；直接输入列表中的完整工单号查询；再选择“标题”并输入标题关键词查询；依次切换“待办 / 我发起的 /
  全部”。
-
预期结果：检索栏保留时间范围、查询类型、查询内容和查询按钮；查询类型默认选中“工单号”，输入框默认提示“请输入工单号查询”，选项仅包含“标题”和“工单号”，不显示“等待分析 /
分析中 / 等待审批 / 执行准备”等内部状态；选择“工单号”时请求只提交 `ticketBizId`，选择“标题”时请求只提交 `ticketTitleName`
，两类条件均可准确定位目标工单且不再提交 `ticketStatus` 参数；列表默认每页展示 20 条，分页器显示 `20 条/页`；切换列表分类后按对应分类刷新数据；列表表格只由外层表格容器绘制一圈
`1px` 边框，表头顶部不再叠加原生表格的第二条顶边，工单列表及其他复用 `DmTable` 的列表页保持相同发丝线粗细。
- 恢复/清理：清空时间和标题条件。

### TD-SMOKE-02 创建工单 SQL 输入

- 风险/目的：P0，确认创建工单只要求业务 SQL，不再暴露或提交已移除的回滚 SQL。
- 初始路由与状态：从工单入口进入 `/#/ticket_create`。
- 测试数据：选择隔离测试数据库，SQL 使用 `SELECT 1;`，标题使用唯一标识 `codex_ticket_<时间戳>`。
- 准备方法：确认账号具备创建数据库工单权限，并准备可安全校验的测试数据源。
- 操作步骤：检查 SQL 编辑区和右侧工单表单；填写标题、描述和业务 SQL，点击“校验并提交”；只验证到校验结果时可停止，不强制提交工单。
- 预期结果：页面只显示业务 SQL 编辑器，不显示“填写回滚 SQL”选项和“回滚 SQL”编辑器；提交请求不包含 `rollBackSql` 字段；移除后主编辑区连续占用可用高度，没有多余空白、分隔条或隐藏编辑器残留；校验流程与原有业务 SQL 行为一致。
- 恢复/清理：未提交时直接离开；已提交时关闭本流程创建的测试工单。

### TD-MAIN-01 进度与步骤详情联动

- 风险/目的：P0，确认横向进度与服务端步骤状态一致。
- 初始路由与状态：完整工单详情已加载。
- 测试数据：创建、分析、审批、确认、执行均有数据的完整工单。
- 准备方法：打开完整工单。
-
操作步骤：先分别进入一条分析中的工单、一条已完成工单和一条填写了多行拒绝理由的已拒绝工单，记录首次选中的步骤；不手动切换分析中工单的步骤，在另一标签页将其推进到审批并等待至少两个自动刷新周期；再依次点击创建、分析、审批、确认、执行步骤，并在手动切换后等待至少两个自动刷新周期、点击刷新。
-
预期结果：进行中工单首次进入时默认选中服务端当前进行中的步骤，已完成工单默认选中最后一个“执行”步骤；用户尚未手动选择步骤时，服务端从分析推进到审批后，进度和步骤详情自动跟随到审批，无需点击刷新；用户手动选择历史步骤后，自动刷新和手动刷新均保留仍然有效的用户选择，不抢回当前步骤；“进度”和“步骤详情”位于同一个流程容器，通过留白分区且中间没有横向分隔线；进度按业务顺序横向展示，每个节点展示时间和真实处理人；节点间连线不穿过标题、时间或处理人；完成、当前、未开始、失败使用不同语义状态，创建、分析和其他已完成步骤在步骤详情中均显示“已完成”；点击或悬停步骤不出现大块背景，选中标题和当前节点状态清晰；步骤详情同步更新名称、处理人、开始时间和状态，桌面四列与平板两列使用细竖线分隔相邻字段，手机单列时不显示孤立竖线；未开始步骤的处理人显示
`-`，不补充虚构人员；已拒绝工单选中“审批”步骤时，在步骤摘要下方以和分析结果摘要一致的静态横向信息行显示接口返回的完整“拒绝理由”，该信息行不提供展开箭头或下拉交互，多行文本保留换行且长内容自然换行，切换到其他步骤后不显示该理由。
- 恢复/清理：重新选择分析步骤。

### TD-MAIN-04 工单执行弹窗

- 风险/目的：P0，确认执行配置可读、可操作，避免表单项过度挤压或不同执行方式下布局跳动。
- 初始路由与状态：具备执行权限、处于等待确认或待执行状态的数据库工单详情。
- 测试数据：使用 `SELECT 1;` 的无副作用测试工单。
- 准备方法：打开工单详情并确认右上角“执行”按钮可见。
- 操作步骤：点击“执行”；依次切换“已手动完成”“立即执行”“定时执行”；在定时执行状态选择日期时间；切换事务模式；输入多行备注；最后取消弹窗，不提交执行。
-
预期结果：弹窗标题为“工单执行”；执行策略、事务模式、备注按上标签下控件分组展示，各组之间有清晰纵向留白；执行策略可换行但不重叠；事务开关与说明位于同一柔和背景区域并保持间距，关闭状态显示“关闭”；备注框默认展示三行；切换定时执行后“执行时间”标签单独占一行，日期控件在下一行展示且不挤压其他选项；桌面与窄屏下均无横向溢出，主操作和取消按钮可见；取消后不产生执行请求。
- 恢复/清理：关闭弹窗，确认工单状态未变化。

### TD-MAIN-05 自动执行任务与日志

- 风险/目的：P0，防止任务执行区脱离执行步骤，或因工单类型限制导致发布流变更工单缺少执行任务与日志。
- 初始路由与状态：分别打开一条已自动执行的 `DM_QUERY` 工单和一条已自动执行的 `DM_CHANGE` 工单。
- 测试数据：自动执行成功工单，以及一条因数据库返回明确错误而执行失败的工单。
- 准备方法：从工单列表按类型定位已完成且产生自动执行任务的两条工单。
-
操作步骤：先选择非执行步骤，确认步骤详情内容；再点击“执行”步骤，核对任务执行状态、计划执行时间和任务表格；点击“调度日志”，关闭弹窗后再点击任一任务行的“日志”；对失败工单打开失败任务的“日志”并核对数据库错误；收起和展开任务表格；刷新页面后重新选择执行步骤；对另一种工单类型重复上述操作。
-
预期结果：任务执行区只在选中“执行”步骤且工单存在自动执行任务时展示，位于步骤摘要下方的同一“步骤详情”容器内；其摘要行、图标底板、状态标签、左侧展开箭头及渐进动效与“行为分析”保持一致，点击左侧箭头可在同一个容器内展开或收起任务表格；展开后表头直接衔接摘要行，表格贴合摘要区域，不再使用带背景和四周留白的内容容器套住表格，整个任务执行区只保留一圈
1px 外框，摘要行和表格组件不重复绘制外框，表格内部行列分隔保留；任务状态与计划执行信息组成清晰摘要，调度日志、刷新和任务控制操作位于摘要行右侧，分页与数据区右侧对齐；
`DM_QUERY` 与 `DM_CHANGE`
展示相同的任务状态、计划执行时间、调度日志、任务日志、刷新和展开/收起操作；任务及步骤中的完成、执行中、失败等状态标签统一使用胶囊形，不因状态类型出现长方形圆角；点击任务“查看”后，SQL 弹窗与页面内 SQL、“查看内容”弹窗使用相同的 Menlo/Monaco 等宽字体、14px 字号、400 字重、21px 行高和 0 字距；调度日志与任务日志弹窗展示对应日志数据；失败任务的日志至少包含 Sidecar 上报的原始数据库错误，不显示空表；切换到创建、分析、审批或确认步骤后任务执行区不可见；刷新后重新选择执行步骤仍能加载服务端任务终态；窄屏下摘要和操作区可换行，任务表格可横向滚动且不撑破页面。
- 恢复/清理：关闭日志弹窗并重新选择分析步骤，无数据写入。

  进度”一致的白色卡片、细边框、圆角、阴影、内边距和左侧绿色标题标识；有明细时在外层卡片内使用扁平的权限记录列表，以留白和横向发丝线分组，不再嵌套一张带完整外框和纵向网格线的表格；数据源实例前展示与明细
  `dataSourceType` 对应的数据库产品图标，实例、资源路径和生效时间形成稳定的元数据区，权限标签使用低对比度标签并可自然换行；历史权限
  key 无法在当前权限字典中查到时，页面仍能正常加载并原样显示该
  key，不弹出接口错误；无明细时展示卡片内部带权限图标的轻量“暂无权限明细”空状态；窄屏时记录元数据折叠为单列，卡片不脱离页面边距且不与其他区域重叠。
- 恢复/清理：无。

### TD-BOUNDARY-01 空值与长内容

- 风险/目的：P1，防止空字段和长文本破坏布局。
- 初始路由与状态：分别打开描述为空和描述超长的工单。
- 测试数据：边界工单。
- 准备方法：通过正常创建入口提交对应描述和 SQL。
- 操作步骤：检查概览字段、步骤名称、处理人、SQL 文件名和错误提示。
- 预期结果：空字段显示 `-` 或既有空状态；标题与描述允许自然换行，数据库路径等紧凑字段单行省略且可查看完整值；Unicode
  和特殊字符不乱码；操作按钮不被挤出容器。
- 恢复/清理：关闭测试工单。

### TD-EXTREME-01 视口与缩放

- 风险/目的：P1，验证常见桌面宽度和极窄视口。
- 初始路由与状态：完整工单详情。
- 测试数据：完整工单。
- 准备方法：打开页面并保持分析步骤选中。
- 操作步骤：分别在 1512×982、1440×900、1024×768、390×844 检查页面；再使用 1209×786、1152×720、1008×655、960×600
  的有效视口模拟标准 MacBook 在 125% 和 150% 浏览器缩放下的可用空间，并在 1365px、1279px、1079px 断点两侧各复核一次。
- 预期结果：应用侧栏在中等有效视口逐级收窄，但菜单文字、分组和当前选中态仍可用；工单标题与操作区不会相互覆盖；概览网格按断点从四列降为两列和单列，带目标数据库的修饰网格同样生效，创建时间和完成时间保持完整日期格式，不按单个字符断行；可用宽度缩小时进度仍保持横向步骤流，并同步缩小节点、文字区、间距和连接线，标准 MacBook 及浏览器高缩放场景下所有步骤完整可见；只有极窄视口确实无法容纳完整字段时才出现明确可见的横向滚动条，不切换为纵向步骤流；步骤摘要和分析结果正常换行；SQL 内容区在高视口下填满剩余高度、矮视口下保持至少
  `240px` 的编辑器可视高度；页面仅主内容区纵向滚动并保留外层滚动条，SQL 编辑器不显示纵向滚动条，页面无并排双纵向滚动条、横向溢出和按钮遮挡。
- 恢复/清理：恢复 100% 缩放和原窗口尺寸。

### TD-REPEAT-01 快速切换与旧响应

- 风险/目的：P1，防止快速操作和轮询导致旧状态覆盖新状态。
- 初始路由与状态：非终态工单详情。
- 测试数据：进行中工单。
- 准备方法：触发安全的测试工单并停留详情页。
- 操作步骤：快速切换多个步骤，连续点击手动刷新一次，等待至少两个自动刷新周期；另开标签页查看同一工单并推进状态。
- 预期结果：按钮 loading 期间不会重复提交；当前选择在数据刷新后仍有效；服务端状态推进后两个页面最终一致；旧请求不会把终态覆盖为旧状态。
- 恢复/清理：关闭重复标签页。

### TD-FAILURE-01 请求失败与恢复

- 风险/目的：P1，确认接口异常不会破坏已展示页面。
- 初始路由与状态：非终态工单详情已加载。
- 测试数据：进行中工单。
- 准备方法：临时切换 Chrome 为离线，或在隔离测试环境令详情/SQL 预览接口返回 500。
- 操作步骤：触发刷新或 SQL 预览请求，观察错误后恢复网络并再次点击刷新。
- 预期结果：失败时有项目统一错误提示；已有页面结构不崩溃；恢复网络后可重新获取最新状态和 SQL；自动刷新不会产生叠加请求。
- 恢复/清理：恢复网络条件。

### TD-LIFECYCLE-01 页面生命周期

- 风险/目的：P1，确认刷新、离开与重新进入行为稳定。
- 初始路由与状态：非终态工单详情。
- 测试数据：进行中工单。
- 准备方法：打开工单详情。
- 操作步骤：刷新页面；切换到其他标签页超过一个轮询周期再返回；通过侧边栏离开后使用浏览器后退重新进入。
- 预期结果：首次进入或整页刷新时，进行中工单选中当前步骤，已完成工单选中最后一步；页面内刷新保留仍然有效的手动选择；页面不可见时不进行无意义刷新；返回后恢复更新；离开页面后计时器和
  SQL 请求不再继续；重新进入不出现重复轮询。
- 恢复/清理：返回工单列表。

### TD-PERMISSION-01 权限与登录失效

- 风险/目的：P0，防止越权操作入口显示。
- 初始路由与状态：分别使用只读、审批、执行权限账号访问同一测试工单。
- 测试数据：等待审批或等待执行的测试工单。
- 准备方法：由管理员为测试账号分配最小权限，测试结束后恢复。
- 操作步骤：检查审批、执行、关闭和第三方审批按钮；在会话失效后刷新页面。
- 预期结果：只读账号仅可查看；有权限账号只显示对应操作；按钮可见性与后端权限一致；会话失效走项目统一登录处理，不暴露工单内容。
- 恢复/清理：恢复测试账号权限并重新登录。

### TD-STATE-01 状态一致性

- 风险/目的：P0，确认概览、进度、步骤详情和任务执行状态使用同一服务端事实。
- 初始路由与状态：进行中工单详情。
- 测试数据：可推进至完成或失败的测试工单。
- 准备方法：按正常流程推进工单。
- 操作步骤：在分析、审批、确认、执行各阶段观察概览状态和进度；完成后等待自动刷新并手动刷新复核。
- 预期结果：同一时刻各区域状态一致；未开始步骤保持未开始且处理人显示 `-`；完成时间只在终态出现；进入终态后自动轮询停止；手动刷新结果与服务端一致。
- 恢复/清理：关闭或归档测试工单关联的数据。

## Cleanup

- 关闭或完成本流程创建的测试工单。
- 删除仅为测试创建的发布流、测试 SQL 文件和下载文件。
- 恢复测试账号权限、Chrome 网络条件、浏览器缩放和窗口尺寸。
- 不直接删除共享环境工单记录；确需清理数据库时必须使用隔离环境并保留可恢复备份。

## Skip Conditions

- 没有审批或执行权限账号时，可执行只读布局、步骤切换和 SQL 内容场景；权限按钮与真实审批/执行操作标记为 SKIP，并记录未覆盖权限路径。
- 没有可安全执行的隔离数据库时，审批、确认和执行写入场景必须 SKIP；可使用已有终态工单验证只读展示，但不能替代状态推进验证。
- 无法稳定构造 400/403/500 或超时时，异常恢复场景可用断网验证基础恢复，其他状态码路径标记覆盖缺口。
- 浏览器不支持目标断点模拟时，使用可调整窗口尺寸验证；仍无法覆盖极窄视口时明确标记 SKIP。
