## 第 1 步实库样本

样本标识为 `cdm_iot_231ab691`。两个实例分别创建维护账号 `cdm_iot_231ab691_maint` 和低权限账号 `cdm_iot_231ab691_read`。数据库和账号保留供后续步骤复用，密码单独保存。

| 编号 | 样本 | JDBC 直连证据 |
| --- | --- | --- |
| V1 | `root.cdm_iot_231ab691` | 维护账号列出两个设备、四个测点，读到对齐设备的两个温度值，并在测试测点完成建、写、读、清理。低权限账号仅列出和读到授权测点，查同设备的 `pressure` 返回空结果，写入被拒绝。 |
| V2T | `root.cdm_iot_231ab691` | 维护账号回读树库、两个设备、普通与对齐标志及四个测点，完成测试测点的建、写、读、清理。低权限账号仅列出和读到授权测点，查同设备的 `pressure` 返回空结果，写入被拒绝。 |
| V2R | `cdm_iot_231ab691` | 回读会话模式为 `TABLE`。维护账号列出两个表，`DESCRIBE` 返回四种列角色，采样表读到两台设备，并完成测试表的建、写、读、清理。低权限账号仅列出并能读取 `motor_samples`，查询 `motor_private` 和尝试写入均被明确拒绝。 |

## 第 4 步会话与结果验证

在开发机的独立 JVM 中加载实际插件包，通过 Sidecar 资源管理器和会话 SPI 连接远端。TCP 代理记录 Thrift 取数、关闭操作和 SQL 请求，并可在收到远端响应后丢弃或暂缓回包。临时测点和表在本轮验证后删除。

| 基线 | 结果与证据 |
| --- | --- |
| V1 | PASS。Tree 读取 4200 行，覆盖时间、数值、文本和空值，代理观察到 119 次取数 RPC 及结果集和语句关闭。取数中断返回部分数据和终止错误。配置 750 毫秒网络超时的连接在读超时后释放。配置 1 秒查询截止时间和 5 秒网络超时，约 1 秒返回查询超时。 |
| V2T | PASS。Tree 同样完成多批读取、取数中断、网络超时和查询截止时间验证。2.0.11 上取消 Tree 的阻塞请求时，Table 查询正常完成。重开 Tree 后能继续执行树模型查询。 |
| V2R | PASS。Table 能独立查询样本表。取消 Table 的阻塞请求时，Tree 查询正常完成。Sidecar 在连接中断后保留 Table 模式与通过 `USE` 选择的库，新会话从这两个字段恢复后可执行非限定表名查询。 |
| 写入结果与资源 | PASS。两个版本确认成功写入的 JDBC 更新计数均为 `-1`，手动事务被拒绝。V1、V2T 和 V2R 的写入回包被丢弃时，Sidecar 会话队列产出“语句执行结果未知”，代理只观察到一次写入请求，独立连接确认该次写入已生效。断开的逻辑会话保留错误供读取，释放的物理连接配额可用于新会话。 |
| 共用 SQL 审计 | 待讨论。延迟后丢弃 Table 写入回包时，Sidecar 审计监听先收到等待进度，再收到终态错误。共用审计把前者映射为成功事件，终态错误可能无法更新已有的成功状态。最终集成用例同时检查工作台提示和审计记录。 |

在独立 JVM 中加载实际插件，通过 Sidecar 元数据入口和 JDBC 原生结果对照。验证使用已有维护账号和低权限账号，临时测点及树转表视图在验证后清理。

| 基线 | 结果与证据 |
| --- | --- |
| V1 | Tree 库、设备、测点及详情与 `SHOW DATABASES`、`SHOW DEVICES`、`SHOW TIMESERIES` 对齐。264 个测点分为 256 和 8 两页，两个同名 `temperature` 以完整路径区分。覆盖设备深度、库本身作为设备、对齐标志、带点号的引用节点和低权限可见范围。 |
| V2T | 同样通过 Tree 元数据对照和分页，回读两种模型入口。与 1.3.7 驱动在同一 JVM 中加载后，两套路径解析和元数据查询均可用。 |
| V2R | 库、普通表和视图与原生列表一致，列顺序、类型及 `TIME`、`TAG`、`ATTRIBUTE`、`FIELD` 与 `DESCRIBE` 对齐，JSON 往返保留列角色。以相同库名尾段和同名 `motor_samples` 验证模型隔离。临时树转表视图保留只读标记和原生定义，查询读到 Tree 样本值。 |

## 第 6 步 SQL 解析与语言服务验证

在开发机独立 JVM 中加载实际插件包，调用 Console 的 `QueryAnalysisServiceImpl` 和 Sidecar 会话，再以相同版本的原生 JDBC 连接对照。逐条核对拆句数量、类型、对象及动作、返回行或错误码。写入分别使用两套临时对象，验证后清理。

| 基线 | 结果与证据 |
| --- | --- |
| V1 | PASS。Tree 脚本按四条查询拆分，`SELECT LAST` 返回最新记录，`ALIGN BY DEVICE` 返回普通及对齐设备四行，带点号的引用路径读取文本 `a;b`，部分通配符 `tem*` 命中温度测点。块注释中的分号保留在编辑器原文内，原生 JDBC 执行带块注释的输入返回 `700`，移除注释后与平台返回相同数据。创建、插入、`DELETE FROM`、回读、`DROP TIMESERIES` 分类和对象均正确。删数据后保留第二行，删测点后元数据为空。 |
| V2T | PASS。在独立 Tree 会话重跑 V1 的查询、路径、注释、通配符、分类及写入回读用例，结果一致。 |
| V2R | PASS。限定库名、大小写引用、表别名、条件及派生子查询提取实际库表，带块注释和行注释的查询也与原生 JDBC 返回相同行。批脚本成功创建表、插入两行、更新属性为 `m;2`、按标签和时间删一行并回读。直接提交末尾带分号的 SQL 返回 `700`，平台将分号作为脚本分隔符。尝试更新 FIELD 列时，平台和原生 JDBC 均返回 `616`。 |
| SPI 和构建 | PASS。实际插件包中的方言和语言 SPI 可发现。覆盖偏移起始行、拆句原文、模型关键字、Tree 完整设备路径、Table 限定表名补全、语法诊断和首批范围外语句。对象补全在语言 SPI 层使用模拟的可见对象列表验证。两个插件模块构建、`customFatJar`、Console 和 Sidecar 编译通过。 |
