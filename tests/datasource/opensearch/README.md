# OpenSearch 接入基线与验证

本目录维护 OpenSearch 2.x、3.x 的版本组合和接入证据，结果持续更新在 [能力矩阵](opensearch-test-matrix.md)。第 1 步原型验证、第 2 步插件注册及加载验证已完成，相关辅助验证脚本和专用依赖配置已清理，保留版本矩阵、选型结论与驱动准备说明。第 3 步已接通连接配置与会话生命周期并开放产品入口，集成验收待统一进行。第 4 步接入共享 REST DSL、产品能力及执行入口校验；第 5 步已接通元数据、基础命令传输与结果输出；第 6 步已接通符合条件的 Scroll/PIT 自动分页与统一结果缓存，实库、页面及导出验收待统一进行。

## 当前决定

- 第 1 步验证候选：`org.opensearch.client:opensearch-java:3.10.0`、HttpClient `5.6.4`、HttpCore `5.4.3`，JDK 17。生产插件按实际用途只引入 HC5。
- 原生 `ApacheHttpClient5Transport` 暂不直接采用：在双节点故障探针中，即使关闭自动重试，同一 POST 仍被接受两次；取消 Generic Client 返回的 Future 后，底层连接仍被占用。
- 后续传输层采用 **OpenSearch 插件内部的 HttpClient 5 异步适配**：每次请求选择一个端点，保留真实 HTTP 取消句柄及当前交换的端点终止动作，显式关联结果终态，配置有界响应消费者及执行期限。不会为此给公共 Session、公共 HTTP 工具或 ES 客户端增加 OpenSearch 分支。
- HC5 原生连接池等待期限不能单独作为可靠门禁。本轮验证了显式排队预算取消；生产阶段仍须落实排队与执行阶段的期限切换，并验证调度器关闭、竞争及释放，不能只复制本原型中主线程的 `Future.get(timeout)`。
- 符合条件的文档查询：2.x、3.0～3.2 优先采用 Scroll；3.3+ 优先采用 OpenSearch PIT + `search_after`。早期 PIT 的稳定排序需要额外前提，不能假设业务文档有唯一排序字段。聚合等查询不自动套用文档分页。

以上是原型选型结论。3.9.0 的直接 HTTP 验证不替代其他版本、普通账号、产品权限/脱敏、插件类加载、页面或安装包验收。

## 第 1 步验证结论

原型没有使用 OpenSearch SDK 的内部包。独立消费者是为了验证有界读取及终态处理；曾直接复用 SDK 缓冲消费者到原始 HC5 请求，实库 TLS 超限后出现 Future 等到超时的现象，故最终采用显式取消的独立消费者。不能由这个现象推定所有 SDK TLS 请求都会失败；本地 SDK TLS 大响应对照通过，SDK 实库 TLS 连接也通过。

取消复测还发现，HC5 复用连接的同步借出回调可能使外层借连接依赖覆盖在途请求依赖，单独取消返回句柄未及时释放连接。原型通过公开 `AsyncExecChainHandler` SPI 保留该交换的 `AsyncExecRuntime.discardEndpoint`，而非修改 HC5 或公共 Session；正式接入仍须复核这一扩展点的版本约束及生命周期。

历史验证覆盖本机故障服务与 OpenSearch 3.9.0 实库：本地 22 个必需断言通过；5 个原生对照中 1 个通过、4 个失败；实库 11 个必需断言通过。具体场景、分页样本和清理结果见[能力矩阵](opensearch-test-matrix.md)，这些记录不表示已接通产品运行时。

原型取消的是 HTTP 交换，不代表服务端写任务已回滚或已停止。断开后写入结果未知时不自动重放；服务端任务取消及平台审计终态属于后续会话接入验收。

## 下一步接入约束

1. 第 3 步已在独立插件内实现端点选择、认证/TLS、HTTP 取消句柄与期限管理；故障恢复、取消竞争和资源释放的集成结果仍为 `NOT RUN`。
2. `opensearch-java` 候选带入 Jackson 2.22.2，而当前平台声明为 2.19.0。插件注册阶段按实际用途只准备 HC5，未引入 SDK 或提高平台 Jackson；隔离边界见[插件注册说明](plugin-registration.cn.md)。
3. 第 4 步通过 `RestApiProfile` 集中选择产品能力，共用 sql-es 语法、拆句、格式化和分析；两个插件固定各自产品身份，平台 Session、Console 和 HTTP 工具未增加产品分支。第 8 步已接入前端 REST 语言映射和当前请求选择，页面验收按长期流程统一进行。
4. 其他服务器组合及产品流程保持 `NOT RUN`，后续逐项回填矩阵，不用 3.9 的原型结果代替正式支持承诺。

## REST DSL 与产品能力

第 4 步的长期用例见 [REST DSL 集成验收](rest-dsl-integration.cn.md)。共用语言服务由 `RestDslLanguageSpi` 提供，ES / OpenSearch 插件各自绑定固定产品；`restProduct` 与真实服务端 `version` 使用现有参数容器传递。OpenSearch 使用独立的 `OpenSearch DSL` 引擎名称，不伪装成 ES 版本。

OpenSearch 的类型路由、`include_type_name`、ES 向量接口、顶层 `knn` / `retriever`、`runtime_mappings`、Mapping 的 `runtime` / `subobjects`、嵌套向量查询及 `lang: knn` 脚本按首期能力拒绝。普通文档、查询值和字段名称不作关键字扫描。索引管理接受 `cluster_manager_timeout`，保留实接口仍接受的 `master_timeout`；PIT 从 2.4、稳定排序从 3.3 分开建模。

编辑器拆句与格式化保持仅处理语法，便于整理尚未通过能力校验的请求。校验、分析、改写及执行入口使用产品能力限制；第 5 步已在这些校验后接通白名单命令传输、索引元数据及结果输出。本步没有启动应用、执行数据库升级或完成实库验收。

## 元数据与基础执行

第 5 步实现均位于 `ds-opensearch`，未修改公共类或 ES 插件。支持精确索引/字段、完整索引定义、Mapping/Settings/Alias 读取，以及首期查询、聚合、文档 CRUD、同步 by-query 和索引管理。OpenSearch 字段类型独立注册；冲突、部分失败与空结果分别处理，by-query 影响行数保留实际 updated/deleted 计数。

取消和总期限贯穿预检查、请求与输出；命令不自动重放。单次响应受配置大小及平台结果限制，第 6 步已接入符合条件的 Scroll/PIT 自动分页。完整长期用例见[元数据与执行验收](metadata-execution.cn.md)，实库和页面仍为 `NOT RUN`。

## 分页、结果展示与导出

第 6 步在独立插件内实现旧版本 Scroll 和 3.3+ PIT + search_after，保留默认相关度与显式排序。结果持续写入同一个 ResultBuilder/缓存，展示及导出沿用现有链路；公共 Session、结果缓存、导出服务和前端均未增加产品分支。

有效 size 大于 1000 且符合保守形状条件时自动分页；聚合、偏移、URL sort、脚本、相对时间、外部文档引用等继续原生单次执行。最新游标 ID 在终态检查前保留，清理使用独立期限，清理失败不伪装成功；会话关闭有资源回收上限。具体边界和多分片、并发写入、展示/下载文件验证见[分页与导出验收](pagination-export.cn.md)。实库与页面结果仍为 `NOT RUN`。

## 权限、只读、审计与脱敏

第 7 步新增插件安全规则注册、不可可靠脱敏请求的执行前拒绝、创建索引模板检查、3.3+ 系统生成 Search Pipeline 检查及 model_id 隐式资源检查。共享权限/审计/脱敏/导出生产代码未修改；按本轮决定保留共享脚本语言规则，自定义脚本引擎资源范围尚待决定。

模板匹配的创建请求首期统一拒绝；3.3+ 搜索需要读取集群配置的数据库权限。详见[安全集成验收](security-integration.cn.md)，其中包含权限矩阵、账号准备、所有结果出口、审计终态和仍需确认的边界。应用、实库和文件出口统一验收后再回填状态。

第 8 步补齐独立图标、REST 语言映射和多地址处理，并将当前请求选择的 ES 专用判断收敛为共享 REST 编辑行为。名称、分类、连接字段及中英文说明复用插件下发的配置；命令模板、结果与导出沿用已有接口。共享语言 ID 不改变请求的会话、产品和版本。未修改后端公共类或数据库结构。
