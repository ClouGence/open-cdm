# open-cdm 数据源接入指南

用于新增数据源或补齐已有实现。本文只维护通用步骤与注意事项；具体数据库的版本、差异、开发进度和验收结果放在 `tests/datasource/<name>/`，页面流程放在 `tests/frontend/`。本文尚未转为 skill。

以下按关系型数据源组织。非关系型数据源沿用范围、插件、连接、权限、页面和交付步骤，按实际协议替换 SQL、schema、事务与编辑部分，不强行套用 JDBC 模型。未纳入的能力需写明原因。

## 使用方式

- 先盘点，再实现；每步都检查“已有实现 → 调用方 → 页面入口 → 实际效果”，不凭类名或 SPI 存在判断完成。
- 复用现有家族与平台流程，仅实现真实差异。兼容协议不代表元数据、类型、权限和 DDL 完全兼容。
- 修改公共接口或执行链时，列出受影响数据源并回归；公共性能、队列和状态机问题单独评估，避免随接入扩大改造。
- 实现进度与验收结果分别记录。缺环境时可以继续独立开发，未执行项保持 `NOT RUN`；入口开放不等于产品验收通过。

## 接入步骤

### 1. 确定范围与验证基线

- **工作**：确定数据库产品、精确版本、兼容模式、部署形态、驱动版本、认证方式及首期能力；准备隔离环境、普通账号、管理账号和可清理样本。
- **注意**：云服务与自建部署分别评估；驱动列表中的版本不能自动视为已认证。查询、编辑、治理、工单和 CI/CD 分别决定是否纳入，不默认承诺全部高级对象。
- **验收**：建立能力矩阵，至少记录“能力/入口、实现位置、支持边界、版本组合、验证方法、结果/证据”。后续步骤持续回填，不到最后才补测试范围。

### 2. 盘点已有实现与复用边界

- **工作**：检查产品枚举、插件模块、驱动、SQL 引擎、前端入口和测试资产；选择最接近的家族，列出必改、可复用和不涉及的部分。
- **注意**：已有但隐藏的实现要核对隐藏原因、空实现、继承默认行为及前端类型特例；保留稳定的产品标识、驱动家族、引擎名称和配置格式，避免旧连接失效。
- **验收**：得到有源码依据的差异清单；全新接入不重复创建已有能力，补齐实现不照搬历史缺口重新开发。

### 3. 注册模块、插件与 SQL 引擎

- **工作**：按需创建 `clouddm-ds/ds-<name>`，在 `settings.gradle` 注册；配置 `DataSourceType`、`DsType`、`@Plugin`、`DsPluginBinder`、类型映射与各 SPI。
- **注意**：独立方言优先放在 `clouddm-sql/sql-<name>`，由数据源模块依赖；复用引擎时绑定实际名称。核对服务发现文件、`includePackages`、共享依赖和插件类加载边界，避免驱动重复打包或维护不一致的 parser。
- **验收**：模块编译、插件包生成和插件发现成功；产品标识、序列化 provider、驱动工厂与引擎绑定对应。这里只检查绑定一致，不要求所有名称相同。

### 4. 接通驱动、连接配置与安全连接

- **工作**：实现配置模型、动态表单、序列化和 `DsFactory`；配置 `drivers.xml` 与工厂服务声明，映射地址、账号、数据库/schema、超时、TLS/SSH 等属性。
- **注意**：核对单位、编码、默认端口、自定义 URL 与其他字段的优先级；证书文件须在实际执行节点可用。日志不输出凭据或含敏感参数的 URL。`compileOnly` 不代表运行时驱动已安装。
- **验收**：产品内新增、保存重开、修改和测试连接成功；错误账号、不可达端口、慢连接、错误证书按预期失败，初始化失败释放连接。在线准备与离线交付方式明确。

### 5. 统一会话、事务与资源生命周期

- **工作**：沿用会话工厂、Session/Hooks 和资源管理器，适配初始上下文、自动提交、隔离、只读、参数绑定、更新计数、多结果集、流式读取和取消。
- **注意**：明确查询 tab、平台 Session 与物理连接的关系，以及关闭/重建条件。DDL 的提交边界、只读效果和隔离级别以目标实现为准；不能盲目重试提交结果未知的写入，也不能依赖透明重连保留会话状态。
- **验收**：双连接验证提交/回滚与会话参数；双会话取消只影响目标。覆盖重复/迟到取消、取数中止、断网、初始化/关闭失败；保留原始错误，复位执行状态，释放连接、Statement、ResultSet 和后台任务。

### 6. 对齐元数据、对象路径与类型

- **工作**：实现 `MetaService` 及元数据 provider，明确 catalog/database/schema 层级；补齐首期对象、列、默认值、注释、键、索引、程序参数和类型映射。
- **注意**：连接目标与连接内可切换层级分开定义；对象路径须与权限、血缘一致。系统视图关联不能只用裸对象名，约束聚合要保留对象身份及列顺序；未知类型不伪映射，索引所属对象不假定总是表。
- **验收**：普通账号可见性、跨库/schema 同名对象、多列约束、引号与大小写正确；核对数值精度、时区/时间精度、Unicode、二进制、LOB、NULL。对象树、详情与数据库实际结构一致。

### 7. 完成 SQL 方言与语言服务

- **工作**：实现或复用 `Dialect`、`DslProvider`、`SplitAnalysisSpi`、`DsLanguageSpi`、`RewriteSpi`；提供关键字、补全、校验、拆句、格式化及查询限制改写。
- **注意**：拆句、结构校验、语义分析和格式化职责不同；明确各自支持范围。不用简单正则或按分号切割代替过程体解析。补全受授权范围约束；编辑器位置要处理 Unicode/UTF-16 差异。
- **验收**：覆盖引号、注释/字符串内分号、过程体、嵌套块、CTE、集合查询和错误输入；改写保留原语义及已有更小限制，分页无重复遗漏。格式化保留文本含义，可撤销、重复执行稳定，失败保留原文。

### 8. 接入行为分析、权限、审核、血缘与脱敏

- **工作**：接入 `BehaviorAnalysisSpi`、`SecDomainResolveSpi`、规则支持和 `LineageAnalysisSpi`，使读写/程序对象及输出列来源进入平台治理链路。
- **注意**：平台授权与数据库账号权限分别验证。动态 SQL、无法分析语句、无来源列、程序多结果集都要明确处理，不能把分析失败当作无资源访问或审核通过；SPI 缺失导致的规则降级也要检查。
- **验收**：受限账号不能通过别名、子查询、跨 schema、复杂 DML 或程序调用绕过授权；规则可命中和阻断。多表、表达式、星号、视图、部分敏感豁免及结果导出均不错误解除脱敏。

### 9. 补齐结构编辑与对象脚本

- **工作**：对齐 `EditorProvider` / `SqlBuilder`、UI 面板、DDL 转换和对象脚本；覆盖纳入范围的建表、改表、键/索引及其他对象操作。
- **注意**：菜单、元数据和 SQL 生成器成套核对；模板不等于读取已有对象定义。无修改不产生 DDL，清空注释/默认值要区别于未修改；有损转换须明确拒绝或提示，不静默丢失属性。
- **验收**：完成“预览 → 执行 → 刷新回读”，验证列顺序、类型、约束和默认值；在隔离环境验证脚本等价重建。未实现的属性/编辑入口不显示空页面或假成功。

### 10. 完成数据编辑与导入导出

- **工作**：确定安全的原行定位方式，接通值转换、批量编辑、导入部分失败、分页/流式导出及 SQL 回放。
- **注意**：不能唯一定位的行禁止更新/删除；键值修改仍按原行定位。前端与公共 INSERT 区分字段缺失、显式 NULL 和实际值，全默认值 INSERT 等语法留在数据源实现；生成列和只读对象准确限制。
- **验收**：复合键只修改目标行，高精度数值、时间、二进制、Unicode 和 LOB 往返一致；导出无遗漏/重复、不绕过脱敏。取消/断网释放资源，部分失败结果准确，截断展示值不冒充完整导出数据。

### 11. 对接执行计划、工单与 CI/CD

- **工作**：适配原生计划生成、读取和清理，验证平台现有分析、审批、执行及结果展示流程。
- **注意**：计划分析不能执行原写入；并发请求不能串计划。原生计划与语句推断分开标识，零估算与未知估算分开表示。DDL 混合事务、部分提交、重试/重复调度要核对数据库效果与平台状态。
- **验收**：普通账号权限不足和计划获取失败能反馈；成功/异常均清理临时记录。工单完成一次实际流程；公共问题若暂缓，单列范围、影响和后续处理，不因插件完成而记为已解决。

### 12. 对齐页面能力与国际化

- **工作**：检查名称/图标、分组、连接表单、对象菜单、编辑器、工具栏、规则和导出入口，复用通用组件与后端能力描述。
- **注意**：逐项核对“SPI → 后端响应 → 按钮/菜单 → 实际调用”，避免按数据源类型硬编码能力。前端文案放 `frontend/src/locales/`，插件文案用后端 i18n；声明支持不能仅靠返回 true。
- **验收**：中英文、常见桌面/窄屏、tab 切换与恢复正常；未支持功能禁用/隐藏或明确提示。按仓库规则完成 Web 构建和浏览器复测，共享组件变更回归其他数据源。

### 13. 验证发布包、开放入口并交接

- **工作**：验证约定版本与部署模式，检查 `customFatJar`、SQL/共享依赖、服务注册和资源；确定在线下载、离线预置或随包内置驱动方案，按约定调整 `@Plugin.display`。
- **注意**：`drivers.xml` 与 `built-in-drivers.xml` 职责不同，离线可用不等于随包内置；内置时核对版本、坐标与分发条件。Console/Sidecar 各执行节点都需驱动和证书，不能只验证开发机 classpath。
- **验收**：实际安装包可加载插件、建立连接、重启恢复并读取旧配置；从正常新增入口完成查询及约定管理/治理流程。记录版本、制品摘要与未覆盖项；提前开放须记录明确决定，不改写未执行项的状态。

## 验证与交付约定

| 证据层级 | 能证明什么 | 不能替代什么 |
| --- | --- | --- |
| 编译、已有单测、离线解析/代理探针 | 代码、局部契约与样本行为 | 真实数据库及产品流程 |
| 直接驱动连接 | 驱动和数据库的局部行为 | 平台配置、权限、会话及执行节点链路 |
| 产品实库与页面复测 | 指定组合下的用户流程 | 其他版本、账号与部署形态 |
| 实际发布包安装/重启 | 指定制品的交付与恢复 | 未覆盖能力和未测版本 |

- 专项矩阵记录 PASS、PARTIAL、FAIL、NOT RUN 或 BLOCKED 及依据；`NO-SOURCE` 不是测试通过。明确不支持的能力写出实现/产品边界，不把漏实现归为“不适用”。
- 复用并扩展现有样本和测试；未获用户明确要求不新增测试类。公共模块变更按调用方扩大回归，而非只测新数据源。
- 长期页面流程只维护操作、断言和清理步骤，结果放专项矩阵；代理按 `frontend/AGENTS.md` 使用 @Browser，用户安排手动验收时记录交接。
- 交付支持范围、部署/驱动准备说明、能力矩阵和复测入口；不提交凭据、厂商二进制、运行数据或生成日志。不因接入自动新增业务表或修改历史 migration。

常用命令如下，替换 `<name>`；每条从仓库根目录独立执行，其他要求以仓库规则为准：

```bash
cd backend && ./gradlew ':ds-<name>:build' ':ds-<name>:customFatJar'
cd backend && ./gradlew ':sql-<name>:test'  # 仅适用于独立 SQL 模块
cd backend && ./gradlew :s-test:test      # 公共数据源测试模块
cd package && ./all_build.sh web         # 修改前端源码后必须成功
cd package && ./package.sh --build       # 发布包阶段；打包不替代测试
```
